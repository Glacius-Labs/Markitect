# Actual Markdown Module replacement fixture

This source fixture installs and binds one exact target capability at a time. `original.yaml` selects the existing `markitect-markdown@1.0.0`; `replacement.yaml` selects `markitect-markdown-reference@1.0.0`. Both configurations use the same Foundation package, workflow Schema, Projection, four workflow Definitions, and four Markdown ProjectionPolicies. The Rule, Process, Responsibility, and Gate files under `definitions/` are byte-for-byte copies of the public `examples/canonical-workflow/` inputs. Only the installed Markdown package and binding differ.

The alternate package manifest declares target `markdown`, entrypoint `markdown-reference`, and the same `docs/represented/` target root. Its statically composed implementation emits `canonical-projection.md`; no private implementation is copied into this source fixture. Run `go test ./internal/modules/markdownreference` to check deterministic bytes, preservation of canonical JSON payloads, refusal paths, and the changed layout. The verifier reads only the supplied public semantic inputs and generated candidate bytes; no provider output can replace or authorize those inputs.
