# The usual way

Type: [Rule](../../core/rule.md)

## Applies to
[The roles](../team/README.md), [the rules for kinds of modules](../plan/README.md)

## Rule
Every role has a usual way of working, written in its role document: where it usually works, which roles it usually works with, and what another role is usually there for. This holds for a role an agent fills as for one a person fills. What a rule for a kind of module says the module never does is a usual rule too. The Assistant leads by these documents, and every session recognizes by them when work lies outside the usual. Whoever deviates is warned and asked for the reason; both land as a note in the context. When deviations pile up or their reasons are thin, that becomes a smell. When they pile up with good reasons, the role document is wrong, and it becomes a finding of type Process.

## Example
A person asks the Architect to write the code during a planning. Its role document says that a planning session never builds: the agent says so in one sentence and asks why; the answer, "it is one line and I want to see it now", goes into the note, and the work goes on.
