# One trace from origin to file

Type: [Rule](../../core/rule.md)

## Applies to
[Story](../plan/story.md), [the Reviewer](../team/reviewer.md), [the Builder](../team/builder.md)

## Rule
One trace serves everything. The story names its origin, a finding or a report, and under Realizes every place in the model that its files realize, also where it changes nothing there. When no document of the model covers its files, something is missing in the model, and the story's planning adds it; a story with fixed tasks that meets such files aborts and is planned ([abort](../building/abort.md)). A story that changes no file, such as a smell analysis, names none. Whenever files that realize a place change, that place is confirmed again: in building every place the story names under Realizes, `unchanged` ones included; in accepting each place whose files the polishing changed. For each place, the Reviewer's confirmation names every file that realizes the document, those that did before and still do and the new ones, tests included, and the test that proves it. A document that no file realizes, such as a watch's document, which the Observer reads as it is, is confirmed as such, with that reason. A document that files realize but no test can prove, such as how the application is started for trying, is confirmed by the Reviewer doing what it says. A skill has no test: for an activity's document, the Reviewer confirms that the skill says what the document and what it links say, no more and no less. The confirmation stands in the report of the Reviewer whose round agreed, one statement per document, with the outcome `confirmed`; that report names the story as its item, is written on the story's branch and lands with it, so that `main` never holds a confirmation without the files it confirms. Where another open story names the same document, the statement says which part it confirms. Nothing of the confirmation goes into the story's Result. A document counts as built when every story that changes it has landed and it is confirmed for each of them ([the model runs ahead](../plan/the-model-runs-ahead.md)). The commit names the story. So the trace leads from the origin to the file and back, and answers "where does it say it should be so?", for the product and for the way of working alike. Who checks names the evidence, not who built. Files from before this way of working have no entry; they get one when a story touches them.

## Example
For the story "Renew a loan", whose merge commit names the story, the Reviewer confirms in its report `reports/review/2026-11-24-1432-renew-a-loan.md` the document `lending/period`: realized by `src/loans/renew.ts` and `tests/loans/renew.test.ts`, proven by `tests/loans/renew.test.ts`.
