# Notes: reference implementation

One line per reading chosen where a page was unclear. Authors append.

## Layer 1: ledger, notices, households, guardians, waivers, ppe, lockouts, inspections, staffing, parts, rooms

- `bookings/active.go` is a new file with one read-only accessor, `ActiveIntervals(machineID, at)`, so that `protocol` can supply staffing's need `ActiveReservations`; no existing bookings file or behavior was touched.
- `guardians` keeps a birth date after the request date as a minor, and `declareMinor` judges `not_a_minor` on the request date only; `ConsentMissing(member, family, day)` is the one call the gates need.
- `staffing.OnShift(user, at)` means a scheduled shift with `start <= at < end` (half-open); `SupervisorMissing(family, start, end)` is the `supervisor_required` test.
- `lockouts`: `releaseLockout` by an admin works on a lockout applied by someone else; `ReleaseSource` skips lockouts already released and leaves their `releasedAt`.
- Flag arguments accept exactly the JSON literals `true` and `false`; a string `"true"` is `invalid_argument`. `policies.GuardianRef` is the `guardianId` argument (existing member, ownership on it alone).
- Still to be wired by the next authors: the gates in `createReservation` and `checkIn` (`guardians.ConsentMissing`, `waivers.Missing`, `lockouts.LockedOut`, `inspections.DueOn`, `staffing.SupervisorMissing`, `ppe.Missing`), notices posting from other modules (`notices.Post`), ledger postings (`ledger.Post`), the household discount (`households.OfMember`), and the rooms API (`Capacity`, `Free`, `HoldFor`, `ReleaseHold`).

## Layer 2: billing changes, deposits, passes, promotions, scholarships, refunds, dunning, lockers, guests, volunteering

- `billing.New(mem, led, hh)` now takes the ledger and households. `GrantCredit` (used by `issueCredit` only) counts a credit event and posts `expenseGoodwill`; `AddCredit(member, amount, debitAccount, memo, at)` is the capability for all other credit and counts nothing in `revenueReport`. `AddCharge` is the capability "create a charge" for every kind.
- API for the next authors: `passes.Draw(member, minutes, at) int` (call before the usage charge); `promotions.OldestUnused(member, "course"|"material") *Redemption` (nil if none, `.Percent`) and `promotions.Use(r, ref, at)`; `scholarships.ActiveAward(member) (award, remaining, ok)` (`award.Percent`, `award.FundID`) and `scholarships.Spend(fundID, amount)`; `guests.GuestPassOf(id)` (member, date as day number, status); `refunds.RefundedOnLine(invoice, line)`; billing `OpenInvoices`, `OverdueInvoices(at)`, `ChargeOnPaidInvoice(kind, ref)`, `Invoice(id)`, `InvoiceOfMonth`, `InvoicesOfMonth`, `AccountOf(member, at)`, `PaymentsInMonth`, `CreditsIssuedInMonth`, `CreditBalance`; `members.InGoodStanding`, `members.SetStanding` (no audit), `members.Tiers`.
- `refunds.issueRefund` judges `invalid_line` as `lineNumber` above the number of lines and `refund_too_large` against the line amount less earlier refunds of that line; a zero-cent line has nothing left, so any refund of it is `refund_too_large`.
- `guests`: a pass is charged when the member holds `perMonth` or more issued passes dated in the month of the new pass (the tier is the member current tier); a charge of 0 cents is still created and `charged` is true.
- `decideVolunteerTime` checks `invalid_state`, then `approver_not_on_shift` (staff only, via `staffing.OnShift`), then the cap; a rejection never checks the cap. An approval at rate 0 sets `creditCents` 0 and posts nothing.
- `dunning` walks a snapshot of the invoices overdue at the request time; the case (`dun-N`) is created by the first step taken, and each step is taken once per invoice. The fee charge and the suspension notice are created in the same run if due.
- `ownership` (check 6): `depositId`, `rentalId`, `guestPassId`, `entryId` and `invoiceId` args carry an owner function; `noticeId` was already there.

## Layer 3: bookings, training, materials, consumables

- Needs (supplied in `protocol/server.go`, stubs marked `// supplied by <module> in the next layer`): `bookings.Needs.BadgeOutside(member)`; `training.Needs.AttendanceOwed(course, member, enrolledAt, at)` (true = owes, stub false) and `AssessmentMet(course, member)` (stub true); `materials.Needs.HazardRefusal(member, material, quantity, at)` (code or "", stub "") and `Counted(material)` (stub false). `materials.Counted` forwards to the need.
- API for the next authors: `bookings`: `ReservationOf(id, at)`, `ActiveReservationsOfFamily`, `UpcomingReservations(machine, at)`, `CancelReserved(id, at) bool`, `OpeningHoursOf(day)`, `ActiveReservationOverlaps`, `CompletedSessions`. `training`: `FamilyOf`, `EnrollmentOf(course, member)` (with `Number`), `FreePlaces`, `Enroll(course, member, at)` (the full operation without role checks and audit; returns the refusal). `materials`: `UnitPrice`, `Stock`, `UnitsBought(member, material, month)`, `PurchaseExists`, `PurchaseOf(id)`, `AddStock`, `SetStock`, `Draw(material, units)`, `Counted`. `consumables.Draw(reservation, member, machine, metered, at)` returns the charges.
- `enrollInCourse` judges the award as covered when `feeCents - ChargeAmount(1, fee, percent) <= budget - spent`; an award whose discount rounds to 0 still wins on percent when it is higher or equal. The promotion is used only when it wins; `usedOn` is the course id.
- `checkOut` draws passes first, then creates the usage charge on `billable`, then the material charges on the full metered minutes; a row with `drawn` 0 creates no charge. `bookings.New` and `training.New` and `materials.New` gained parameters (needs first, then the modules).

## Layer 4: access, instructors, classes, assessments, waitlists, payouts, events

- Needs wired in `protocol/server.go` (stubs replaced): `bookings.Needs.BadgeOutside` from `access.BadgeOutside`; `training.Needs.AttendanceOwed` from `classes.AttendanceOwed`, `AssessmentMet` from `assessments.AssessmentMet`; `instructors.Needs.HasClasses` from `classes.InstructorHasClasses`. API for later authors: `access.BadgeOutside(member)`; `instructors.Qualified(user, family)` and `HoldsAny(user)`; `classes.ScheduledInMonth(user, month)` (scheduled classes with minutes) and `InstructorHasClasses`.
- Arguments named `userId` and `instructorId` accept any existing user (member, staff or admin); the page rules (`not_eligible`, `not_instructor`) refuse the unsuitable ones at check 7.
- `admitGuest`: `guestPassId` carries no owner function, only `badgeId` does (ownership on `badgeId` alone); a revoked pass is read from `guests.GuestPassOf`.
- `enterDoor` judges opening hours with `bookings.OpeningHoursOf`: opening minute in, closing minute out, Sunday none; the overdue balance is `billing.AccountOf(member, at).Overdue`.
- `assessments` identifies an enrollment period by `training.Enrollment.Number`, not by `enrolledAt`, so an enrollment at the minute of the completion starts a new period; `recordAttempt` `not_enrolled` needs status `enrolled`, `markAttendance` `not_enrolled` any enrollment.
- `waitlists` builds the `enrollments` records itself from `training.Enroll`; a promotion posts the `waitlist` notice only after a successful enrollment, and entries left untried when the course fills stay in place with their order.
- `events` credits through `billing.AddCredit` with debit account `revenueRefunds` and memo the `ticketId` (billing posts it); a price of 0 therefore gives no credit and no entry. `cancelEvent` cancels tickets with the same helper and returns only the tickets it cancelled.
- `generatePayouts` marks the month as generated even with no payout, and posts `expensePayout`/`payable` per payout in creation order; `settlePayout` posts `payable`/`cash`; a 0-cent payout posts nothing.

## Layer 5: hazmat, purchasing, stocktake, workorders, escalations

- Needs wired in `protocol/server.go` (stubs replaced): `materials.Needs.HazardRefusal` from `hazmat.HazardRefusal(member, material, quantity, at)` (the certification is judged with `training.Certified` on `DayOf(at)`, the limit with `materials.UnitsBought` in `MonthOf(at)`), `materials.Needs.Counted` from `stocktake.Counted(material)`. API for later authors: `workorders.OpenLinked(machine, summary, opener, incident, at)`; `purchasing` and `stocktake` use `materials.Counted`, `AddStock`, `SetStock`, `Stock`, `UnitPrice` and `ledger.Post`.
- `parts` gained one exported function, `PartView`, so that `useParts` returns the part record in the shape of `listParts`; nothing else in `parts` changed.
- The escalation page states no `reason` for the lockout; the work order's lockout always has the work order's `summary` as `reason` (`Escalated incident <incidentId>` for an escalation), as `openWorkOrder` states.
- `approveOrder` judges `approval_requires_admin` on the actor role `staff` only; an admin may approve any total. `approveOrder` and `receiveOrder` never judge the supplier status at a receipt; `createOrder` and the approval do.
- `receiveOrder` checks `stocktake_open` after `over_receipt`, as the page lists; `closeStocktake` takes the stock at the request time for each count and posts one entry per count with a difference other than 0 (shrink: `expenseWriteOff` to `inventory`; gain: `inventory` to `expenseWriteOff`).
- An escalation consumes its work order and lockout numbers even though the escalation itself is the last thing created; refusals consume nothing. Cancelled reservations are the `bookings.UpcomingReservations` of the machine, cancelled with `CancelReserved`, each followed by its `cancellation` notice.

## Layer 6: projects, quotes, jobs, compliance, finance

- `equipment.FamilyIDs()` and `households.MemberIDsOf(householdId)` are two small read accessors added so that `compliance` (one row per family) and `finance` (household statement) need no state of their own; nothing else in either module changed. Needs: none, `protocol` only wires the five modules.
- `projects`: `attachReservation` judges `not_project_member` on the reservation's member at the request time and `already_attached` against every project; a collaborator that is the owner is `already_collaborator`. `getProjectCost` counts a reservation as completed by its status at the request time.
- `quotes`: a quote's `validUntil` is the date of the request time plus 30 days, and `decideQuote` refuses acceptance when the date of the request time is after it. `addQuoteLine` checks `invalid_state` before `unknown_line_ref`, as the page lists. `QuoteOf(id)` gives jobs the customer, status, total and lines.
- `jobs`: `startJob` checks the certification of every `machine` line (any line without a valid certification refuses with `maker_not_certified`, valid on the day of the request time via `training.Certified`); `completeJob` credits through `billing.AddCredit` with debit account `expenseMaker` and memo the `jobId`; `recordJobPayment` posts `cash`/`revenueJobs`.
- `compliance`: `lockouts.LockedOut` is read at the request time whatever the date; the blockers are the `createReservation` gates in its order; `complianceSummary` rows judge `consent` as "not a minor or consent held" and `waiverSigned` as "no waiver or latest signature current", both on the date of the request time. `complianceSummary` and `checkEligibility` take `memberId` as the owner argument.
- `finance`: `refundedCents` sums `refunds.RefundedOnLine(invoice, n)` for every line `n` (1-based) of the month's invoices; `financeSummary` is admin only (`nna`); `agedReceivables` takes `billing.OpenInvoices()` (open at the request time) and computes `daysOverdue` as the difference of the date argument and the date of `dueAt`, at least 0.
