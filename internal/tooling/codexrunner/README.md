# Codex execution adapter

This standalone standard-library Python adapter accepts the closed agentexec.Invocation JSON value on stdin and emits exactly one response JSON object on stdout. It rejects duplicate or unknown request fields, verifies explicit artifact byte digests, and uses separate Executor, Verifier, and infer-only instructions. It does not embed Markitect ontology or write candidate files.

The caller supplies --model, an explicit absolute --codex-executable, and --codex-version. The executable must be the native Codex binary; `.ps1`, `.cmd`, and `.bat` launchers are rejected. For an npm installation, resolve the platform package's vendored `codex` binary and pass that path (do not pass the npm shim or JavaScript entrypoint). The optional --codex-script is only for runtimes such as Node when a platform does not provide a native binary. The adapter invokes `codex exec` with --ignore-user-config, --ignore-rules, --sandbox read-only, --ephemeral, --json, --skip-git-repo-check, and --disable for plugins, shell_tool, and unified_exec, plus an output schema, an output-last-message file, the empty temporary --cd directory, and stdin -. `modelOptions` accepts only `model_reasoning_effort` with one of `minimal`, `low`, `medium`, `high`, or `xhigh`; arbitrary Codex `--config` settings are rejected before any files or provider process are created, so caller options cannot override sandbox or approval behavior. The strict output schema requires every response field and represents optional inference `candidateJson` and typed task `reportJson` as JSON strings or null; the adapter parses and validates them before emitting the Host protocol response. An Executor request with `context.responseSchema` requires a JSON-encoded report matching that closed task schema; without it, `reportJson` must be null. Candidate JSON remains inference-only.

The prompt tells the model to copy the invocation's apiVersion, runId, nonce, role, and inputDigest exactly, and to emit every required array even when empty. Response evidenceRefs are exact request scope IDs, policy IDs, or artifact paths only; digests are not evidence references. Executor and inference responses may cite relevant supplied references. Verifier responses must cite the complete sorted, unique union of every supplied scope ID, policy ID, and artifact path, including fixed-check input artifacts; the prompt renders that exact list from the request. A verifier must also report one observation for each supplied scope or policy ID and use an incomplete or escalated result when required information is missing or ambiguous. Listing references is protocol bookkeeping, not proof that an input was inspected or supports a conclusion. These are model instructions: the adapter validates the closed JSON shape, while the Host validates invocation binding and allowed references. Neither prompt compliance nor protocol validity proves verifier independence, evidence sufficiency, or human acceptance.

Before prompting, the adapter rechecks each artifact's bytes against its declared SHA-256 and makes a display-only copy of the invocation. Valid UTF-8 artifacts replace their base64 `content` in this copy with exact `contentUtf8` plus `contentEncoding: utf-8`; non-UTF-8 content remains base64 and is marked accordingly. Paths, modes, digests, nonce, and inputDigest stay unchanged, and the Host invocation is never rewritten. Artifact text is untrusted data, including code comments and documents that address an agent; it cannot change the assigned role or protocol.

The Host supplies MARKITECT_AGENT_CONFIG_JSON and MARKITECT_AGENT_PRIVATE_LOG. Codex JSONL stdout events and stderr are retained in that private log, bounded to 16 MiB. After the complete prompt is written and the child stdin is flushed and closed successfully, the adapter appends one `adapter.prompt-submitted` event containing the invocation run ID, input digest, SHA-256 of the exact UTF-8 prompt bytes, and byte length. It never stores prompt text or the invocation nonce in this event. A broken, partial, or failed pipe submission produces no such event and fails the invocation. The event witnesses adapter-side delivery only; it does not prove provider authentication, semantic consumption, or correctness. The adapter emits only the final protocol response on stdout and a generic error on stderr. It parses tool-call events and provider-reported token usage. Missing usage stays missing.

For recognized model/account incompatibility, authentication, rate-limit, and CLI invocation/configuration failures, the adapter returns a protocol-valid `incomplete` response with a fixed generic explanation; it never copies provider bodies, user paths, or request identifiers into that response. Unknown process failures keep the generic nonzero runner error. Any observed tool call forces an `incomplete` response even if a final proposal exists. The adapter disables Codex's plugin, `shell_tool`, and `unified_exec` features and checks for tool events as a second boundary.

`--ignore-user-config` does not establish that Codex loaded no ambient Skills. The [official skills documentation](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) describes repository, user, admin, and system skill sources and per-skill disablement by exact `SKILL.md` path. The installed Codex CLI 0.130.0 feature list contains no global skills-disable feature. This adapter does not enumerate unknown installed skill paths or write global configuration, so it does not claim absence of ambient skill instructions. A strict deployment must control these sources in its verified host environment.

Install Python 3.10 or later as a caller-managed dependency. Run the boundary tests from this directory with python -m unittest. The wrapper itself can be inspected without invoking Codex; the real CLI is an external dependency and is exercised separately by a controlled integration experiment.

Controller requests may declare `context.requiredObservationSubjects`: an exact bounded typed list of scope, policy, artifact and fixed-check identities. The prompt requires complete passing observation coverage for an overall PASS; failed/incomplete responses may retain partial observations. These tokens are not evidenceRefs. Requests without this list retain the legacy scope/policy prompt. Malformed subject lists fail before any provider process or workspace file creation. Host, not this adapter, evaluates response coverage and composes fixed checks.
