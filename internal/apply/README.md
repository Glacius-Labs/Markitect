# Apply composition

Apply consumes checked [Project](../project/README.md) capture. Workflow selects complete fresh Assessment, Implement and Verify Runs with one shared allowance and deadline. Implement submits; only final stored Verify approval permits publication. A rejection carries mandatory Findings into a fresh correction and Verify; model blockers and technical or cleanup uncertainty stop the command. Before a correction pair, workflow checks that the remaining allowance can start Implement and Verify, each with every Manager once; otherwise the command ends incomplete with the cause "budget does not cover a correction pair". The check refuses only an impossible start; a started pair can still run out of budget.

The standalone [Run](../run/README.md) closes all resources and persists its terminal result. Apply independently rereads final acceptance before handing a durable reference to publication. The publisher reopens exact Git objects and retained external inputs in a separate host repository, repeats structural and declared checks, compares complete captured Census, transfers guarded paths and reads back. No owner commit or push occurs. Partial transfer is reported with completed paths. Assessment approval enables Implement, including when Implement leaves the actual complete input unchanged; fresh Verify remains mandatory. Assessment rejection or model blocker stops without publication.

The first controlled source vertical exercises real Git and Store, all five fixture Managers, parent corrections, closure and publication. Bootstrap composes the explicit Codex account profile, Linux Run copies and independent Linux publication-check copies. Controlled source tests do not establish complete native Apply or product acceptance; those require separately bounded evidence. See the [delivery plan](../../docs/implementation-plan.md).
