---
name: markitect-audit
description: Audit the spec itself. Fresh markitect-auditor agents read the spec as newcomers, one per Package that holds Operations or Reactions and one for the rest, and report contradictions, gaps, unclear and duplicated statements, missing links and the topics of the coverage list the spec neither states nor rules out to the owner, triaging the unlinked mentions markitect vet finds. It changes nothing and records nothing. Use before a spec is built, after a large change of it, or when the user asks to check the spec rather than the code.
allowed-tools: Bash(markitect status --json), Bash(markitect config strategy.audit), Bash(markitect list), Bash(markitect run *), Bash(markitect inbox *)
---
Run `markitect config strategy.audit` for how to audit: `sequential`, `parallel`, `auto` or the name of a custom workflow. With `auto`, audit as with `sequential`. Under every strategy the auditors run at once, since they change nothing. Change no file yourself. Before you start the auditors, run `markitect run start audit --strategy <how you audit> --trigger <owner, or claude when you started this audit on your own>`, and after you opened the inbox items below `markitect run end <how it ended>`, one of `done`, `no-progress`, `stopped` or `failed`; in a Git repository commit `.markitect/history.jsonl` and `.markitect/inbox.jsonl` alone after each.

- **Sequential:** run `markitect list`, which names each Package with its Definitions and their Kinds. Start, in one message with the Agent tool, one markitect-auditor for each Package but Root that holds a Definition of kind `std/Operation` or `std/Reaction`, with the message "Audit Package PACKAGE: read markitect doc --read PACKAGE --bound first, and triage the unlinked mentions markitect vet --strict lists in it.", and one more with "Audit the rest of the spec: Root's own folders, the Packages ALL OTHERS, and the edges between Packages. Read markitect doc --read --bound first and write the lines for Root's own Operations and Reactions; walk the coverage list, and triage the unlinked mentions markitect vet --strict lists there.", ALL OTHERS being the Packages but Root that have no auditor of their own, and "the Packages ALL OTHERS" being "no other Package" when there are none. Add to each message the Packages or Definitions the user asked to focus on or to leave alone, if any.
- **Parallel, or a custom workflow:** start the workflow with the Workflow tool, `markitect-parallel` for parallel or the custom workflow by its name, with the args `{"mode": "audit", "focus": "<what the user asked to focus on or to leave alone, or empty>"}`. It starts the same auditors and returns their reports.

When the audit has ended, merge the auditors' reports into one: their findings, the most serious first, in plain words, each with its place and its question, a finding that several report once. Say how many Operations and Reactions the auditors walked, and name each Definition of kind `std/Operation` or `std/Reaction` that `markitect list` shows, Root's included, for which no report has its line. The missing links found come as one list, each with the Definition to link: the owner adds them, in their session with the markitect-architect skill, or by hand. The topics of the coverage list the spec neither states nor rules out come as one list too: the owner states each, or rules it out as the list says. Then open one inbox item per finding, the missing links and the open topics of the coverage list each as items too: `markitect inbox add --source audit --kind KIND --settle owner --place PLACE -m "WHAT IS WRONG" --ask "THE QUESTION OR THE CHANGE"`, KIND being contradiction, gap, unclear, duplicate, missing-link, coverage, design or question, and `--settle agent` for a missing link and for a change as mechanical. An item open already is not added twice. The owner settles the rest in the spec, with the markitect-architect skill or by hand; no verdict is recorded. When the audit runs as the step of starting a project in the markitect-architect skill, open no item and give the user none of the findings: that skill settles them and hands over.
