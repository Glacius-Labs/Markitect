---
name: markitect-audit
description: Audit the spec itself. A fresh markitect-auditor agent reads the spec as a newcomer and reports contradictions, gaps, unclear and duplicated statements, missing links and the topics of the coverage list the spec neither states nor rules out to the owner, triaging the unlinked mentions markitect vet finds; a large spec is audited in parallel, one auditor per Package and one across them. It changes nothing and records nothing. Use before a spec is built, after a large change of it, or when the user asks to check the spec rather than the code.
allowed-tools: Bash(markitect status --json), Bash(markitect config strategy.audit)
---
Run `markitect config strategy.audit` for how to audit: `sequential`, `parallel`, `auto` or the name of a custom workflow. With `auto`, audit sequentially for now. Change no file yourself.

- **Sequential:** start the markitect-auditor agent with the message "Audit the spec, walk the coverage list, and triage the unlinked mentions markitect vet --strict lists.", and add the Packages or Definitions the user asked to focus on or to leave alone, if any.
- **Parallel, or a custom workflow:** start the workflow with the Workflow tool, `markitect-parallel` for parallel or the custom workflow by its name, with the args `{"mode": "audit", "focus": "<what the user asked to focus on or to leave alone, or empty>"}`. It returns the auditors' reports.

When the audit has ended, give the user its findings, the most serious first, in plain words, each with its place and its question; merge findings that several auditors report. The missing links found come as one list, each with the Definition to link: the owner adds them, in their session with the markitect-architect skill, or by hand. The topics of the coverage list the spec neither states nor rules out come as one list too: the owner states each, or rules it out as the list says. The findings are for the owner to settle in the spec, with the markitect-architect skill or by hand: nothing is recorded and nothing is committed. When the audit runs as the step of starting a project in the markitect-architect skill, give the user none of them: that skill settles them and hands over.
