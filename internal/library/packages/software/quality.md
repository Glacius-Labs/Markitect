# Quality

How well the system must work, along the nine characteristics of ISO/IEC 25010:2023. Take it once per system, as the README of its quality part. Each characteristic says what the system requires of it, with links to quality requirements, or why it requires nothing. Take a [quality requirement](quality-requirement.md) for each single requirement.

## Requirements
The [quality requirements](quality-requirement.md), as links, one per line. Example: `[Pages load quickly](pages-load-quickly.md)`.

## Functional suitability (optional)
How completely, correctly and appropriately the functions serve the stated needs. Example: `Every loan the desk can make can also be renewed online.`

## Performance efficiency (optional)
Time, resources and capacity under the stated conditions. Example: `[Pages load quickly](pages-load-quickly.md)`.

## Compatibility (optional)
Working beside other products and exchanging information with them. Example: `The catalog export follows the format of the town library network.`

## Interaction capability (optional)
How well the intended users can learn, operate and use it. Example: `A new member renews a loan on the first try without help.`

## Reliability (optional)
Doing what it must, without failure, for the time it must, and recovering when it fails. Example: `Available during opening hours; after a crash the loans are restored within one hour.`

## Security (optional)
Protecting information and data, so that people and systems have only the access they are allowed. Example: `A member sees only their own loans.`

## Maintainability (optional)
How effectively and efficiently it can be changed. Example: `A new lending period is a change of one setting.`

## Flexibility (optional)
Adapting to changed requirements, contexts of use and environments. Example: `Nothing: the library has one site and one way of lending.`

## Safety (optional)
Avoiding states in which human life, health, property or the environment is endangered. Example: `Nothing: the system controls no physical device.`
