# Software project

The description of a software system. Its sections are the table of contents: each links to the README of its part. Take it for a system that fits the six chapters of the `software` template, once per system, as the README at its top. The `software` template also serves as a checklist for the part `project`, which is cut differently.

## Purpose
Why the system exists, as a link to the purpose part. Example: `[Purpose](purpose/README.md)`.

## Context
What is given from outside, as a link to the context part. Example: `[Context](context/README.md)`.

## Domain
What the system does, as a link to the domain part. Example: `[Domain](domain/README.md)`.

## Interfaces
How it is reached, as a link to the interfaces part. Example: `[Interfaces](interfaces/README.md)`.

## Quality
How well it must work, as a link to the quality part. Example: `[Quality](quality/README.md)`.

## Architecture
How it is built, as a link to the architecture part. Example: `[Architecture](architecture/README.md)`.
