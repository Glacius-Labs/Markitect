# Project preparation

Project owns structural acquisition and deterministic preparation. It retains the canonical model and dependencies, complete repository Census, exact registry and ignore inputs, authored ownership/scope, Manager instruction references and declared checks. Static context includes actual Definitions, provenance and inclusion reasons. A second acquisition observes the complete closure again; it never extends an old guard.

`Prepared` requires a complete committed capture. Its binding includes exact model inventories (including empty Packages), controls and Census bytes/modes. `Basis` is the narrower digest of what candidates are judged against: the checked model, its sources and dependencies, the Manager inventory and the execution, ignore and instruction inputs by repository path, mode and bytes. It leaves out the Census, the registry, acquisition boundaries and runtime profiles, so it stays the same across realizations and working directories; Run uses it for the already-verified fact ([DEC-073](../../docs/concepts/register.md#dec-073-change-minimality-on-an-unchanged-model)). Candidate validation preserves those inputs while allowing valid realization and registry changes. Known invalid candidates are repairable judgments; acquisition and incomplete observations are technical failures.

A registry link to a Definition the checked model no longer has is a well-formed record and an accounted artifact; accounting lists it under `Stale`, not as a failure. Preparation, `markitect check` and the Apply preflight therefore accept a model that deletes a realized Definition. `ValidateCandidate` is the complete check and refuses any stale link, as before publication; `ValidateCandidateFor(state, manager)` refuses only those within that Manager's Package subtree (Root: every shard; `CommandInput`: none, for the command's input and Assessment). A shard whose Package the model no longer has, removed or merged away, is orphaned (`Registry().Orphaned()`), not invalid: accounting hands each file it still explains to the Manager owning the file's area (Root where no area owns it), whose own live registration supersedes the orphaned one, and `StaleLinks` gives Root the shard to delete.

`markitect.execution/v2` declares `instructions` as an exact Package-to-ordered-file-list mapping, plus optional `ownership`, `scope` and `checks`. Check declarations select a logical profile, working directory, literal arguments, timeout and optional `requiredBy` Definition. Runtime images, executable metadata, provider protocols and finite invocation budgets belong to outer configuration and adapters.

`runtimeconfig` prepares closed static native/check profile metadata from acquired bytes. Project neither resolves that metadata nor starts Sessions, checks or working copies. CLI `check`, `context` and the guarded model view consume Project directly. The [current plan](../../docs/implementation-plan.md) owns execution authority.

`requiredBy` names the model obligation, not sufficient placement in a private working copy. A non-Root Manager runs a declared check only when it already covers that obligation and validated ownership confines the check directory and every nested file/directory area to its modeled subtree. Missing ownership or a root/cross-area directory keeps the check at an eligible ancestor or Root. Checks without `requiredBy` remain Root-only. Directory ownership does not declare build dependencies; Managers must prepare owned prerequisites before delegation or use reviewed correction on the current parent baseline.
