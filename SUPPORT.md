# Support

## Getting help

For general questions about Markitect, open a GitHub issue and describe what you are trying to do. Include the Markitect version, operating system, relevant command, and a minimal example when possible. Remove credentials, secrets, and private repository content before posting.

For unexpected behavior, choose the **Bug report** issue form. For a proposed capability or improvement, choose **Feature request**. Start with the [documentation map](docs/README.md). The [project workflow](docs/guides/project-workflow.md) describes the model-first source workflow, including troubleshooting; [Usage](https://github.com/Glacius-Labs/Markitect/blob/1f4a1ede214d05fd2fee615b3905207df7702426/docs/usage.md) links the immutable earlier release guide. [Architecture](docs/architecture.md) owns current product boundaries, [CONTRIBUTING](CONTRIBUTING.md) the development process and the [distribution guide](packaging/README.md#release-operations) release operations.

## Project-specific questions

Adopting repositories own their resources, checks, import scripts, and custom output policy. Markitect issues can clarify the product contract; questions about a particular repository's policy or acceptance belong with that repository's maintainers.

## Distribution

Source changes in this repository do not change an installed release. Check [GitHub Releases](https://github.com/Glacius-Labs/Markitect/releases) for published distributions and their documentation.
