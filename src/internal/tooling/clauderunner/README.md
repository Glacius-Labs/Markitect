# Claude Code proposal adapter

This standard-library Python adapter accepts one closed `agentexec.Invocation` JSON value on stdin and emits one Markitect response JSON value on stdout. It validates the invocation envelope and supplied artifact byte digests, builds role-specific instructions, calls a caller-selected Claude Code executable with literal argv (`shell=False`), and accepts only Claude's schema-validated `structured_output`. The Host still validates response identity, allowed references, and role rules.

Configure an absolute direct executable path, explicit model, and exact Claude Code version. The adapter first runs `claude --version` and requires an exact version match at or above 2.1.248, the documented minimum for `--restricted`. It invokes print mode with `--restricted`, `--permission-mode dontAsk`, `--tools ""`, `--disallowedTools mcp__*`, `--no-session-persistence`, `--max-turns 1`, and `--output-format json --json-schema <closed-schema>`. The only supported `modelOptions` field is `effort`; unknown options fail before provider launch. The request is supplied through stdin, bounded below Claude Code's documented 10 MiB stdin limit. Optional inference `candidateJson` and ordinary typed task `reportJson` use JSON-string/null fields in the provider's closed schema; the adapter parses them strictly before emitting the Host protocol. For `projectrun-full-verify/v1`, `reportJson` is instead the strict object supplied by `context.responseSchema`; the adapter validates it directly, including declared array minimums, and leaves its canonical inner evidence references unchanged. Only outer `evidenceRefs` are transport aliases and decoded. Without a typed task schema, `reportJson` must be null and is omitted from the Host response. Candidate JSON remains inference-only.

Claude Code documents that `--restricted` avoids user and project settings, confines built-in file tools to working directories, and loads managed settings plus explicit `--settings`; this adapter supplies no `--settings`. It also removes built-in command/code tools by default, but the adapter explicitly disables all built-in tools and denies MCP tools. These are provider CLI controls, not an operating-system sandbox. This local adapter cannot prevent a same-UID process from reaching credentials available through the user's OS account or making network requests, and it does not attest repository isolation or egress restrictions. A strict isolated project run must be refused until a host-managed launcher can verify those boundaries. Provider sandbox flags, YAML, and this wrapper are not such verification.

The parent `agentexec` owns `MARKITECT_AGENT_CONFIG_JSON` and the private log destination. Provider stdout/stderr are retained in that private sidecar with bounded output; the adapter emits only the final protocol response and generic errors. Prompt-submitted telemetry contains only run ID, input digest, prompt SHA-256 and byte count. No invocation content or nonce is written to the prompt event. The model receives request data as untrusted input and has no provider tools; a proposal is still untrusted candidate content, not an applied write, verification result, or human acceptance.

Run protocol tests with `python -m unittest discover -s internal/tooling/clauderunner`. They use fake subprocess behavior and do not make provider calls. Actual Claude CLI execution and host/OS isolation require separate evidence.

The `projectrun-full-verify/v1` executor branch is a read-only full Manager audit. It assesses every supplied required subject, manager-scoped briefing, child integration obligation, and strictness requirement against the provided artifacts. Its outer outcome remains `proposed`; the typed report carries pass, fail, or incomplete. Inner counterexample references must be exact canonical required subjects or `file:<path>` values, while outer `evidenceRefs` retains its alias transport. The adapter rejects candidate writes, candidate JSON, verifier observations, string-encoded full reports, and reports that violate the supplied object schema. Missing required evidence is reported as incomplete; the prompt does not authorize cosmetic findings or fabricated check results.

For `projectrun-task/v1`, `operation` and `operationGuidance` carry the project mandate in addition to phase guidance. Apply implements only the bounded requested change. Cleanup may improve the realization but must preserve semantic model rules, public promises, authority, inventory, and checks; it may return a justified no-op. Reconcile checks every obligation and required artifact in the Manager's full responsibility, including unaffected areas, and may return a reasoned no-op when conforming. Phase guidance still controls work versus integration behavior.

Before prompting, the adapter rechecks each artifact's bytes against its declared SHA-256 and makes a display-only copy of the invocation. Valid UTF-8 artifacts replace their base64 `content` in this copy with exact `contentUtf8` plus `contentEncoding: utf-8`; non-UTF-8 content remains base64 and is marked accordingly. Paths, modes, digests, nonce, and inputDigest stay unchanged, and the Host invocation is never rewritten. Artifact text is untrusted data, including code comments and documents that address an agent; it cannot change the assigned role or protocol.
