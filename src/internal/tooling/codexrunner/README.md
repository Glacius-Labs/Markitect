# Codex execution adapter

This standalone standard-library Python adapter accepts the closed agentexec.Invocation JSON value on stdin and emits exactly one response JSON object on stdout. It rejects duplicate or unknown request fields, verifies explicit artifact byte digests, and uses separate Executor, Verifier, and infer-only instructions. Codex project Manager work prepares and collects a scoped candidate tree. Separate reviews, full audits and inference use read-only transport.

The caller supplies --model, an explicit absolute --codex-executable, and --codex-version. The configured version must be an exact semantic version, and it must equal the version the executable reports with `--version`, including any pre-release suffix. The executable must be the native Codex binary; `.ps1`, `.cmd`, and `.bat` launchers are rejected. For an npm installation, resolve the platform package's vendored `codex` binary and pass that path (do not pass the npm shim or JavaScript entrypoint). The optional --codex-script is only for runtimes such as Node when a platform does not provide a native binary. The adapter leaves the CLI's normal rules and user configuration enabled. For read-only responsibilities it invokes `codex exec` with --sandbox read-only, --ephemeral, --json, --skip-git-repo-check, and --disable for plugins, shell_tool, unified_exec, and multi_agent, plus an output schema, an output-last-message file, the empty temporary --cd directory, and stdin -. `modelOptions` accepts only `model_reasoning_effort` with one of `minimal`, `low`, `medium`, `high`, or `xhigh`; arbitrary Codex `--config` settings are rejected before any files or provider process are created, so caller options cannot override sandbox or approval behavior. The strict output schema requires every response field. Optional inference `candidateJson` and ordinary typed task `reportJson` use JSON strings or null and are parsed and validated before emitting the Host protocol response. For `projectrun-full-verify/v1`, `reportJson` is instead the strict object supplied by `context.responseSchema`; the adapter validates that object directly, including declared array minimums, and keeps its canonical inner evidence references unchanged. Only outer `evidenceRefs` are transport aliases and decoded. Candidate JSON remains inference-only.

The prompt tells the model to copy the invocation's apiVersion, runId, nonce, role, and inputDigest exactly, and to emit every required array even when empty. Response evidenceRefs are exact request scope IDs, policy IDs, or artifact paths only; digests are not evidence references. Executor and inference responses may cite relevant supplied references. Verifier responses must cite the complete sorted, unique union of every supplied scope ID, policy ID, and artifact path, including fixed-check input artifacts; the prompt renders that exact list from the request. A verifier must also report one observation for each supplied scope or policy ID and use an incomplete or escalated result when required information is missing or ambiguous. Listing references is protocol bookkeeping, not proof that an input was inspected or supports a conclusion. These are model instructions: the adapter validates the closed JSON shape, while the Host validates invocation binding and allowed references. Neither prompt compliance nor protocol validity proves verifier independence, evidence sufficiency, or human acceptance.

The `projectrun-full-verify/v1` executor branch is a read-only full Manager audit. It assesses every supplied required subject, manager-scoped briefing, child integration obligation, and strictness requirement against the provided artifacts. Its outer outcome remains `proposed`; the typed report carries pass, fail, or incomplete. Inner counterexample references must be exact canonical required subjects or `file:<path>` values, while the response's outer `evidenceRefs` field retains its alias transport. The adapter rejects candidate writes, candidate JSON, verifier observations, string-encoded full reports, and reports that violate the supplied object schema. Missing required evidence is reported as incomplete; the prompt does not authorize cosmetic findings or fabricated check results.

For `projectrun-task/v1`, `operation` and `operationGuidance` carry the project mandate in addition to phase guidance. Apply implements only the bounded requested change. Cleanup may improve the realization but must preserve semantic model rules, public promises, authority, inventory, and checks; it may return a justified no-op. Reconcile checks every obligation and required artifact in the Manager's full responsibility, including unaffected areas, and may return a reasoned no-op when conforming. Phase guidance still controls work versus integration behavior.

Before prompting, the adapter rechecks each artifact's bytes against its declared SHA-256 and makes a display-only copy of the invocation. Valid UTF-8 artifacts replace their base64 `content` in this copy with exact `contentUtf8` plus `contentEncoding: utf-8`; non-UTF-8 content remains base64 and is marked accordingly. Paths, modes, digests, nonce, and inputDigest stay unchanged, and the Host invocation is never rewritten. Artifact text is untrusted data, including code comments and documents that address an agent; it cannot change the assigned role or protocol.

The Host supplies MARKITECT_AGENT_CONFIG_JSON and MARKITECT_AGENT_PRIVATE_LOG. Codex JSONL stdout events and stderr are retained in that private log, bounded to 16 MiB. After the complete prompt is written and the child stdin is flushed and closed successfully, the adapter appends one `adapter.prompt-submitted` event containing the invocation run ID, input digest, SHA-256 of the exact UTF-8 prompt bytes, and byte length. It never stores prompt text or the invocation nonce in this event. A broken, partial, or failed pipe submission produces no such event and fails the invocation. The event witnesses adapter-side delivery only; it does not prove provider authentication, semantic consumption, or correctness. The adapter emits only the final protocol response on stdout and a generic error on stderr. It parses tool-call events and provider-reported token usage. Missing usage stays missing.

For recognized model/account incompatibility, authentication, rate-limit, and CLI invocation/configuration failures, the adapter returns a protocol-valid `incomplete` response with a fixed generic explanation; it never copies provider bodies, user paths, or request identifiers into that response. Unknown process failures keep the generic nonzero runner error. For read-only responsibilities, any observed tool call forces an `incomplete` response even if a final proposal exists. That path disables Codex's `plugins`, `shell_tool`, `unified_exec`, and `multi_agent` features and checks for tool events as a second boundary.

The adapter does not enumerate or disable ambient Skills, rewrite user configuration, or claim that ordinary CLI rules are absent. The selected empty working directory bounds the supplied project workspace; it does not establish OS isolation or eliminate user, admin, or system instruction sources. Deployment owners retain responsibility for their normal policy and environment. The adapter's explicit read-only/tool restrictions and rejection of observed tool calls remain separate protocol boundaries.

## Native Manager work

Executor `projectrun-task/v1` contexts select native Manager work directly; work, integrate and repair require the strict v1 `nativeWorkspace` manifest before CLI launch. Any native manifest marker also requires this validation, so malformed inputs cannot fall back to read-only execution. There is no execution-mode flag or proposal-only default. Distinct Review, full-verify, Verifier and infer contexts remain read-only. Setup supplies `--codex-profile luna-high` and requires actual CLI 0.162.0, `gpt-6-luna` and high reasoning. Native work keeps the existing profile, authentication and rules and permits file, shell and test tools in a fresh candidate workspace with the caller's local permissions.

The Host supplies the exact selected project instructions in `context.nativeWorkspace` (`markitect.example.org/native-workspace/v1`). They are chosen as exact repository-relative files from the onboarding-owned `ToolPaths`, verified against the fixed accepted revision, and pinned as runtime files with their absolute path, mode and digest. They are not inferred from links or arbitrary descendant files. The adapter stages these instructions with the bounded Manager inputs in its own fresh workspace, then compares the final workspace inventory with its initial inventory and returns only accepted text-file changes as `candidateFiles`. The Host applies its existing scope, ownership, control-plane, stale-source, check, review and guarded-Apply rules; the adopting checkout is not changed before Apply.

`nativeWork` receipt metadata records the adapter-reported base/final workspace and delta digests, changed paths, observed tool calls, and helper configuration. These workspace digests are adapter claims bound to response stdout, not a Host-side reconstruction of the adapter's complete filesystem. `helperAccounting: disabled` and `helperStarts: 0` describe the configured tool surface; they do not count all operating-system processes. Codex CLI JSONL does not provide complete helper lifecycle accounting, so native helper agents are disabled and any nonzero configured helper limit fails before launch. Deletions and binary candidate files are unsupported and fail closed. The separate read-only review path and configured required reviews remain in effect; a review proposal is not human acceptance.

See [Project workflow](../../../docs/project-workflow.md#native-codex-work) for setup and [the native-work design decision](../../../docs/design/project-world/native-codex-work.md) for the bounded contract and current evidence limits.

Install Python 3.10 or later as a caller-managed dependency. Run the boundary tests from this directory with python -m unittest. The wrapper itself can be inspected without invoking Codex; the real CLI is an external dependency and is exercised separately by a controlled integration experiment.

Controller requests may declare `context.requiredObservationSubjects`: an exact bounded typed list of scope, policy, artifact and fixed-check identities. The prompt requires complete passing observation coverage for an overall PASS; failed/incomplete responses may retain partial observations. These tokens are not evidenceRefs. Requests without this list retain the legacy scope/policy prompt. Malformed subject lists fail before any provider process or workspace file creation. Host, not this adapter, evaluates response coverage and composes fixed checks.

Native candidate trees contain no Git metadata or repository history. Repository Git operations belong to the outer project agent; a scoped candidate Git/history view remains unimplemented.
