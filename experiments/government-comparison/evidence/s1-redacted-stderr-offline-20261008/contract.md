# Bounded redacted stderr: offline implementation contract

Assignment `s1-redacted-stderr-offline-20261008`, accepted base `c179b4107520492aa5f9b980c3767f4a4feaa86b`. Overseer explicitly replaces the self-imposed discard-only rule prospectively. The previous DPAPI capsule/human-reader proposal is not implemented. All historical source/evidence and frozen study inputs remain unchanged. This package implements and tests only a standalone prospective collector/output path: **zero runtime allocation**, no app-server/CLI/candidate/provider/Actor/product/study start, no session freeze, no current client wiring. Architect retains the heavy slot.

## Implemented path

`RedactedStderrCollector(stop_event, known_paths=())` uses the existing probe pattern of a terminal event, bounded chunk ingestion, cleanup-only continuation and a final receipt. It cannot launch a process or send an RPC. A future separately bound client must retain its existing immediate stderr pump signal, RPC admission guard and finite cleanup, then call this collector. Offline tests exercise ingestion, stop ordering, redaction, rendering and the actual exclusive file writer; they do not prove live transport behavior.

| Step | Exact behavior |
| --- | --- |
| Terminal | `feed(nonempty)` sets the supplied stop event before decoding, scanning, redaction or output, including fully suppressed/error cases. Nonempty continuation requires `cleanup=True`; the collector adds no cleanup deadline or new runtime permission. |
| Selection | First four physical complete lines only, even if dropped. At most1,024 original input bytes including LF/CRLF; no search for replacement lines. A cap-cut or unfinished line is dropped. Pending memory is bounded by the input budget, stricter than the old16KiB transient ceiling. |
| Suppression | Invalid UTF-8, remaining control/escape/Unicode control-format characters, literal Unicode/hex escapes, malformed object-shaped JSON (including a timestamp/severity prefix), escaped object-shaped JSON, known/ambiguous credential-bearing lines and redactor exceptions are fully dropped. Only recognized numeric `ESC[...m` SGR sequences are removed; unsupported forms are suppressed. No raw exception text is emitted. |
| Credentials | Authorization/Bearer/Basic; sensitive token/secret/password/authcode/API-key/credential/private-key/signing-key words and assignments (including JSON keys); cookie headers; PEM key/certificate headers and following block lines; JWT shapes; recognizable OpenAI/GitHub/AWS/Slack/Google patterns; credential URLs; long ambiguous base64-only lines. Rules are conservative and may suppress useful diagnostics. |
| Replacement | URLs, email addresses, absolute drive/UNC/POSIX paths, and exact known home/probe paths use fixed markers. Quoted paths preserve surrounding error text. Unknown unquoted paths redact their remaining line tail to avoid exposing space-containing path suffixes. Caller-known forms and slash variants are also handled. |
| Public receipt | `finish()` returns metadata only: observed/selected byte counts, complete/included counts, original dropped-line numbers/reasons, cap/truncation/incomplete flags and known-pattern-only guarantee. No excerpt text, raw data or stderr-content fingerprint. |
| Private output | `render_private()` returns UTF-8 JSON with that metadata plus sanitized text, original line numbers, redaction markers and SGR-removal flags. Whole text records are dropped with `output-cap` if encoding would exceed2,048 output bytes including metadata/newline. No byte-cut output or logging. |
| File path | `write_private_excerpt(directory)` writes only sanitized bytes, exclusively, to `redacted-stderr.json` in an absolute, existing, empty, non-link external directory outside this repository. It produces no console output. Directory access/private destination selection are obligations of the future grant, not an ACL or OS-isolation guarantee. |

The module does not assign causal categories. A later authorized diagnosis task may read the sanitized file through a targeted local tool read and derive `reported_configuration`, `reported_authentication_or_authorization`, `reported_transport`, `reported_runtime` or `other_or_insufficient`, with original line number and uncertainty. Those describe the message, not verified root cause, enforcement, historical equivalence or product acceptance. This offline package captures **no real message**; it cannot reconstruct R2's lost lines.

## Retention and honest limits

A future sanitized excerpt may exist only in a newly bound private local external evidence folder and enter Scientist/Overseer context through a deliberate targeted local tool read. It must not enter public Git/PRs, callback text or product-implementer handoffs. The extra local file must be deleted after diagnosis/closure. **The sanitized tool read becomes part of the task history/model context and may remain there; deleting the file does not erase that history.** Raw stderr/frames and their content fingerprints must never enter either path. No DPAPI storage or mandatory human reading step exists.

Known-pattern redaction cannot establish perfect secrecy. Unrecognized secret formats, obfuscations and context-dependent sensitive text can remain; same-user processes/destination access and retained model history are further explicit limits. Ambiguous recognized-sensitive lines are suppressed; malformed/unsupported content can lose diagnostic value. More than four lines, cap-cut text and output-cap records are deliberately unavailable. This is a small probe-specific filter, not a general privacy parser or logging platform.

The remaining runtime controls stay unchanged in any later grant: first stderr terminal; no further RPC/turn/tool/interrupt/retry; valid thread response also terminal; no policy/auth/profile/model/provider changes; exact source/request/freeze/binary/schema/input/authority pins; Windows Job before GO; existing metadata33s/thread15s/native50s/cleanup10s/controller65s/outer80s, queue64/frame1MB/raw8MB/notifications2048. Runtime use needs a new finite grant and a free slot. Classic main integration does not change frozen study pin `c91363b7ac4decbe87212ff0f588b5451581a152` / v0.14.1 or its inputs. All six study cells remain NOT RUN.

## Focused verification

Twelve distinct synthetic unittest cases cover ordinary readable messages, stop-before-redaction even when every line is suppressed, credential patterns, private output/receipt separation and exclusive write, path/URL/email replacement, SGR versus other controls, chunk/CRLF/split-UTF8 boundaries, invalid/unfinished lines, first-four selection,1,024-byte cap,2,048-byte output fallback, and malformed/escaped JSON plus fail-closed redactor errors. No actual secret or real stderr is used. The first11-case execution had one fixture error (continuations missing `cleanup=True`); fixture correction passed11/11. After two narrow source hardenings, only the changed path case and new structured-line case ran:2/2 passed. Independent review then found a known private-key label gap and a prefixed-JSON gap; each source correction reran only its affected existing method with added subtests:1/1 and1/1 passed. No unchanged full-suite rerun occurred.
