# Independent source review

I reviewed the R3 candidate client, its source/input validation and six focused synthetic test results against the fresh grant and accepted account-routing contract. I found no material source blocker.

The candidate derives from the real R2 runtime client and `run_once.py`, whose hashes are pinned in the candidate. It contains no offline fake-mode switch. The exact account observer is byte-identical to the accepted offline helper, checked by SHA-256 before import, and bound in the request/source contract. The new route is limited to `account/updated`; it runs after the shared frame, notification-envelope/count/timestamp, lifecycle-phase, and provisional checks. It also requires the validated own thread, a dispatched turn request, no prior protocol stop, and the collector’s own thread ID. Only an `observation-only` result continues; negative classifications stop through the existing fixed refusal path. The existing notification maps and pinned helpers/collector remain unchanged according to the source comparison.

The observer validates the pinned schema first, applies the stricter local shape and explicit `chatgpt` mode rule, and receives the complete raw frame size. Its parameter and frame caps are each 4096 bytes, its observation ceiling is eight, and its fixed projection is capped at 2048 bytes. The emitted `accountStatusObservation` contains bounded classification metadata, not account, plan, authentication, or payload values. It is connection/account telemetry only and does not establish account ownership, thread identity, or authentication success. `turn_requested` is a handling-phase condition after request dispatch; the unchanged pump/queue does not establish physical frame-arrival chronology.

The focused suite ran once: all six groups passed in 0.321 seconds, with zero real native starts. The tests exercise the actual client consumer through a synthetic process fixture, including compatible and negative account notices, unknown methods, pre-thread/pre-turn rejection, frame-size and observation limits, cleanup/interrupt behavior, and grant/window binding checks. This is not evidence that the provider emits this notification or that a native account state, model response, or product behavior has been validated.
