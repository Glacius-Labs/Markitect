# Projection assurance: research alignment

Status: orientation assessment during the projection-first source slice, not a new language proposal. The owner supplied the [research thesis](../research/ontology-projection-assurance.md) as context while developing further models in parallel. It refines the existing desired-state direction; it does not authorize implementing every named concept.

## Decisions carried into this implementation

- One semantic owner per selected normative fact; downstream representations cannot redefine it. Narrative meaning may remain human-owned, and explicit external/vendor/tool inputs retain their owners.
- Custom vocabulary stays in activated adopter Domains/packages. Core remains generic; projection contracts and technology-specific checks stay outside Core.
- AI returns a candidate representation. The synthetic proof uses independently owned fixed checks; agent-authored tests alone do not establish independent assurance. Generic Project contracts execute configured checks and do not prove their independence or semantic sufficiency.
- Context delegates a bounded responsibility using the existing declared closure and explicit contracts. No promise of the mathematically smallest context or complete intent coverage is made.
- Ownership accounting, deterministic representation matching and behavioral evidence are separate claims. A green ownership check is not semantic proof.
- Unknown/unavailable evidence remains incomplete; a known contradiction is drift. Technical evidence and human authority remain separate.

The new pure Projections Module describes explicit source/target/materializer/freedom/check contracts. Host supplies normalized IR, captured artifacts, registered rendering, trusted check execution and guarded Apply. Existing finite Domain semantics are unchanged. Two fresh synthetic candidates are tested against a fixed independent checker, not self-certified or adopted as semantics.

## Boundaries not implemented by this slice

| Research direction | Current boundary / next evidence needed |
|---|---|
| Obligations and assurance cases | Named Project checks and bound contract evidence exist. No new Claim/Obligation primitive, rubric language or complete assurance tree. Prove two recurring cases before considering a shared semantic addition. |
| Integration assurance | Contract prerequisite state is explicit; it is not proof that independently passing parts compose. Projects must declare integration checks. No implication `valid(A) and valid(B) => valid(A+B)`. |
| Scoped AI semantic reviewers | Not an implemented verification authority. Compare independent rubric judgments, uncertainty, correlated errors and executable counterevidence before acceptance design. |
| Thin universal provider bootstrap | Existing deterministic provider views remain supported projections. A replacement bootstrap/context experiment is future UX work, not an implicit removal or promise of reduced duplication. |
| Coverage matrix | Reports expose exact owners, sources, targets, checks, provenance and missing evidence. No percentage of project understanding or globally complete semantic coverage. |
| Architecture/language re-projection | Plausible research experiments, not automatic migration capabilities. Any changed observable contract remains canonical intent. |
| Continuous autonomous development | External actors can call bounded operations. No background controller, autonomous integration permission or guaranteed drift prevention. |

## Research evaluation

RQ1 (expressiveness): record whether meaningful intent requires implementation-level modeling, generic language changes or awkward authoring. RQ2 (projection): use fresh candidate diversity, misses, exact target ownership and materialization outcomes. RQ3 (verification): inject independently selected contradictions; record detections, misses, unknowns and integration obligations. RQ4 (human attention): measure modeling/review/maintenance and remaining human corrections in a real owner-reviewed slice under [Measurement](../measurement.md). Synthetic convergence establishes feasibility only.

Preserve the prior gauntlet and adoption negative findings. The thesis fails if canonical upkeep costs more attention than it saves, important drift escapes checks, integration assurance dominates cost, or apparent assurance creates false confidence. New parallel owner modeling is input for later review; no inferred fact becomes policy without explicit adoption.
