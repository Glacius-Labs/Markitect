# Frozen evaluation harness

This directory contains the evaluation material prepared before any comparison trial. It does not contain trial results. Keep it outside all agent checkouts and do not include it in task packets.

The runner targets .NET 8 and references the Meetings Application project at the selected adopter root supplied as `AdopterRoot`. It compiles the unchanged upstream `ApplicationTests.cs` by linking the copy at `.artifacts/adoption/upstream/src/Modules/Meetings/Tests/ArchTests/Application/ApplicationTests.cs` (SHA-256 `2aef4aef91032ff32c60aca30a7e8b10a7235ad9d05c767a5a4c3951471463a3`). The runner's local `TestBase.cs` contains only the helper methods and `ApplicationAssembly` property that this source file uses. It omits the original `DomainAssembly` and `InfrastructureAssembly` properties because the selected source bundle does not contain the test infrastructure project and those properties are unused by `ApplicationTests.cs`. This is a bounded linked-source runner, not the upstream test assembly or a full upstream test-suite result.

`Original-TestBase.cs.txt` preserves the complete upstream helper source as evidence. `LICENSE` preserves the upstream MIT notice. The linked `ApplicationTests.cs` remains at its upstream path and is not copied or edited by this harness.

For Task 2, an additional NUnit test reflects over exactly `AddMeetingAttendeeCommandValidator` and `CancelMeetingCommandValidator`. It constructs each command using its upstream constructor, checks that an empty Guid fails validation, and that a non-empty Guid passes. This tests the compiled validators' behavior; it does not prove dependency injection registration or additional business rules.

Before an agent starts, capture its own input tree as the baseline: `evaluate.ps1 -AdopterRoot <root> -Task task1|task2|task3 -Arm <label> -OutputDirectory <baseline.json> -CaptureBaselineOnly`. After the trial, run `evaluate.ps1` with the same task and arm, that baseline path, and an output directory outside the agent checkout. The script builds the Application project, runs the linked architecture tests (and the Task 2 runtime validator test), evaluates the selected project's `ProjectReference` graph with the tracked checker at `experiments/real-project-adoption/checks/check-module-project-references.ps1` and its frozen owner/layer map, and records a JSON report. It records build/test/reference exit codes and changed-file counts against that pre-run file manifest. The reference checker receives a temporary operator-only root containing a junction to the adopter's `src` and the frozen public source manifest at `experiments/real-project-adoption/evidence/source-manifest.json`; the shim and junction are removed after evaluation and never enter an agent checkout. All command output is captured in the report. Restore uses `https://api.nuget.org/v3/index.json`.

The reference checker evaluates only the 18 explicitly mapped Application, Domain, IntegrationEvents, and BuildingBlocks projects. Its result describes evaluated `ProjectReference` items and their owner/layer policy; it says nothing about runtime dependency mechanisms. SQL changes require human source review. No database/runtime is available in the selected subset, and the linked architecture tests do not establish SQL semantics.

Do not compare raw changed-file counts as productivity or safety measures. They are descriptive only. The script does not inspect or grade agent reports against hidden oracles; oracle scoring remains a separate evaluator responsibility.
