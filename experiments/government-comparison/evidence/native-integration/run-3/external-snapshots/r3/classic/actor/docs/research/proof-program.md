# Capability proof program

Historical protocol-v1 checkpoint. The later owner steer supersedes its blanket implementation pause; [proof-readiness decisions](../design/proof-readiness-capabilities.md) govern continued implementation and fresh trials. Frozen observations and their FAIL status remain unchanged.

Protocol v1, frozen before execution on 2026-10-06. Product baseline: integrated main `75031b8eca8161b0a247414741828bfb2e1d9069` (PR #80). Published v0.13.0 remains unchanged. [Vision](../vision.md) owns the thesis; this program tests it rather than extending it.

## Inventory and architecture freeze

The [implemented inventory](implemented-capability-inventory.md) was collected read-only before this change. Source, not aspirational design, determines available operations. No Core, Host, Module, schema, package, CLI or release behavior changes are authorized by a successful demonstration alone. Earlier negative findings, invalid runs, unopened holdouts and private adopter boundaries remain intact.

The inventory exposed a specified stop condition: ordinary canonical reconciliation acquires complete snapshots before selecting semantic inputs. This checkpoint therefore confirms that finding with a small witness. It does not proceed to new AI trials, a benefit benchmark, longitudinal evolution or technology re-projection while that condition remains unresolved.

## Frozen first checkpoint

The witness reuses the exact-pinned public canonical-projection fixture. Two existing representations share three commerce Definitions; one .NET-only ProjectionPolicy changes. A unique, unrelated Billing note is outside all canonical inputs and target roots. Harness-created synthetic materialization records with a placeholder plan digest are supplied explicitly and remain **unverified**; no semantic convergence is inferred from them.

Expected narrow positive observation: one scoped materialization proposal, one unchanged representation, and separately reported conservative evidence invalidation. The CLI is read-only. Target files, candidate tasks and checks are not executed.

Falsification observation: candidate, base and working-tree acquisition each contain the unrelated Billing bytes. Count materialized snapshot entries and byte lengths, not filesystem syscalls, tokens, agent reads or human attention. Compare those measured acquisitions with the CLI's same public pipeline and identical derived plan.

Decisive negative control: remove only the unrelated note's unique loose Git blob from the isolated temporary repository. Selected canonical Git blobs and commits remain present. A fresh normal CLI reconcile-plan must now fail acquisition before semantic parsing, naming the unrelated file. Restoration is confined to the temporary fixture. A successful no-work plan after a full read is not targeted-execution success.

Freeze fixture paths/bytes, Module pins, mutation, expected classifications and this negative control before running. Git author/committer identity and timestamps are fixed for portable content/revision comparisons. Record real fixture revisions, model/snapshot/plan digests and supplied record IDs. No fake Git revision or synthesized policy result may stand in for an executed trial.

## Claim sequence and gates

The [matrix](capability-matrix.md) separates existing narrow evidence from new trials. C1–C13 retain the owner's meanings. After this stop gate is resolved, the intended order is:

1. Five structurally typed ontologies (C1); disjoint Module capabilities/imports and replacement (C2/C11).
2. Fresh unknown ontology, actual bounded AI candidate and independent checks; absent **and insufficient** policy controls (C3).
3. Canonical change through execution and verification (C4); Orders/Billing plus three independent representations with read/check/work measurements (C5).
4. One-to-many and many-to-one provenance (C6), real unknown/excluded discovery (C7), unchanged-intent drift repair (C8).
5. Actual implementation-level leaf/UseCase/Module composition failures (C9); fresh independent Executor/Verifier adversarial trials (C10).
6. Goal-led greenfield (C12) and a real owner-reviewed brownfield slice (C13).

Only after those sufficiently pass: matched strong conventional versus Markitect workflow; concurrent stale work; 30–50 meaningful sequential changes; technology re-projection. These have no recorded outcome yet. Owner review cannot be replaced by an automated reviewer or a supplied review reference. Private evidence requires its exact approved acquisition boundary; this checkpoint uses only public fixture bytes.

## Evidence rules

Every run records Claim, Setup, Frozen inputs, Canonical revision, Module versions, Mutation, Expected behavior, Negative control, Observed behavior, Artifacts touched, Context supplied, Checks/evidence, Human interventions, PASS/PARTIAL/FAIL, Limitations and Follow-up. NOT RUN is a trial state, not FAIL or a favorable outcome. INVALID preserves an infrastructure-confounded run and its reason; corrected trials receive distinct identities.

Ownership, byte integrity, behavior, composition, agent independence, human approval and economic benefit are different claims. Record only observed metrics. Uninstrumented calls/tokens/human minutes are unavailable; elapsed automation time is not attention. Supplied records are operational claims, not semantic truth. Absence of writes is not proof of reduced work.

## Stop decision

Pause at the first demonstrated stop condition and report before expanding experiments or product work. Do not preemptively replace the complete snapshot/digest contract with selective capture: that would change identity, unknown-artifact visibility and freshness semantics. The smallest next design assessment must preserve those boundaries while separating required canonical acquisition, declared target observation and conservative evidence refresh. This document proposes no implementation of that assessment.

This checkpoint can establish a falsification and a reproducible gate. It cannot complete the whole proof phase, claim human-attention savings, authorize a release, or prove reliable AI projection.
