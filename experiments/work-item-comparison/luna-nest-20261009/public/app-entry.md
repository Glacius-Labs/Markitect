# Native App entry for the existing nest

This is a prospective, manually orchestrated entry using the available `collaboration` tools. It does not call a Python/CLI agent API. Original native CLI pilots stay terminal and retain their original sources, profile receipts and failure accounting. The App uses a different runtime. A new exact enabled owner grant is required before any measured App actor starts.

`app_ledger.py` only reserves and records case-local entries. It imports the existing nest file/Git helpers and uses the existing lock. It invokes no model, provider or collaboration tool. Reservations are cooperative: actors with normal App tools can bypass this file, so it is not proven hard enforcement, OS isolation or a global concurrency cap.

For a fresh primary, helpers/inner roles and final assessor, reserve an entry before the native call and invoke `collaboration.spawn_agent` with `fork_turns="none"`, `model="gpt-6-luna"`, and `reasoning_effort="high"`. Record the exact returned own handle, task name, call result and time. No cwd argument exists in this tool. A continuation uses only an explicitly returned own handle through `followup_task`, after reserving another outer entry. Failed requests still consume reservations; record actual tool call/model start separately and never infer a turn from a reservation alone. `send_message` to an already active own actor does not start an idle actor; use it only for resource/stop coordination, never case advice. Do not enumerate or message unrelated agents.

The initial semantic task is exactly the existing `nest.PROMPT`; a fixed continuation is exactly `nest.CONTINUE`. Add only execution bindings: own absolute project path, own public rules, model/resource bounds and own ledger location. Do not supply foreign case candidates/code/solutions, private implementation-specific history, private holdouts/evaluation vectors/judgments or semantic evaluator feedback. Actors do not deliberately read other case/chat/memory sources. Fresh calls request `fork_turns=none`; that selection is not proof of system/developer/workspace sanitization. Common system/developer/tool/workspace instructions and general App memory/setup hints are allowed when they contain no foreign case solution or private evaluation material. Legitimate history from the actor's own current task and previous station is allowed.

Record actual inherited CWD, instruction origins, tool scope and known exposure categories without copying private content. Native tools inherit the execution owner's App context; directing file/shell calls to the fresh case does not change inherited CWD or provide OS isolation. A generic memory or parent-history label alone is not evidence of forbidden case content and does not itself stop work. Concrete known forbidden exposure is terminal. Unresolved case-specific exposure is reported as uncertain, never silently declared clean; do not seek more foreign material or use uncertain case-specific material as implementation advice. Continue ordinary work from the allowed own/public sources without an extra context probe, helper or sanitizer. This prospective distinction applies identically to both future arms; it does not rescore closed runs or grant a retry.
