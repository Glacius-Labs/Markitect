# Common independent assessment

[The study contract](study-contract.md) owns the ordinary CLI user question and validity limits. Assess total method benefit/burden, including initial modeling and owner/Scientist assistance; retain setup and later work separately. Do not treat transport equality as proved, hide product failures, or generalize small synthetic cases to all ordinary users. Functional checking may hide labels/transcripts, but model files can reveal the method; report that blinding limit.

Assess frozen main against the requirements released through the retained station, including all earlier behavior. Unmerged work is evidence of incomplete implementation, not completed behavior. Give the assessor only the public case/rules, snapshot identity and necessary exact tools; exclude implementer transcript, private earlier assessments and the other arm. The assessor does not repair the candidate. Future requirements not yet released are NOT RUN, never failed retroactively.

The finite public checker is `public/common/checks/acceptance.py`, copied into each case as `checks/acceptance.py`. A future authorized assessment runs it on frozen main with `--case roombook|readinglog --station 1|2|3|4 --repo PATH`. It covers selected examples, not complete correctness. Add independent cases from the same public requirements: boundaries, invalid inputs, state preservation/restart, regression, filters/composition, CSV atomicity/escaping, compatible rename and source/document consistency. Baseline behavior belongs to Brownfield assessment. Keep candidate test suites as evidence rather than treating their pass alone as acceptance.

The new checker distinguishes a missing application entrypoint from checks that could not execute, reports return code/stderr before JSON decoding, and marks harness execution errors separately. Those are new reporting repairs; historical assessments are unchanged. Preparation tests use fabricated process outputs only. No real case acceptance, implementing actor or product was run in this pass.

Use PASS / FAIL / NOT RUN / EVALUATION_ERROR / unknown with evidence, affected rule/scope/severity and detected/repaired/remaining state. Record false alarms/unverifiable rules. Separate function/rules, durable state/regression, code quality/changeability, source/docs/config consistency, tests/docs, architectural drift/continuation and method conformance. Conventional has no model upkeep obligation; Markitect model/generated-view/realization/check consistency is its method-specific assessment. Artifacts alone earn no business-quality credit.

For S3 distinguish requested collaboration from observed starts, genuine overlapping execution, contributions, merges and reviews. For S4 review active behavior/interfaces, source, tests, docs/config and Markitect canonical model/views; intentional legacy aliases, stored data and historical logs are allowed. Text matching alone cannot decide rename consistency.

Retain setup and initial model preparation separately from implementation, model upkeep, checks, failed attempts/repair, review, merge, context resume and oversight. Preserve actual UTC intervals and scoped role/start/end/usage receipts. Do not sum overlapping wall intervals or duplicate parent/child tokens. Agent active time, manual interventions and human active time are distinct; unknown receipts/prices/cost stay null. Four waves of one project are dependent observations. No freely weighted quality total, automatic winner or human acceptance follows from one small pair.
