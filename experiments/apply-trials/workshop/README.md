# Workshop: bounded R1 input

One operator maintains customers and parts, opens repair jobs, reserves and consumes stock, writes and pays invoices and reads the combined workshop report. W1 contains **26 Definitions**, **six named Packages** (`shop` plus five children), and **seven Manager roles** including the ordinary Root. The source WIP `e514b9543c99c049c550bf177a433047bdb00c6d` called this 24/5; that count was not adopted. No meter, depth or fan scenarios were adopted.

R1 uses **W-G**, a model-only start. Its three arms receive identical requirements and freedom. Only direct/staged's explicit strategy selection differs. The plan arm gets all Definitions and provenance through the existing renderer, with no reference, fault key or oracle. `execution.yaml` defaults to direct; packet generation explicitly selects either strategy. The case does not prescribe the reference's module organization or JSON storage layout.

**Controls, never extra D attempt slots:** W-N is the conforming reference. W-M adds three independently discriminated faults: w1 rounds the loyal parts discount half up; w2 counts unpaid invoices toward loyalty; w3 lowers the low-stock report threshold. These controls exercise rounding, payment/customer/billing integration and parts/report integration. The oracle computes expected public values from model statements, rather than importing reference functions. Its 22 checks cover stated workflows, exact records, input boundaries, ordering/filtering, reservations and consumption, prices/tier snapshots, tax rounding, refusal preservation and bounded storage/CLI failure cases. Automated reference tests are a separate artifact, not its answer key.

**Limits:** this is one local CLI with one operator, not a representative application sample. No GUI, network, authorization, concurrency, schema migration, business-calendar workflow or production storage durability is modeled or tested. The oracle is not exhaustive proof of every clause or input combination. “Malformed data” is underspecified for syntactically valid JSON with invalid internal records; the oracle's corruption controls use invalid JSON/encoding and unreadable paths, without imposing the reference's schema. Atomic replacement has bounded public refusal/leftover checks, not crash/power-loss durability evidence. README command presence and test discovery are artifact checks; they do not establish complete documentation or test quality.

Provider-free controls: `python -B -m unittest discover -s experiments/apply-trials -p test_workshop.py` from the repository root. Structural preparation and independent plan coverage use the actual Markitect CLI with explicit Core/Software dependency manifests, as for the existing packets. A green control validates the kit, not a new Apply or ordinary-Agent run.
