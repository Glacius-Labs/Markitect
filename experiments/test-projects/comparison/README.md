# Documentation and one coding Agent

These source packets prepare the owner's ordinary-documentation comparison from
[Measurement](../../../docs/measurement.md#quality-first-comparative-evaluation).
They contain no study results or execution authority. Measurement owns the
procedure, controls and interpretation; this directory supplies project inputs.

The ordinary arm receives documentation with the same intended world as the
matched canonical model, then one coding Agent reads it and implements it.
The Markitect arm receives that canonical model and uses the product's own
realization process. An independently prepared assessment stays outside both
writers' packets and evaluates both against the same hidden expectations.

## Materialize a matched pair

This is a manual source preparation recipe. It launches no Agent, provider,
container, Apply or assessment. A separate finite run grant and a completed
manifest are necessary before any future execution.

1. Select a committed packet revision containing the reviewed ordinary
   requirements, prompt and manifest. Resolve it to a full Git SHA and retain
   that value outside the writer packets. The manifest names the independently
   integrated model revision. A packet does not need to contain its own future
   commit SHA; bind that externally when selecting the packet.
2. Read every `unbound` entry in the manifest. Bind the actual application
   snapshot, model/dependencies, document/prompt bytes and independent assessment
   privately. Bind model, effort, tools and versions, permissions, runtime,
   budgets and authorized freedom for both arms before execution. Unknown
   values remain unbound and prevent claiming a ready or matched run. Do not
   infer a runtime image, SHA, model setting, price or time from this document.
3. Extract sources from their named committed revisions, preserving repository
   paths and Git blob bytes. `git archive REVISION -- PATH...` can package the
   selected paths without a checkout's line-ending conversion. Compare the
   raw bytes with the recorded SHA-256 values. A source manifest includes every
   necessary model manifest, lock, Definition and dependency; a directory name
   or model digest alone does not bind those bytes.
4. For an isolated pair or the first longitudinal stage, create fresh, isolated
   application workspaces with identical initial
   application files, modes and state. Record a content inventory for each and
   verify equality before adding either requirement representation. For an
   empty greenfield application, retain an explicit empty inventory. For an
   existing application, retain its actual revision and complete inventory.
   Keep any common bootstrap files identical and account for their preparation.
5. Add only the ordinary requirements as `requirements.md` and its instruction
   as `implementation-prompt.md` to the ordinary writer's context. Materialize
   the corresponding complete canonical model and dependencies for Markitect.
   The ordinary writer does not need this repository, the canonical YAML or
   this coordinator manifest. Keep the same actual implementation tools,
   environment, model/effort settings, permissions, budgets and freedom wherever
   they are shared; record the intended difference in realization process.
6. Have the independent assessor bind one assessment package outside both
   writer contexts. Do not expose hidden tests, expected answers, evaluation
   files or assessor findings to either writer before its first result is
   frozen. Writer-authored tests are realization artifacts, not the independent
   assessment. Retain packet and assessment access inventories.
7. Predeclare the same start of human-attention accounting for both arms,
   including initial specification authoring and preparation. Record ordinary
   document authoring and upkeep as well as canonical model authoring and
   upkeep. Existing preparation is not free: retain observed effort when
   available, or mark it unavailable. Also count discovery, review, clarification,
   correction prompts, reassurance reviews, interventions and recovery. Keep
   human attention, elapsed execution, token use and actual monetary cost
   separate, preserving unknowns and failed attempts.
8. At the first delivered result, stop writer changes and bind the actual
   application inventory/revision, writer output, transcript and declared
   checks before any human review, correction or extra reassurance request.
   Preserve that first result. Later assistance and corrected candidates receive
   separate records; they do not replace the first attempt.

The prompt prescribes one coding Agent and ordinary build/test access. It does
not prescribe Managers, an extra reviewer, delegated subtasks or a second
conventional organization. Independent outcome assessment sits outside both
writer arms. Markitect's internal review belongs to its process and is recorded
as such. Any stronger prescribed conventional organization is a separately
labeled arm under Measurement.

## Review the source packet

Review ordinary requirements against every intended obligation of the bound
canonical model, including relationships, types, interface, refusal behavior,
delivery requirements and permitted implementation choices. Check source hashes,
complete dependency packaging and equal starting application state. These are
source checks; they do not demonstrate a working application or comparative
benefit. A future assessment prioritizes independently observed quality and
intent fidelity, with attention, elapsed time and money reported separately.
