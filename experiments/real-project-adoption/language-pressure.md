# Pilot pressure observations

No Core language feature was added. These observations are from one extracted adopter and should not be converted into universal requirements.

| Observation | Current expression / boundary | Classification and next evidence |
|---|---|---|
| The v2 owner means selected state-changing Commands, but the language does not inspect arbitrary intent fields or infer business state changes. | Explicit `validation: required` labels plus a finite `intent == Command` guard. Untagged Commands are outside the rule. | Adopter selection/coverage maintenance; existing selector pressure, not evidence for a new primitive. Repeat on owner-maintained cohorts before designing anything. |
| Feature ownership should agree with UseCase ownership. | One bounded `same-target` constraint over declared singleton paths. The new Query can reuse the same explicit label and references. | Existing language succeeds; no extension needed. |
| Actual .NET project references include imported build-target behavior. | A project-owned MSBuild observation with 18 explicit project mappings. Core sees source bytes and the declared check, not C# or MSBuild semantics. | Adapter/check concern. The literal XML reference adapter alone would not establish these imported references. |
| A contract update can intentionally produce failed policies, yet Context/Impact then refuse their normal output. | The failed check/model report exposes the two failures; a narrow temporary exception permits subsequent context, with the violation retained as waived. | Application workflow/diagnostic problem. It needs investigation without a new assertion or weakening structural failure boundaries. No fix was made during the experiment. |
| Package/configuration and inventory changes cause conservative impact. | The current fallback names all resources even when the added policy cohort is small. Known local input changes can be measured separately. | Impact precision/explanation and adopter review UX; do not claim false precision or remove the fallback without sound dependencies. |
| Context can contain a relevant graph but omit the governing read ADR. | Narrative links explicitly select ADR 0007/0017, not ADR 0009. The agent follows the existing code pattern; the omitted ADR is still a coverage miss. | Bad adopter source selection plus context-review UX. Record the miss; do not repair the frozen experiment to make it win. |
| Canonical model records need continued upkeep beside original ADRs and architecture tests. | Explicit UseCase/Handler records, shared references, source paths and complete versioned Domain definitions. Generated views are projections. | Authoring/maintenance cost. A future authoring aid may reduce mistakes while retaining an explicit effective definition. No inheritance/macros are justified. |
| IntegrationEvents project ownership does not prove which contracts a caller uses or that no runtime coupling exists. | Canonical Interface intent plus bounded evaluated project-reference evidence; Infrastructure coupling remains out of coverage. | Specialist evidence and human review; identity allowlists, runtime analysis and a universal ontology remain unproved. |

Aggregate fan-out, incoming/exclusive Handler ownership, mixed-relation cycle groups, identity-pair allowlists, arbitrary spec-field selectors, Pattern/Trait/Composition and Domain/package inheritance remain intentionally unsolved. This pilot establishes no repeated generic semantic inability that would justify another Core primitive or arbitrary graph query capability.
