# Autonomous A/B longitudinal gauntlet

The [vision](../../docs/vision.md) states the thesis; [measurement](../../docs/measurement.md) owns the limits. This synthetic experiment compares mechanism behavior and accumulated architectural drift under a strong conventional workflow (A) and the same engineering intent mediated by Markitect (B). It does not measure real human attention, market demand or production reliability.

## Freeze and parity

The source candidate is clean main `adef79d935399f8ac63ad874dbdeab8d15c418a1`, built with Go 1.27.1. Its embedded version remains 0.13.0; this is a new source build, not the published release binary. No production changes may occur during round 1. The protocol, seeds, twelve task cards per project, public checks, parity tables, hidden evaluators, harness and tool binaries receive an exact byte manifest before dispatch. Builder and operator preparation is outside scoring.

Both arms begin with identical application source and intended facts. A receives concise agent instructions, architecture/process documentation, conventional CI and executable implementation checks. B receives those implementation expectations and checks plus explicit canonical ownership, the current Markitect-first workflow, context, impact and configured modules where relevant. Project-specific parity tables must expose every mechanism difference. B receives no hidden business requirement or architecture exception.

Three independent trial chains per arm use fresh native collaboration agents for each task, with identical inherited model/effort/sandbox/tool settings and no parent turns. The active parent session records gpt-6.1-sol/xhigh; no actor override is used. Repository state accumulates across tasks; failure states are retained. Both arms receive one initial public validation and at most two self-repair attempts. Actor intent commits are allowed for fixed Markitect analysis; the operator only records resulting state and never repairs it. Required escalation is evaluated independently of task implementation, so refusing an unauthorized change is not mislabeled failed autonomy.

Tasks 09–12 are holdout. Each development chain stops after task 08. Holdout dispatch begins only after a generic fix/no-fix decision is recorded; native actor messages therefore cannot reveal holdout outcomes to fix authors. If development tasks produce no justified product fix, the explicit no-fix decision precedes dispatch with the original candidate. A second candidate is not manufactured merely to populate a comparison table.

## Isolation and raw evidence

Actors run in external, separate repositories without inheriting Markitect's repository entrypoint. They receive only their accumulated project and current task. Candidate binaries and a public-check recorder are supplied separately; Markitect implementation and hidden evaluators are not supplied as context. Evaluators operate after the actor on captured state and do not feed results into later tasks.

Workspace-write controls writes, but does not prove that every unrelated path is unreadable. Oracle secrecy therefore means undisclosed, outside-workspace input plus an audited no-access instruction, not proven operating-system read isolation. Any detected cross-arm, evaluator or product-source access invalidates that run. This limit prevents an unsupported hard-isolation claim.

Exact native task prompts and actor responses/available receipts, input/output commits, before-validation snapshots and final snapshots are retained outside actor workspaces before analysis. Unscored CLI JSONL/stderr is retained separately. YAML is the format for Markitect-owned manifests and summarized measurements; native platform JSONL is preserved as emitted. Existing authentication is used in place and is never copied or printed.

The unscored CLI preflights report runtime usage but are not scored trials. The selected native driver does not expose backend token/model-call telemetry, so those values remain unavailable. Neither driver necessarily exposes precise source read ranges or active-agent time. Shell events can support observed command/search counts and an audit, but not complete cognition/read telemetry. Missing data is recorded as unavailable. No token estimate is derived from bytes.

## Outcomes and maintenance

Every task has separate functional, mutation-boundary, architecture, escalation and protocol outcomes. The architecture vector records concrete forbidden edges, missing owned concepts, orphaned/unmanaged artifacts, stale surfaces and rule/check drift. No composite winner score is used. The autonomous streak stops at the first unresolved hidden functional or architectural failure, while later tasks retain that failure state.

Changed paths and byte/line deltas are separated into authored governance, generated projections, implementation, tests and check configuration. B's extra model/projection maintenance counts even when checks pass. A's manual synchronization also counts. Neither generated file counts nor fewer tool calls establish reduced human coordination.

Parallel forks begin at the exact retained task-06 revision. Integration uses a fixed order and the same bounded automated repair protocol in both arms. Conflicts and unresolved failures remain evidence. Policy evolution preserves the same explicit v1/v2 history and selected cohort in both arms.

After round 1, only high-confidence generic defects may produce separate product fixes and regression tests. Tasks and oracles remain unchanged. Holdout must not inform those fixes. Negative results, baseline wins and source-contract limitations remain in the final report. Private Konfyra owner review is independent and remains necessary.

## Unscored runtime decision

CLI 0.130.0 rejects the Desktop model alias and cannot write the test file under its preserved execution rules. Authenticated model/shell access was established, but the actual write was blocked by policy. No execution rules, user configuration or credentials were modified to get around it. Native collaboration passed a real scoped write/read smoke in the permitted external arena, and is therefore selected before freeze. This runtime decision is preparation evidence, not a Markitect product defect or an A/B outcome.
