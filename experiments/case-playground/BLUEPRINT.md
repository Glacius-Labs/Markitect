# Case Playground v2: blueprint

This is the build plan for a lean rebuild of the case-study playground that compares
**Conventional** agentic coding with **Markitect** on the same staged backlog. It
replaces `experiments/work-item-comparison/playground` for new runs; that old folder
is not on main and stays as an archive on the research-backup remote.

## Why a rebuild

The old harness ran Codex directly on the Windows host. Almost every blocker came
from that: inherited `~/.codex` (config, hooks, plugins, global AGENTS.md), only the
direct child process being killed (orphans holding files, sharing violations), the
Codex Windows sandbox (ACL refresh, protected `.git`, writable-root denials, shell
CWD in `System32`) and CRLF vs LF byte hashing. On top sat one-off admission code
with hardcoded order hashes, executable hashes and `C:/Users/...` paths.

Design rules for v2:

1. **The container is the isolation boundary.** One fresh Linux container per run.
   Inside it, Codex runs with `--dangerously-bypass-approvals-and-sandbox` (the flag
   is documented for externally sandboxed environments). No host home, no host
   `~/.codex`, no global hooks/plugins/MCP servers. The agent can branch, commit and
   merge like a normal user.
2. **Fresh Codex home per run.** Only `auth.json` is copied in; `config.toml` is
   generated by the runner and minimal.
3. **Kill everything the agent started.** The agent runs as the unprivileged user
   `agent`. After every station the runner kills all `agent` processes and counts
   leftovers. The host can always `docker kill` the whole run.
4. **Linux filesystem for all work.** The case repo lives in the container
   filesystem, not on a Windows bind mount. Only `/in` (read-only inputs) and
   `/out` (results) are bind mounts.
5. **No governance in code.** No order hashes, no reservation ledgers, no dates, no
   absolute user paths in source. Everything a run needs is in one JSON manifest
   plus host CLI flags. Run outputs never go into git.
6. **Stdlib-only Python 3.11+.** Same code runs on the Windows host (host side) and
   in the container (runner side). Always pass `encoding="utf-8"`; never rely on the
   locale. Use list-form `subprocess` calls, never `shell=True`.

Unit tests: from the worktree root,
`python -B -m unittest discover -s experiments/case-playground/tests -t experiments/case-playground`
must pass on the Windows host and inside the container. Tests that need Linux-only
features (`setpriv`, uid switching) must skip cleanly elsewhere.

## Manifest (schema 1)

```json
{
  "schema": 1,
  "id": "conv-readinglog-001",
  "case": "readinglog",
  "method": "conventional",
  "agent": {
    "kind": "codex",
    "codexVersion": "0.162.0",
    "model": "gpt-6-luna",
    "effort": "high",
    "maxSubagents": 3
  },
  "limits": {"stationSeconds": 5400, "totalSeconds": 14400},
  "container": {"cpus": 4, "memory": "8g", "pidsLimit": 2048},
  "markitect": {"sourceRepo": "C:/path/to/Markitect", "commit": "669cecd2"}
}
```

- `id`: `^[a-z0-9][a-z0-9-]{0,62}$`. `case`: `roombook|readinglog`.
  `method`: `conventional|markitect`. `agent.kind`: `codex|fake`.
- `markitect` is required for `method: markitect` and forbidden otherwise.
- `manifest.load(path) -> dict` validates and returns the manifest, raising
  `ManifestError(ValueError)` with a clear message. No other module re-validates.

## Host side (`playground/host.py`)

Command: `python -m playground host run --manifest M.json [--out DIR] [--codex-auth PATH] [--keep-container]`.

1. Load the manifest. `--out` defaults to `~/markitect-playground-runs/<id>`; it must
   not exist and must not be inside a git checkout. `--codex-auth` defaults to
   `~/.codex/auth.json` (required only for `kind: codex`). Never read, print, copy
   or hash the auth file; only check it exists.
2. Build the image `markitect-playground:codex-<codexVersion>` from
   `container/Dockerfile` with `--build-arg CODEX_VERSION=...`. Record the image ID.
3. For `method: markitect`: build a Linux binary from the product repo at the given
   commit: `git -C <sourceRepo> -c core.autocrlf=false archive --format=tar <commit>` into
   a temp dir, then `go build -trimpath -o <out>/inputs/bin/markitect ./src/cmd/markitect`
   with `GOOS=linux GOARCH=amd64 CGO_ENABLED=0` (and `GOFLAGS`, `GOWORK=off` pinned;
   `GOTOOLCHAIN=auto` follows the commit's go.mod, and the Go version used is recorded). Record the resolved full commit and the
   binary SHA-256. Fail clearly if Go is missing.
4. Stage `<out>/inputs/`: a copy of `playground/`, `cases/common`, `cases/<case>`, the
   task prompt, for Conventional `methods/conventional/AGENTS.fragment.md`, and the
   manifest. Nothing else: the agent can read `/in`, and `methods/markitect/README.md`
   holds notes for people. `<out>/results/` is created empty.
5. `docker run` with:
   `--name mpg-<id> --label markitect-playground=1 --init`,
   `--cpus/--memory/--pids-limit` from the manifest,
   `--mount type=bind,source=<out>/inputs,target=/in,readonly`,
   `--mount type=bind,source=<out>/results,target=/out`,
   for codex: `--mount type=bind,source=<auth>,target=/run/secrets/codex-auth.json,readonly`,
   env `MPG_IMAGE_ID=<image id>`, `MPG_MARKITECT_SHA256=...` when relevant,
   command `python3 -m playground run --manifest /in/manifest.json --out /out`
   with working dir `/in` so the package imports from `/in/playground`.
   Use `--mount` rather than `-v` (paths with spaces, drive letters).
6. Wait with a host timeout of `totalSeconds + runner.overhead_bound_seconds()` (the
   runner's worst-case setup, checks, snapshots and final assessment). On timeout or
   Ctrl+C: `docker kill`, then record `host-timeout` / `host-interrupted` in
   `<out>/host.json`. A failed `docker wait` is `wait-failed`, and a still-running
   container is then kept. Otherwise `docker rm -f` at the end unless `--keep-container`.
   Refuse to start when a container `mpg-<id>` already exists.
7. Write `<out>/host.json` (manifest, image id, docker version, markitect commit and
   sha, start/end, container exit code) and print the path of `results/report.md`.

Also: `python -m playground host clean` removes containers labelled
`markitect-playground=1` that are not running.

## Container image (`container/Dockerfile`)

- `FROM node:22-bookworm-slim` (Codex CLI is an npm package).
- apt: `python3 git ca-certificates procps bubblewrap ripgrep util-linux tini`.
- `ARG CODEX_VERSION` then `npm install -g @openai/codex@${CODEX_VERSION}`; fail the
  build if `codex --version` does not report that version.
- Create user `agent` (uid 1000, home `/home/agent`). The `node` user in the base
  image already has uid 1000: remove or reuse it so `agent` is uid 1000.
- No secrets, no `ENTRYPOINT` logic beyond the default; the host passes the command.

## Runner side (`playground/runner.py`, runs as root in the container)

`run(manifest, out: Path) -> int` performs one trajectory:

1. **Agent home.** Create `/home/agent/.codex/`, copy `/run/secrets/codex-auth.json`
   to `auth.json` (mode 0600, owner agent) when present, write `config.toml` via
   `codex_agent.write_config(...)`. Nothing from the host home is used.
2. **Prepare.** `lifecycle.prepare(seed=/in/cases, repo=/work/<case>, audit=/out/audit, case, method)`
   creates a fresh git repo with `core.autocrlf=false`, the seed commit and
   `.study/station.json` releasing S1. Then `chown -R agent:agent /work`.
   Root never runs Git on the agent-owned repo: `lifecycle` runs those Git commands as
   the repo owner, with hooks, fsmonitor, external diff and textconv switched off, so
   nothing the agent configured runs as root. No `safe.directory` is needed.
3. **Method setup.** `methods.setup(method, repo, ctx)` runs as `agent` and commits
   its installation. Duration and stdout/stderr go to `/out/setup/`.
4. **Stations S1..S4.** For each station:
   - Start (S1) or resume (S2+) the agent with the unchanged prompt from
     `cases/task-prompt.txt`. Timeout = min(`stationSeconds`, remaining total), where
     the total counts agent time only (harness work between waves is not charged).
   - After the agent process ends (or times out): `codex_agent.kill_all_agent_processes()`
     kills every process of uid `agent` and returns how many were still alive.
   - Save `agent.json` first, then `lifecycle.snapshot(repo, audit, sweep=kill_all_agent_processes)`
     captures main, worktree, branches, dirty state. A snapshot or advance error is
     recorded in the station folder and stops the run; freeze, final and report still run.
   - `assess.station(snapshot_main_dir, case, station)` runs the public checks on a
     scratch copy and stores the result under `/out/stations/S<n>/checks.json`.
     Results are never shown to the agent.
   - If not the last station: `lifecycle.advance(repo, audit)` releases the next
     station by rewriting only `.study/station.json` (keep owner agent).
   - Stop early only on an infrastructure failure (agent never produced a session
     id, auth error, binary missing) or when total time is used up. A station
     timeout or non-zero agent exit is recorded and the run continues.
5. **Freeze.** `lifecycle.freeze(repo, audit, reason)`.
6. **Final assessment.** `assess.final(frozen_main_dir, case, method)` on a scratch copy
   **without `.git`**: public checks for S4 (cumulative), the candidate's own tests
   (`python3 -m unittest discover` from the repo root; record, do not judge), and for
   Markitect the product's own validation command if the product offers one
   (recorded separately as method conformance).
7. **Report.** `report.build(out)` writes `/out/report.json` and `/out/report.md`.

Exit code: 0 when all four stations ran (whatever the quality), 1 when stopped early,
2 on runner error. Write `/out/runner-error.txt` with the traceback on runner error.

## Agent (`playground/codex_agent.py`)

- `write_config(home: Path, agent_cfg: dict, mcp_servers: dict) -> Path` writes a
  minimal `config.toml`: `model`, `model_reasoning_effort`, `features.memories=false`,
  `agents.max_concurrent_threads_per_session`, `agents.default_subagent_model`,
  `agents.default_subagent_reasoning_effort`, and `[mcp_servers.<name>]` tables.
  Verify the key names against `codex --help`/docs in the container; the Windows
  wrapper used exactly these `-c` keys successfully with 0.162.0-alpha.2.
- `build_command(agent_cfg, prompt, session_id=None, last_message: Path) -> list[str]`:
  - S1: `codex exec --json --dangerously-bypass-approvals-and-sandbox --skip-git-repo-check -o <last_message> <prompt>`
  - S2+: `codex exec resume <session_id> --json --dangerously-bypass-approvals-and-sandbox -o <last_message> <prompt>`
  - `kind: fake`: `python3 /in/tests/fake_agent.py ...` with the same contract
    (so stage `tests/fake_agent.py` to `/in/tests/` as well).
- `run_as_agent(cmd, cwd, env, timeout, stdout_path, stderr_path) -> dict` runs the
  command as uid/gid `agent` (`setpriv --reuid=agent --regid=agent --init-groups --reset-env`
  or `preexec_fn`), in a new session (`start_new_session=True`), with a clean env:
  `HOME=/home/agent CODEX_HOME=/home/agent/.codex PATH=<image path> LANG=C.UTF-8 PYTHONUTF8=1 TERM=dumb`.
  On timeout: kill the process group, then everything of uid agent. Returns exit
  code, timed_out, wall seconds.
- `parse_events(jsonl_path) -> dict`: session/thread id, number of completed items
  (any type), command executions, file changes, MCP and subagent calls, errors, and
  the token usage of the last turn-completion event (input, cached input, output).
  Codex reports the thread's running total there, also after a resume, so per-wave
  tokens are deltas; the runner takes them from Codex's session records
  (`codex_agent.session_totals`), which also cover subagents and Markitect's inner
  roles. Tolerate unknown event types and malformed
  lines (count them). Event names must be checked against real `codex exec --json`
  output of the pinned version; keep the parser tolerant.
- `kill_all_agent_processes() -> int`: SIGKILL all processes of uid agent, wait until
  none remain (bounded), return the count found.

## Methods (`playground/methods.py`)

`setup(method, repo, ctx) -> dict` with `ctx` holding the manifest, the agent home
and helper callables. Returns `{"method", "seconds", "commit", "mcpServers": {...}, "notes"}`.

- **conventional:** append `methods/conventional/AGENTS.fragment.md` to the repo's
  `AGENTS.md`, commit as `agent` ("Install conventional workflow"). No MCP servers.
- **markitect:** use `/in/bin/markitect`, copied to `/usr/local/bin/markitect`. Run the
  real product onboarding for a repository the way the product docs describe it
  (read `docs/project-workflow.md`, `docs/onboarding.md`, `docs/usage.md` and
  `src/internal/host/projectcli/` in the product repo at the pinned commit). This is
  roughly: `project init` / `project onboard` (preview, then write with the returned
  digest), `project setup` for native Codex with the manifest's model and effort
  (preview, then write with the returned `editPlan.digest`), and an MCP server entry
  `markitect project mcp --repo /work/<case>` for the outer Codex. Commit the
  installation as `agent`. Do not author the business model; the actor does that
  as part of normal work. Record every command, exit code and duration.
  If a product command fails, the setup result is `blocked` with the error; that is
  a product finding, not something to work around.

## Assessment (`playground/assess.py`)

- `station(candidate_dir, case, station) -> dict` runs
  `python3 cases/common/checks/acceptance.py --repo <scratch> --case <case> --station <n>`
  on a scratch copy without `.git`, as uid agent when available. Returns pass/fail
  counts parsed from its output plus raw output paths.
- `final(candidate_dir, case, method) -> dict`: station 4 checks, own tests, and
  Markitect conformance as described above. Never modifies the candidate.

## Lifecycle (`playground/lifecycle.py`)

Port `prepare`, `snapshot`, `advance`, `freeze` from the old `lifecycle.py` and keep
its proven behavior (raw git bundle, immutable main checkout, worktree copy, dirty
and branch capture, hash manifest). Drop `record-setup`, `record-execution`, the
`workspace_snapshot` target and all authorization fields. Keep a small CLI for
manual use. Seed sources come from `cases/common` plus `cases/<case>`; method files
are not part of the seed.

## Report (`playground/report.py`)

`report.json`: manifest, versions (codex, image id, markitect commit/sha), setup
seconds, and per station: wall seconds, exit code, timed out, leftover processes
killed, tokens (outer session and all recorded sessions), command and MCP/subagent call
counts, commits on main, public checks passed/total; final assessment; setup notes;
the fairness fields both arms must share; total tokens and wall time. `report.md`: the same as one short table plus
a few lines. Unknown values stay `null`, never zero.

## Shared interfaces (binding for all builders)

```python
# manifest.py
class ManifestError(ValueError): ...
def load(path: Path) -> dict

# codex_agent.py
AGENT_USER = "agent"; AGENT_HOME = Path("/home/agent")
def install_auth(src: Path, home: Path) -> bool            # False when src missing
def write_config(home: Path, agent_cfg: dict, mcp_servers: dict) -> Path
def build_command(agent_cfg: dict, prompt: str, session_id: str | None, last_message: Path) -> list[str]
def run_as_agent(cmd: list[str], cwd: Path, timeout: float, stdout_path: Path,
                 stderr_path: Path, extra_env: dict | None = None) -> dict
    # -> {"exitCode": int|None, "timedOut": bool, "seconds": float}
def parse_events(jsonl_path: Path) -> dict
    # -> {"sessionId": str|None, "items": int, "commands": int, "fileChanges": int, "mcpToolCalls": int,
    #     "collabToolCalls": int, "errors": int, "malformedLines": int,
    #     "tokens": {"input": int|None, "cachedInput": int|None, "output": int|None}}  # running total
def session_totals(sessions: Path) -> dict   # thread id -> latest running token total
def kill_all_agent_processes(timeout: float = 30) -> int

# methods.py
def setup(method: str, repo: Path, ctx: dict) -> dict
    # ctx = {"manifest": dict, "case": str, "inDir": Path, "outDir": Path,
    #        "agentHome": Path, "runAsAgent": codex_agent.run_as_agent}
    # -> {"status": "ready"|"blocked", "method": str, "seconds": float, "commit": str|None,
    #     "mcpServers": {name: {"command": str, "args": [str]}}, "steps": [...], "error": str|None}

# assess.py
def station(candidate_dir: Path, case: str, station: int, in_dir: Path, out_dir: Path) -> dict
def final(candidate_dir: Path, case: str, method: str, in_dir: Path, out_dir: Path) -> dict
    # both -> {"passed": int|None, "total": int|None, "status": "pass"|"fail"|"error", ...}

# lifecycle.py
def prepare(seed_root: Path, repo: Path, audit: Path, *, case: str, method: str) -> dict
def snapshot(repo: Path, audit: Path, *, sweep=None) -> dict   # paths incl. "immutableMain" (None without main)
def advance(repo: Path, audit: Path) -> dict
def freeze(repo: Path, audit: Path, *, reason: str, sweep=None) -> dict   # same shape as snapshot

# runner.py / host.py
def main(argv: list[str] | None = None) -> int   # each; __main__.py dispatches "run" / "host"
```

Order inside `runner.run`: install auth → prepare → chown → `methods.setup` →
`write_config(..., mcp_servers=setup["mcpServers"])` → stations → freeze → final → report.
A `blocked` setup stops the run (exit 1) after writing the report.

## Fairness rules (also in STUDY.md)

Same image, same Codex version, model, effort, subagent limits, prompt, case files
and limits for both methods. Conventional gets its AGENTS fragment; Markitect gets
its real product installation and MCP server. Nobody coaches the agent between
stations. Old run outputs and the other arm's results are never inputs.

## Out of scope for this build

Claude Code as a second runtime (keep `agent.kind` open for it), egress filtering
to the model API only, an LLM-based final reviewer, and statistics across runs.
