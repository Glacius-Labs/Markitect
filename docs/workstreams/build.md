The Build and evaluation session builds concept 2.0 and the evaluation suite that measures it, and it is the only session that builds ([workstreams](../workstreams.md)). It owns the suite with its arms, K and the concept 2.0 arm; the concept 2.0 host on `main` (the engine, the agents, the harness and the native host); the records under `docs/validation/`; and the [delivery plan](../implementation-plan.md), which owns the concept 2.0 build steps as well as V1's steps and known deviations. This page holds only the session's state.

## Decisions

- **Model, 28 October 2026:** every arm runs on Claude Sonnet 5.5 (`claude:claude-sonnet-5-5`); Codex runs are recorded separately once Codex has tokens again. The owner: "Sonnet 5.5 for all".
- **Evaluation suite v2, 28 October 2026:** the portfolio is the Library as a smoke only, the Makerspace chain as the main test (its role changed the same day, below) and one new, larger, private project; the suite gets one sandbox for every variant, judges as plug-ins, enough repetitions, a reviewer of another model family when available, and human input as its own area ([design](../design/evaluation-suite-v2.md)). The owner: "Yes lets go with your recommendation and address all of these. The evaluation suite is critical and should be suitable to give us data to base our decisions upon."
- **What is measured, 28 October 2026:** the evaluation judges results against the human attention they need, not the computing they use; time, tokens and machine use are reported, not equalized. Technical failures do not count: each variant is made to run without technical issues, then evaluated ([design](../design/evaluation-suite-v2.md#b-judges-are-plug-ins-too)). The owner: "The goal is not to get better result in less computing. The goal is to get better results in less human attention." and "Technical failures shouldnt count. We should make each of them work without technical issues and then evaluate".
- **Portfolio roles, 28 October 2026:** the Library shows that a variant and the suite work technically; the Makerspace chain is an intermediate for a first idea of what works; the new, unseen project is the real test ([design](../design/evaluation-suite-v2.md#c-portfolio)). The owner: "Library is just there as a small project, to test that a variant technically works and that the eval suite works. Makerspace is an intermediate, where we can get an idea what works without much effort. As you propose the real test should be the new unseen one".
- **Hidden material, 28 October 2026:** the new project's hidden material lives in the private repository `Glacius-Labs/Markitect-Evaluation`, created the same day. The owner: "Private GitHub repo".
- **New project's domain, 28 October 2026:** a local energy community (members, meters, tariffs, shared solar credits, monthly bills). The owner: "Yes, energy".

- **Shape of the 2.0 build, 28 October 2026:** one implementation of concept 2.0, compared with K. The plugin variant and V1's open steps 4 and 5 stop; the Git variant's prototype becomes the start of T3 ([build steps](../implementation-plan.md#concept-20-build)). The owner accepted Build's proposal.

- **Acceptance portfolio, 28 October 2026:** concept 2.0 is accepted on the Library and Makerspace, as §15 says, plus the new, unseen project as the check on material nobody tuned on, because arm M was tuned on Makerspace. Its tasks join T6. The owner accepted Build's recommendation.

- **Standing run approval, 28 October 2026:** the owner approved, in advance, the real container and provider runs of the concept 2.0 build and of the evaluation suite. That covers smokes, judge self-tests and the pilot; Build and its sub-sessions run them without asking again. Each run still has a written bounded dispatch under `docs/validation/` (source, limits, abort, cleanup, then its results, failed attempts included), holds the shared engine lock, uses account login only, and never an API key. Not covered: any release or deployment. The counted acceptance series was delegated to Build later the same day (below).

- **Scoring the stops, 28 October 2026:** every arm is scored on planted tasks by one mechanical rule: a result equal to its start did not land. Every task ends with the same stop rule for every arm: if the requirements contradict each other or leave a boundary behavior open, change nothing and say why. The owner accepted Build's recommendation.

- **Codex runs, 29 October 2026:** Codex has usage again. The counted series stays on Claude Sonnet 5.5, so that it stays comparable with the pilot and the suite's self-tests. A native 2.0 smoke on Codex (Library M1) ran beside the Claude work (T5 above). After the counted series comes a smaller repeat with every arm on Codex Luna; Build proposes its size under the approved protocol. Models are never mixed within one series; Sol High runs only if the owner asks for a strong-model check.

- **Counted series delegated, 29 October 2026:** the owner, going away, let Build run the build on its own: start, steer, merge and archive sessions without asking. The owner also delegated the counted acceptance series to Build, to start once Build judges it appropriate. Build approves the protocol only after the pilot, with an independent review of the protocol before the first counted run. The protocol and its review are recorded under `docs/validation/` before any counted run, and the owner reviews the results.

- **Fixed starts, 29 October 2026:** a fixed reference start reaches the 2.0 arm with registry pages that link each file to the Definitions it realizes, written as an owner adopting Markitect would write them; K gets the same reference files without the pages. This holds for every fixed start the pilot runs and for every fixed start of the counted series. The case without pages ([record](../validation/t7-arm-smoke-20261029.md)) ran once, as the escalation fix's regression run (above). Build decided on the T7 session's finding.

- **Pilot scope, 29 October 2026:** in the pilot, the 2.0 arm runs the chains M1–M5 and W0–C9, the Library's fixed starts M2–M5 and every planted task (two on the Library, three on Makerspace; a planted task also starts from a reference result, so it gets that result's registry pages). It skips the Makerspace fixed starts C1–C9; K runs them too. With one run per task and each chain step counted as one launch, that is 57 launches: 24 for the 2.0 arm and 33 for K. The counted series runs every fixed start for both arms. The T7 session advised this scope, and the owner chose it there: "Library only, as advised".

- **Full check and the series' claim, 29 October 2026:** the full check is `verify --full`, at every milestone the owner names and once ten changes have landed since the last full check, or since the first landing; an `apply --full` that lands counts as a full check too. Every Result says how many changes have landed since then and, from ten on, that a full check is due; the host starts nothing itself. The counted series claims only what it measures: at least K's quality and fewer defects left for a person per change at comparable input, not saved time. Time saved is measured afterwards: on the new project the owner takes three changes per arm to acceptance, blinded, and records minutes and corrections. Recorded by the Topics session ([DEC-082](../concepts/register.md#dec-082-one-run-per-change-impact-decides-who-works-maker-and-checker-per-manager), [DEC-086](../concepts/register.md#dec-086-concept-20-is-the-target), [concept §15](../concepts/v2-concept.md#15-acceptance), [PR #883](https://github.com/Glacius-Labs/Markitect/pull/883)).

- **A new Package's first path patterns, 29 October 2026:** when the owner adds a Package, the owner also writes its registry page with the first path patterns. From then on its Manager maintains them, and a change takes effect from the next Run. `lint` warns about a Package other than Root that claims no pattern. The owner accepted Build's recommendation through the Topics session ([DEC-081](../concepts/register.md#dec-081-the-organization-knows-broad-at-the-top-and-deep-below), [PR #876](https://github.com/Glacius-Labs/Markitect/pull/876)).

- **Required checks gate merged states, not each submission, 29 October 2026:** the required checks block only merged states: a parent's submission that holds its children's merged work, and the state that lands. Every other submission is still blocked by `markitect check`, path ownership and its checker, which sees the check results as evidence. A child's broken build is caught at its parent's merge. The owner accepted Build's recommendation in Build's session after the pilot's Makerspace chain, and the Topics session recorded it ([DEC-087](../concepts/register.md#dec-087-required-checks-gate-merged-states-not-each-submission), [PR #890](https://github.com/Glacius-Labs/Markitect/pull/890)).

- **Evaluation engine, 30 October 2026:** the evaluation keeps running on the regular Docker Desktop engine. The owner declined Build's proposal of a WSL distribution with its own Docker Engine and had already stopped Codex: "Just use the regular one. I stopped codex". Build's rules under this decision, not the owner's words: before each window of native runs, Build asks the owner to stop other Docker work at the process level, not only to pause an app, and checks that it stopped. The runner keeps the [reruns' guard](../validation/t7-pilot-20261029.md#amendment-of-29-october-2026-two-reruns).

- **Reading rule, 30 October 2026:** the 2.0 arm is at least as good as K only when three things hold at once on the new project's fixed starts:
  - the share of hidden cases passed is non-inferior at 0.05;
  - the failed-case count is non-inferior at one case;
  - its landed-change rate is not below K's.

  The owner first answered the independent check's finding "Yes, require both", for the two case contrasts. The owner then accepted the Topics session's stricter recommendation with "Yes, hand it to Build". Build reads "not below" with no tolerance ([Amendment 2](../validation/counted-series-protocol-20261030.md#amendment-2-30-october-2026-scoring-fixes-before-the-gate), [PR #915](https://github.com/Glacius-Labs/Markitect/pull/915)).
