# Government: model, native inventory and bounded execution

This experimental source-only branch implements G1 accounting, G2 bounded execution, G3 recursive integration, G4 delegated model maintenance and G5 finite persistent operation from the [delivery plan](design/government/delivery-plan.md). It does not update an installed release. [The architecture](design/government/architecture.md) remains the design contract; this page owns the executable format and limits. Exact candidate gate results and milestone acceptance belong to the source-bound handoff.

## Commands and input

```powershell
go run ./cmd/markitect government --action schema
go run ./cmd/markitect government --repo examples/government --config government.yaml --action inspect
go run ./cmd/markitect government --repo examples/government --config government.yaml --action plan --order order.yaml
go run ./cmd/markitect government --repo examples/government --config government.yaml --action plan --order negative-order.yaml
```

`schema` emits the actual built-in `markitect.government/v1alpha1` structural Schema. `GovernmentSource` is one strict YAML document with `apiVersion: markitect.government-source/v1alpha1`, `constitution` (full identity), inline `schemas` and `definitions`, and `observation`. Custom domain Schemas and the built-in Schema compile through the unchanged minimal Core. Definitions and relation Definitions carry `purpose`. Full identities contain `apiVersion`, `kind`, explicit `namespace` (possibly empty), and `name`. Host resolves arbitrary `subject` and mandate `scope` identities exactly; these are object values, not polymorphic Core references.

`Constitution` selects one root Area, a nonempty Ressort cabinet and `unanimous-explicit-assent`. Areas recursively reference parents and optional pinned Capabilities. Ressorts reference review Mandates without implicit writer permission. Mandates contain an Area, exact subject scope, allowed actions (`implement`, `review`, `amend-model`) and, below root, a higher mandate. Host validates acyclic delegation, hierarchy and scope/action subsets. `Responsibility` assigns one accountable Area per subject. `Artifact` declares an exact path, class (`canonical`, `realization`, `generated`, `foreign`) and, for managed material, one Area writer. Purpose-bearing `Realization` connects subjects to artifacts many-to-many. File ownership is independent of subject responsibility and crosscutting review.

The caller explicitly selects an already accepted Constitution input. Its digest covers the compiled domain model and organization together, excluding observed bytes and provenance. G1 cannot authenticate this acceptance. `Order` is a separate strict document with `apiVersion: markitect.government-order/v1alpha1`, `kind: Order`, `purpose`, `activeConstitution` (exact prior digest), `action`, and `subjects` and/or exact `paths`. Optional `unknownScope: true` widens to all modeled subjects and root review, and blocks unresolved work. Proposed amendments cannot change the authority of their own plan. Organizational authority changes require owner escalation. G4's bounded model amendment path is described below.

## Native acquisition and coverage

`observation.roots` requires normalized, non-overlapping repository-relative roots; `.` selects the repository. `exclusions` and `admitIgnored` contain `{path, reason}` boundaries. The scanner enumerates tracked, untracked and ignored entries, including conventionally filtered build directories. Excluded directories remain visible without reading their contents. Ignored bytes are read only under explicit `admitIgnored` entries. `.git` metadata is an automatic reasoned exclusion; links, Windows reparse points, special files and Git submodules remain boundaries and are not traversed. Classification errors inside Git repositories fail closed. Non-Git directories are supported as native sources.

Each observed regular file carries a bytes digest, mode, source and status. The report binds roots, exclusion/admission reasons, entries, HEAD when available, and traversal completeness. It is **always provisional**: HEAD is provenance, not a claim that these are HEAD's bytes or an atomic filesystem snapshot. Config and Order must be admitted, unchanged captured inputs. Traversal is bounded to 100,000 entries, 64 MiB per file and 512 MiB total. Unreadable paths remain incomplete; entry-limit exhaustion aborts acquisition.

Survey joins intended artifacts with captured entries. Unassigned files retain `purpose: unknown`; absent artifacts are missing; descendants of excluded/linked boundaries or paths outside roots are unavailable. Exclusion is never conformance. `accounted-within-declared-boundary` means structural accounting only, not implementation or semantic verification. `inspect` exits 1 for incomplete accounting, 0 for accounted scope, and 2 for invalid acquisition/input. The example intentionally exits 1 because it contains unassigned files.

## Planning

Planning follows explicit domain references in both directions and shared realization paths conservatively. It resolves accountable Areas, authorized writers, prior Mandates, parent integration review and the frozen cabinet. Source-code or prose-link semantics are not inferred. Foreign inputs alone cannot fulfill implementation work. Unknown identities, conflicting responsibility/writers, insufficient authority, unavailable selected inputs and empty work block the plan. Unrelated unknown artifacts remain visible and allow only a scoped proposal. Status is `blocked`, `planned-scoped`, or `planned-within-declared-boundary`; none means implementation or acceptance. A blocked plan exits 1, a proposal 0, and invalid input/acquisition 2.

Pure G2 records establish an acyclic chain: `MaterialCandidateID` binds prior authority, base revision, material tree/model, plan, check definitions, tool pins and optional inventory; `EvidenceID` binds immutable result/report digests and round; Voten bind both IDs and prior mandate/configured slot; `DecisionID` binds a complete, current, unanimous vote set from the supplied frozen cabinet. Constructors validate consistency, not authentication, independent review, check sufficiency or promotion rights. No G1 command creates or consumes acceptance decisions.

## G2: one Writer Area through the native Host

```powershell
markitect government --action run --repo C:\absolute\project --config government.yaml --order order.yaml --runtime C:\external\runtime.json --write
```

`run` requires explicit `--write` and a strict external runtime JSON document. The read-only actions reject execution flags. Runtime API `markitect.government-execution/v1alpha1` requires `activeRef`, `expectedBase` (full lowercase Git OID), `stateDirectory`, `temporaryDirectory`, `timeoutSeconds`, `executor`, `verifier`, `ressorts` and `checks`. The active ref must have exactly one safe name below `refs/markitect/government/active/`. Source, Git metadata, state and temporary roots are disjoint real directories. Config and Order are read from the exact active commit, never from uncommitted checkout bytes. Initial mismatch rejects the run.

Each runner names `slotId`, literal `command` and `args`, explicit `model` and `providerVersion`, `timeoutSeconds`, `maxStdoutBytes`, `maxStderrBytes`, and optional `modelOptions` and `runtimeFiles`. Each Ressort entry binds a complete `ressort` identity to its `runner`. Every prior Cabinet member must occur exactly once; executor, verifier and Ressort slots are distinct. Configured slot names are assignments, not authenticated identities. The executable and declared runtime-file bytes are fingerprinted before execution; actual receipt config/executable digests must match the frozen slot. Absolute file arguments require declared runtime files. Supported interpreter invocations require a declared absolute script or explicit inline-code argv; callers own completeness of transitive runtime dependencies.

Runtime JSON is limited to 4 MiB with unknown and duplicate case-folded keys rejected. There are at most 128 checks and 128 Ressorts. Actor limits stay 1–600 seconds and 1 byte–16 MiB per output stream. Run budget is explicit, 1–1800 seconds. Check definitions use the existing fixed-snapshot check contract (default 600 seconds; explicit 1–1800). Before each check, the Host reserves its entire command cap plus wait allowance from the remaining run budget. Actor/Git calls observe the run deadline; each existing snapshot check finishes under its own command cap, and an elapsed run cannot proceed to review or promotion. Cooperative snapshot IO is not a hard real-time guarantee.

The Host freezes the prior Constitution, plan, single nonempty Writer scope, Mandates, Cabinet, base and runtime/tool pins. G2 accepts only `implement` under unchanged prior authority and cannot change Config or Order. It materializes an isolated base snapshot, invokes the configured Executor in a fresh empty process context, audits inputs, and applies returned file bytes only within the frozen Writer paths. Git objects are written with a private index and one parent; the user's index, branch and working files remain outside this write path. The complete Git tree and materialized snapshot digest bind the material identity; unchanged Git paths excluded by source acquisition remain inherited from the base and receive no semantic coverage claim.

Fresh technical checks run against that fixed candidate. Separate Verifier invocations must explicitly pass every required Area integration scope and affected subject with a nonempty explanation and without uncertainty. Only then does the Host form `EvidenceID` from check and actual actor result digests. Each frozen Ressort receives a separate invocation with the same material/evidence/round and must return one `government-vote` observation, with a strict JSON `detail` containing `outcome`, nonempty `reason`, `materialCandidateId`, `evidenceId` and `round`. Both `assent` and explicit `assent-unaffected` count. Missing, rejected, foreign or stale review/vote evidence blocks promotion; successful constructors alone never manufacture process evidence.

Before promotion the Host rechecks candidate bytes and tool pins. Under a common-Git-directory writer fence it durably publishes an external `PromotionIntent`, rechecks checkout/ref state and applies a Git compare-and-swap from the exact base to the exact candidate commit. A private empty hook directory suppresses configured reference-transaction hooks. Checked-out and symbolic refs are rejected. A stale base, changed reviewed tree or occupied writer fence stops takeover. The CAS updates only the dedicated managed ref; it never advances a checked-out user branch.

The JSON stdout report and external JSON records retain actual actor receipts, fresh checks, IDs, votes, decision, promotion state and explicit limitations. Report files use the same exclusive durable publication primitive as the intent: file plus directory sync on Unix and flushed staging plus write-through publication on Windows. Invalid external reporting boundaries cannot safely receive an abort file; the command still emits its incomplete result. `run` exits 0 only for `accepted-scoped`, 1 for a blocked/incomplete execution, and 2 for invalid invocation/runtime input.

The [standalone mechanics fixture](../examples/government-g2/README.md) repairs an actual inventory-overflow implementation, checks it, collects two actual external responses including `assent-unaffected`, and promotes its managed ref. Its deterministic programs prove invocation and gating mechanics; they do not prove autonomous engineering quality, independent authorship, model review or human acceptance. Scientist's public adapter v1.1 wrapper, model budgets and trial orchestration remain separately owned.

State files and Git CAS are separate effects; no atomic ledger/Git transaction or automatic rollback is claimed. G5 supplies the bounded recovery path below. Processes share caller OS rights: fresh contexts, path checks and input audits provide a cooperative boundary. External clients must coordinate managed-ref checkout with promotion; Git offers no shared lock across a worktree checkout and the final CAS. Live, foreign and unrecognized surviving fences are not taken over.

For this bounded G2 slice, the Area verifier is a read-only evidence producer explicitly assigned by the frozen plan to existing local and parent integration duties. Its passed review is separate from Ressort votes and grants no acceptance, change or promotion authority. G2 therefore adds no per-Area review-Mandate gate and derives no review authority from implement. Ressorts retain their explicitly prior-Constitution-authorized review Mandates and their separate votes.


## G3: recursive delegation and parent integration

G3 uses the same explicit `government --action run --write` command with an optional `recursion` runtime object. Omitting it preserves the bounded single-Writer G2 path. `recursion` contains `limits: {maxDepth, maxFanout, maxCalls}`, `parallelism`, `maxRepairs`, and `areas`. Each non-root Area entry names its full `area` identity, distinct `executor` and `verifier` runners and nonempty `checks`; the root uses the existing top-level runners/checks. The runtime must assign exactly the participating non-root Areas from the frozen prior model and plan. It cannot supply a different hierarchy or confer authority.

Limits are explicit and finite: depth 1–32 (root is depth 1), fanout 1–32, total actor calls 1–4096, concurrent process/check operations 1–16, 0–2 repair rounds per Area invocation, and at most 128 non-root Areas. Preflight reserves the initial tree, a separate final Root review and the frozen cabinet. A synchronized live counter covers all actual actor invocations including repairs and final votes; exhausted limits abort rather than imply agreement. Parent waits do not hold process permits. The existing global run deadline and actor/check limits still apply. Model relationships determine the same recursive algorithm at every depth; there is no two-level execution special case. The existing per-invocation protocol also limits subject/policy identifiers and artifacts to 128 entries, artifact payloads to 8 MiB, context to 8 MiB and the full JSON message to 32 MiB. Known oversized node subject/artifact sets reject before child execution; growing lineage still must fit the protocol when invoked.

Each tree node separates its own `Work.Paths` writer permissions from aggregate descendant `Paths` supplied as read context. Its explicit local prior Mandates remain authoritative; delegation cannot enlarge subject/action scope. Selected paths retain exactly their model-declared writer. Parent and child contexts bind the order, prior definitions and authority chain, local Work, exact artifact bytes, delegation/node/input digests, relevant child reports and finite limits. Other Areas' runner configurations and executor transcripts are not supplied as child context. These are cooperative context boundaries, not OS access isolation.

Sibling subtrees run from the same immutable input in separate materialized candidate directories. The Host merges their actual changed bytes and modes only within their disjoint frozen writer sets; collisions, deletions and non-owned changes fail. No child candidate updates the active ref. A parent Executor can change only its own local files. A structural parent without local writer paths receives no Executor call: the Host performs deterministic integration and a fresh external parent Verifier checks the resulting material. This creates no parent writer permission over child files.

Every node runs its own fresh technical checks and independent review on the actual assembled snapshot. An ordinary completed check failure may still be independently reviewed; both the checks and review must pass. Missing tools, input mutation, deadline exhaustion and other incomplete technical evidence stop the run. A failed composition can trigger only the configured bounded repair: the same frozen subtree is delegated again with explicit failed-candidate/check/review feedback, new processes and fresh checks. Earlier successful child reports are lineage, never a substitute for checking the new aggregate.

Only the settled Root result becomes the final Git/material candidate. The Host reruns root checks, invokes a separate fresh Root reviewer on that exact final candidate and gathers new candidate/evidence-bound votes from every originally frozen Ressort, including explicit `assent-unaffected`. Child/intermediate reviews are not votes. The retained delegation and Area report digests join final evidence; G2's prior authority, durable intent, writer fence and exact Git CAS remain the only promotion route. A failed intermediate candidate cannot promote.

The [native G3 mechanics example](../examples/government-g3/README.md) provides two independently valid invoice children whose first composed total is wrong, with a no-repair rejection and a bounded-repair path. It uses deterministic external programs to exercise actual process, byte integration, independent review and promotion mechanics. It does not demonstrate real-model engineering quality or autonomous productivity. Public study fixtures and private scoring remain Scientist-owned; G4 amendment and G5 queue mechanics are described below.

## G4: delegated model maintenance and bounded conflict

An `amend-model` Order requires the explicit runtime `amendment: {maxRepairs: N}` with `N` between 0 and 2. Its purpose states the model gap and desired decision. Host binds the exact caller-selected Government source path into the prior plan. That path must already be a canonical Artifact with one prior writer and an affected Realization. The responsible Area needs an old `amend-model` Mandate for the subject; the model-file writer independently needs that permission for every actually changed subject. Realization files still require their own prior `implement` permission. An amendment permission never becomes general file ownership.

The bounded amendment contract permits substantive changes to existing domain Definitions and their existing purpose-bearing Responsibility and Realization relations. It can change a business rule or transfer its accountable Area within prior-authorized work/review coverage. Full identities, custom Schemas, acquisition boundaries, Artifact paths/writers, Areas, Mandates, Ressorts, Capabilities and Constitution content remain frozen. Additions/removals and authority changes require escalation. The prior Constitution may explicitly list domain Root goals in `spec.protectedSubjects`; those Definitions are immutable for autonomous amendment. Host does not infer a Root goal or business requirement from prose or source code. Model authors must declare the protected identities, and independent reviewers assess semantic sufficiency.

Proposed models compile separately and must retain consistent responsibility, managed realization coverage, purpose-bearing relations and exact prior writer scope. A proposed dependency or realization closure cannot widen the frozen order. The changed model and actual realization bytes form one candidate. Its identity binds both the prior Constitution digest and the proposed model digest, together with the actual Git tree, plan, checks, tools and inventory. Proposed rules may be used to test candidate behavior; they never authorize their own writer, amendment, cabinet or promotion.

Each candidate round runs fresh technical checks and separate independent review. The original cabinet and procedure remain fixed. Every selected old Ressort supplies a new explicit vote on the exact final MaterialCandidateID, EvidenceID and round; an unaffected Ressort still explicitly assents. Changed bytes or evidence cannot reuse an earlier vote. Bounded ordinary repair retains the rejected round and supplies its concrete feedback to a fresh attempt; exhaustion never becomes assent. A stale or malformed vote, unauthorized change or missing prior amendment mandate blocks the affected order. There is no autonomous Owner-approval channel and no court override in this G4 slice.

The external run report retains concrete escalation data: prior authority and base, order and affected subjects, candidate paths/digests, applicable findings, checks/reviews/votes and uncertainty, attempts consumed, and a required decision addressed to an applicable higher prior Area or the Owner. An actor's text `Owner approved` cannot authorize activation. A blocked order creates no promotion or acceptance decision. Separately supplied independent orders can continue under the still-active prior Constitution; shared realization or explicit dependency links broaden their scope conservatively. The finite queue below coordinates those explicitly supplied orders.

The [public native G4 example](../examples/government-g4/README.md) exercises actual model/code changes, protected-goal and missing-mandate escalation, replay of old vote bindings, and an independent order after conflict. Deterministic external actors establish mechanical behavior only. Public fixtures and private study scoring remain separately owned; real-model quality, institutional independence and human acceptance require separate evidence.

## G5: finite persistent queue and recovery

```powershell
markitect government --repo C:\absolute\project --action queue --backlog C:\external\backlog.json --write
markitect government --repo C:\absolute\project --action resume --backlog C:\external\backlog.json --queue C:\external\state\QUEUE_DIRECTORY --write
```

The caller supplies one strict external JSON backlog with `apiVersion: markitect.government-queue/v1alpha1`, an existing absolute external `stateDirectory`, `limits`, and a finite `jobs` array. Each job has a unique `id`, repository-relative `configPath` and `orderPath`, an absolute external `runtimePath`, and explicit predecessor IDs in `dependsOn`. Its runtime retains the existing exact `expectedBase` and managed `activeRef` binding. The scheduler does not rewrite Orders, infer new goals, rebase them automatically, or supply an Owner/Court approval route. Independent branches can use distinct managed refs. Shared realization and subject dependencies still broaden each immutable Government plan conservatively.

`limits` contains `actorStarts` (1–4096), `maxRepairs` (0–64), `maxWallTimeSeconds` (1–86400) and `maxParallelism` (1–16). At most 128 jobs are admitted, with prerequisites listed before their dependent jobs. Orders run serially; their configured recursive actors and checks can run concurrently within the frozen runtime and queue ceiling. Before an order starts, its full runtime concurrency must fit the queue capacity left by retained in-flight actor reservations, including interrupted unknown actors. A blocked or incomplete predecessor blocks its explicitly dependent jobs; other supplied jobs continue while the cumulative budget permits. Empty, exhausted and fully blocked queues end with a durable report and no background polling or scheduling.

Start returns a unique `queueId` and `queueDirectory`. Resume explicitly selects that directory and the same backlog. A flushed journal under the exclusive writer lease binds the queue, job and unique Run IDs, frozen source/model/runtime/tool inputs, states, checkpoints and next action. Replay rejects broken hash chains, inconsistent resource counters and incomplete final records. Reconstruction uses those records rather than chat history. Changed backlog or runtime/tool bindings do not reuse old assent; they require a newly supplied, freshly bound execution. Existing terminal stops and consumption are retained on every resume. A stale queue retains completed job reports as historical evidence and cannot use them to authorize more work.

The queue durably charges each actor reservation before invoking its process and each repair before starting that attempt. `inFlightActors` and `peakParallelism` retain reserved actor slots; an interrupted unknown invocation does not silently free its slot. It conservatively reserves the complete configured run timeout before each order, without refunding the unused part; `elapsedWallTimeSeconds` separately reports queue age from its durable start, including interruption time. A crash cannot reset either reservation. Actor receipts add observed wall time and any supplied token/tool usage. Missing provider usage remains explicitly unknown; known totals are partial observations, not inferred cost. An interrupted reservation remains consumed with unknown effects. The queue never automatically repeats an interrupted actor or turns an unknown effect into success.

Before promotion the Host durably checkpoints the exact candidate, checks, evidence, votes and decision. Promotion then writes its intent, performs Git CAS and writes a separate completion record. Recovery verifies the bound intent and exact tokenized old-to-candidate edge in the managed ref's history. An already advanced ref is retained. A missing, truncated or ambiguous history leaves the job incomplete with a concrete escalation, even if the current ref equals the candidate. Resume never repeats the CAS. An unchanged terminal queue performs no additional actor starts or promotions.

OS-held leases exclude concurrent cooperating hosts and record a fresh fencing token. Only a recognized same-host lease whose OS exclusion is released can be reacquired; live, foreign, empty legacy or otherwise unrecognized locks remain blocked. Recognized v1 owner records require exactly the six supported fields, trimmed nonempty host/user identities, a positive PID, a 64-character lowercase hexadecimal token and a nonzero canonical UTC timestamp. Duplicate, aliased, unknown, missing or invalid fields are rejected without changing existing bytes; Verify applies the same format checks and compares the complete held owner, including its timestamp. These mechanisms do not provide an OS sandbox, atomic Git/journal commit, authenticated approval or semantic acceptance. The [public native G5 fixture](../examples/government-g5/README.md) exercises actual process interruption and deterministic actors; it supplies mechanical evidence only. Scientist owns the independent study and real-model comparison.

Queue actions return JSON on stdout. Exit 0 means the finite scheduling or unchanged resume completed; inspect top-level and per-job states for blocked or incomplete work. It does not mean all jobs were accepted. Invalid CLI combinations exit 2; input, lease, stale-binding and persistence failures exit 1. Durable `events.jsonl`, immutable `queue-report-NNNNNNNN.json` snapshots, and bound run reports remain under the selected external state roots. Resolving an unknown effect or changing an Order's authority requires the responsible human and fresh explicit inputs; there is no automatic waiver or approval prompt.
