# Government: model, native inventory and bounded execution

This experimental source-only branch implements G1 and the bounded G2 execution slice of the [delivery plan](design/government/delivery-plan.md), on accepted G1 `028c137dac733c0a9c8539727e14bdba55fca789`. It does not update an installed release. [The architecture](design/government/architecture.md) remains the design contract; this page owns the executable format and limits. G2 acceptance and full candidate gate evidence are separate from the mechanics described here.

## Commands and input

```powershell
go run ./cmd/markitect government --action schema
go run ./cmd/markitect government --repo examples/government --config government.yaml --action inspect
go run ./cmd/markitect government --repo examples/government --config government.yaml --action plan --order order.yaml
go run ./cmd/markitect government --repo examples/government --config government.yaml --action plan --order negative-order.yaml
```

`schema` emits the actual built-in `markitect.government/v1alpha1` structural Schema. `GovernmentSource` is one strict YAML document with `apiVersion: markitect.government-source/v1alpha1`, `constitution` (full identity), inline `schemas` and `definitions`, and `observation`. Custom domain Schemas and the built-in Schema compile through the unchanged minimal Core. Definitions and relation Definitions carry `purpose`. Full identities contain `apiVersion`, `kind`, explicit `namespace` (possibly empty), and `name`. Host resolves arbitrary `subject` and mandate `scope` identities exactly; these are object values, not polymorphic Core references.

`Constitution` selects one root Area, a nonempty Ressort cabinet and `unanimous-explicit-assent`. Areas recursively reference parents and optional pinned Capabilities. Ressorts reference review Mandates without implicit writer permission. Mandates contain an Area, exact subject scope, allowed actions (`implement`, `review`, `amend-model`) and, below root, a higher mandate. Host validates acyclic delegation, hierarchy and scope/action subsets. `Responsibility` assigns one accountable Area per subject. `Artifact` declares an exact path, class (`canonical`, `realization`, `generated`, `foreign`) and, for managed material, one Area writer. Purpose-bearing `Realization` connects subjects to artifacts many-to-many. File ownership is independent of subject responsibility and crosscutting review.

The caller explicitly selects an already accepted Constitution input. Its digest covers the compiled domain model and organization together, excluding observed bytes and provenance. G1 cannot authenticate this acceptance. `Order` is a separate strict document with `apiVersion: markitect.government-order/v1alpha1`, `kind: Order`, `purpose`, `activeConstitution` (exact prior digest), `action`, and `subjects` and/or exact `paths`. Optional `unknownScope: true` widens to all modeled subjects and root review, and blocks unresolved work. Proposed amendments cannot change the authority of their own plan. Organizational authority changes require owner escalation. Actual model amendment review and activation remain G4 work.

## Native acquisition and coverage

`observation.roots` requires normalized, non-overlapping repository-relative roots; `.` selects the repository. `exclusions` and `admitIgnored` contain `{path, reason}` boundaries. The scanner enumerates tracked, untracked and ignored entries, including conventionally filtered build directories. Excluded directories remain visible without reading their contents. Ignored bytes are read only under explicit `admitIgnored` entries. `.git` metadata is an automatic reasoned exclusion; links, Windows reparse points, special files and Git submodules remain boundaries and are not traversed. Classification errors inside Git repositories fail closed. Non-Git directories are supported as native sources.

Each observed regular file carries a bytes digest, mode, source and status. The report binds roots, exclusion/admission reasons, entries, HEAD when available, and traversal completeness. It is **always provisional**: HEAD is provenance, not a claim that these are HEAD's bytes or an atomic filesystem snapshot. Config and Order must be admitted, unchanged captured inputs. Traversal is bounded to 100,000 entries, 64 MiB per file and 512 MiB total. Unreadable paths remain incomplete; entry-limit exhaustion aborts acquisition.

Survey joins intended artifacts with captured entries. Unassigned files retain `purpose: unknown`; absent artifacts are missing; descendants of excluded/linked boundaries or paths outside roots are unavailable. Exclusion is never conformance. `accounted-within-declared-boundary` means structural accounting only, not implementation or semantic verification. `inspect` exits 1 for incomplete accounting, 0 for accounted scope, and 2 for invalid acquisition/input. The example intentionally exits 1 because it contains unassigned files.

## Planning

Planning follows explicit domain references in both directions and shared realization paths conservatively. It resolves accountable Areas, authorized writers, prior Mandates, parent integration review and the frozen cabinet. Source-code or prose-link semantics are not inferred. Foreign inputs alone cannot fulfill implementation work. Unknown identities, conflicting responsibility/writers, insufficient authority, unavailable selected inputs and empty work block the plan. Unrelated unknown artifacts remain visible and allow only a scoped proposal. Status is `blocked`, `planned-scoped`, or `planned-within-declared-boundary`; none means implementation or acceptance. A blocked plan exits 1, a proposal 0, and invalid input/acquisition 2.

Pure G2 records establish an acyclic chain: `MaterialCandidateID` binds prior authority, base revision, material tree/model, plan, check definitions, tool pins and optional inventory; `EvidenceID` binds immutable result/report digests and round; Voten bind both IDs and prior mandate/configured slot; `DecisionID` binds a complete, current, unanimous vote set from the supplied frozen cabinet. Constructors validate consistency, not authentication, independent review, check sufficiency or promotion rights. No G1 command creates or consumes acceptance decisions.

## G2: one Writer Area through the native Host

```powershell
markitect government --action run --repo C:\absolute\project --config government.yaml --order order.yaml --runtime C:\external\runtime.json --write
```

`run` requires explicit `--write` and a strict external runtime JSON document. The read-only actions reject execution flags. Runtime API `markitect.government-execution/v1alpha1` requires `activeRef`, `expectedBase` (full lowercase Git OID), `stateDirectory`, `temporaryDirectory`, `timeoutSeconds`, `executor`, `verifier`, `ressorts` and `checks`. The active ref must have exactly one safe name below `refs/markitect/government/active/`. Source, Git metadata, state and temporary roots are disjoint real directories. Config and Order are read from the exact active commit, never from uncommitted checkout bytes. Initial mismatch rejects the run.

Each runner names `slotId`, literal `command` and `args`, explicit `model` and `providerVersion`, `timeoutSeconds`, `maxStdoutBytes`, `maxStderrBytes`, and optional `modelOptions` and `runtimeFiles`. Each Ressort entry binds a complete `ressort` identity to its `runner`. Every prior Cabinet member must occur exactly once; executor, verifier and Ressort slots are distinct. Configured slot names are assignments, not authenticated identities. The executable and declared runtime-file bytes are fingerprinted before execution; actual receipt config/executable digests must match the frozen slot. Absolute file arguments require declared runtime files. Supported interpreter invocations require a declared absolute script or explicit inline-code argv; callers own completeness of transitive runtime dependencies.

Runtime JSON is limited to 4 MiB with unknown and duplicate case-folded keys rejected. There are at most 128 checks and 128 Ressorts. Actor limits stay 1–600 seconds and 1 byte–16 MiB per output stream. Run budget is explicit, 1–1800 seconds. Check definitions use the existing fixed-snapshot check contract (default 600 seconds; explicit 1–1800). Before each check, the Host reserves its entire command cap plus wait allowance from the remaining run budget. Actor/Git calls observe the run deadline; each existing snapshot check finishes under its own command cap, and an elapsed run cannot proceed to review or promotion. Cooperative snapshot IO is not a hard real-time guarantee.

The Host freezes the prior Constitution, plan, single nonempty Writer scope, Mandates, Cabinet, base and runtime/tool pins. G2 accepts only `implement` under unchanged prior authority and cannot change Config or Order. It materializes an isolated base snapshot, invokes the configured Executor in a fresh empty process context, audits inputs, and applies returned file bytes only within the frozen Writer paths. Git objects are written with a private index and one parent; the user's index, branch and working files remain outside this write path. The complete Git tree and materialized snapshot digest bind the material identity; unchanged Git paths excluded by source acquisition remain inherited from the base and receive no semantic coverage claim.

Fresh technical checks run against that fixed candidate. Separate Verifier invocations must explicitly pass every required Area integration scope and affected subject with a nonempty explanation and without uncertainty. Only then does the Host form `EvidenceID` from check and actual actor result digests. Each frozen Ressort receives a separate invocation with the same material/evidence/round and must return one `government-vote` observation, with a strict JSON `detail` containing `outcome`, nonempty `reason`, `materialCandidateId`, `evidenceId` and `round`. Both `assent` and explicit `assent-unaffected` count. Missing, rejected, foreign or stale review/vote evidence blocks promotion; successful constructors alone never manufacture process evidence.

Before promotion the Host rechecks candidate bytes and tool pins. Under a common-Git-directory writer fence it durably publishes an external `PromotionIntent`, rechecks checkout/ref state and applies a Git compare-and-swap from the exact base to the exact candidate commit. A private empty hook directory suppresses configured reference-transaction hooks. Checked-out and symbolic refs are rejected. A stale base, changed reviewed tree or occupied writer fence stops takeover. The CAS updates only the dedicated managed ref; it never advances a checked-out user branch.

The JSON stdout report and external JSON records retain actual actor receipts, fresh checks, IDs, votes, decision, promotion state and explicit limitations. Report files use the same exclusive durable publication primitive as the intent: file plus directory sync on Unix and flushed staging plus write-through publication on Windows. Invalid external reporting boundaries cannot safely receive an abort file; the command still emits its incomplete result. `run` exits 0 only for `accepted-scoped`, 1 for a blocked/incomplete execution, and 2 for invalid invocation/runtime input.

The [standalone mechanics fixture](../examples/government-g2/README.md) repairs an actual inventory-overflow implementation, checks it, collects two actual external responses including `assent-unaffected`, and promotes its managed ref. Its deterministic programs prove invocation and gating mechanics; they do not prove autonomous engineering quality, independent authorship, model review or human acceptance. Scientist's public adapter v1.1 wrapper, model budgets and trial orchestration remain separately owned.

G3 recursion, G4 amendments, and G5 queue/restart recovery remain unavailable. State files and Git CAS are separate effects; no atomic ledger/Git transaction, automatic rollback or crash recovery is claimed. Processes share caller OS rights: fresh contexts, path checks and input audits provide a cooperative boundary. External clients must coordinate managed-ref checkout with promotion; Git offers no shared lock across a worktree checkout and the final CAS. A surviving fence is not stolen automatically.

For this bounded G2 slice, the Area verifier is a read-only evidence producer explicitly assigned by the frozen plan to existing local and parent integration duties. Its passed review is separate from Ressort votes and grants no acceptance, change or promotion authority. G2 therefore adds no per-Area review-Mandate gate and derives no review authority from implement. Ressorts retain their explicitly prior-Constitution-authorized review Mandates and their separate votes.
