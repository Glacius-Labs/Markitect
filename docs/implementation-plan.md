## Work streams

The owner has approved at most two writing streams initially: Foundation/Command for S1 and Harness/Provider feasibility against existing source seams. The latter may implement only isolated tested native preparation/transport capabilities with real consumers; it must not define competing Run contracts. S1 hands the shared preparation scope to S2 without introducing a compatibility bridge. S2 has one Project/Run/Git/state integration owner and the Harness/Provider owner as the second writer on reserved files. S3 transfers Apply/workflow/CLI/bootstrap to the command owner after S2 signatures integrate. No independent interface-only F/H/G/N waves.

The Run/Git/state owner is accountable for complete standalone closure, candidate/result persistence and cleanup. The Harness/Provider owner is accountable for actual native loading and login, not only a text builder. Exact file reservations and dependency handoffs are in [future assignments](development/v1-workstream-assignments.md). Coordinator consolidates/reviews; it does not compete in another writer's files. Gate/map/registry/self-model/generated files have one writer at a time.

Use a tiny committed fixture with Root, two siblings, a grandchild and an empty Package. Real local Git and file-backed state meet controlled provider sessions. ## Integration

Source implementation is approved. Keep the existing development policy: focused PR, meaningful local checks, independent complete-diff review, freeze reviewed head, merge the exact head without bypassing protection, then read Main back. Recompose/review substantive overlapping changes. Automatic CI is paused; full CI is manually available and final/release evidence remains separate. No merge waits for hosted CI by default, and absent hosted execution is never reported green.

Use isolated worktrees from verified integrated bases, non-protected scoped branches, preserve unrelated work and revalidate ownership before changes. No parallel Go commands or source edits during a gate in the same checkout. [CONTRIBUTING](../CONTRIBUTING.md#verify-a-change) owns routine checks. New/deleted artifacts require exact registry updates. Self-model changes require official docs preview/digest/write, not manual generated-view edits.
