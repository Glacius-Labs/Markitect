# Selective adoption handoff

This source slice closes the preparation/Copy Me coordination gap. It implements adoption infrastructure outside Core; published v0.12.0 and the Domain language remain unchanged. The [vision](../vision.md) supplies the purpose. The owner selects evidence, preparation captures it, Copy Me interprets supplied bytes, and a separate human-reviewed project change creates authority.

## Contract and acquisition

`adoption-scope/v1alpha1` and `adoption-handoff/v1alpha1` are standalone records under `markitect.example.org/`, not Resources. Scope supplies an ID, purpose, review reference, privacy/excerpt permission, retention expectation, and separate repositories with stable supplied IDs, local roots, full lowercase Git commits, exact paths with inclusion reasons, and optional exclusions. These are claims, not authenticated permissions. Coverage is bounded to supplied questions/items: examined, no-evidence-found, unavailable, redacted-or-withheld, uninspected. It never implies whole-repository inspection.

Preparation validates all selections before reading any blob in that repository. Literal fixed-tree metadata lookup must match each exact path; no globs, directories, symlinks, gitlinks, unsafe portable aliases, or unsupported modes. Only UTF-8 regular/executable blobs are accepted, with existing source memory limits. It opens only the selected blob IDs. Existing whole-snapshot acquisition and `Snapshot.Digest` retain their meaning.

Repository identity binds canonical top-level root, worktree Git directory, common Git directory, object format, and their digest. Linked worktrees keep distinct roots/Git directories and shared common-directory identity. Remotes are neither acquired nor identity-bearing. Root aliases/reparse points are refused. This detects ordinary substitution/location/layout changes, not an authenticated repository incarnation: an identical replacement at the same locations with the same commit/bytes cannot be distinguished durably. No credentials or remote URLs are persisted.

Selection digest binds the ordered effective repository identities, full commits, exact selections/reasons/exclusions, modes/hashes, and optional supplied Markitect evidence identities. Capture digest additionally binds each selected-only snapshot digest. Handoff digest binds the complete typed record, including purpose, review/privacy/retention and coverage. Ordering is canonicalized before capture. Digests exclude their own digest field and use deterministic JSON encoding of closed typed values. Stored handoff YAML also has an exact-byte digest for decision freshness. Neither identity nor hash proves authorization, completeness, truth or privacy at an external model provider.

An unrelated unselected-file change at the same fixed commit has no effect. Selecting a newer commit requires a new scope/review reference and capture: selection/handoff identity changes even if selected bytes and the legacy selected-only snapshot digest do not. Working-tree changes are never read. Changing paths, selected modes/bytes, repository identity, revision, privacy or scope creates a new handoff; old decisions do not transfer.

## Commands and external storage

`prepare --scope FILE --output ABSENT_EXTERNAL_DIRECTORY` captures an owner-supplied selection in memory and previews the machine-readable handoff without writing. `--write --expect HANDOFF_DIGEST` recomputes it and requires the exact reviewed preview digest before exclusive workspace creation. There is no implicit detection or content scan. Existing greenfield `init` is untouched.

The destination parent must already exist, with safe canonical spelling and no reparse ancestry. Destination must be absent and outside, and not an ancestor of, any source root or Git metadata directory. Because no selected source root contains the destination, its Areas/packages/generated outputs cannot overlap it. No Project is required or loaded. The workspace contains only `handoff.yaml` and `evidence/REPOSITORY_ID/EXACT_PATH` selected bytes. Original Git modes are recorded; evidence files are private regular storage, not executable projections. Directories/files use owner-only permissions where the OS honors them; Windows ACLs remain the caller's responsibility. Logical immutability is enforced by exclusive creation and hash validation, not WORM storage or a process sandbox.

Every created directory/file is reported on partial failure. Nothing is automatically removed or rolled back. Any existing destination, including partial state, is refused. The owner controls access, retention, deliberate recovery and deletion; no cleanup daemon or automatic retention enforcement is introduced.

## Copy Me input and decision

`copy-me --workspace DIRECTORY --queue FILE [--decision FILE]` reads only the handoff, its exact stored evidence files, and explicitly supplied queue/decision files. It does not call Git, load a Project, discover files, query a provider or rewrite any input. An evidence request names repository/path/reason/insufficiency; it grants no read authority. A new owner-selected preparation is needed.

The queue keeps evidence entries (stable ID, repository/path/hash, optional bounded line range, stance, observation, privacy-permitted excerpt, duplicate/conflict links), candidate records (rule/scope/conditions/classification, evidence IDs, confidence/basis, alternatives/uncertainty/questions), coverage and explicit requests. Coverage IDs, repositories and questions must remain those selected by the owner; Copy Me may supply a later examination state/reason. Reports retain both immutable preparation coverage and the current interpretive claim. Changing a claim changes queue bytes and stales a prior decision. It does not add evidence paths or prove completeness. Frequency claims bind numerator/denominator, selection rule and repository revision/time scope. The validator checks shape, references, ranges, byte digests and preserves claims; it cannot evaluate semantic merit or completeness. Counterevidence can be absent only as explicit uncertainty, not invented to satisfy a template.

A separate decision records supplied reviewer/calendar-valid `YYYY-MM-DD` date/rationale/scope/status for one candidate file's exact raw-byte digest, exact queue bytes, exact handoff bytes and handoff identity. Accept/reject/defer/split/revise are dispositions; none performs adoption. Any changed queue/handoff/candidate bytes or selected evidence invalidates the old decision. Reviewer identity is unauthenticated. Optional ContextRun/selection/tool/report/context identities are accepted only when explicitly supplied and structurally complete, with their exact selected artifact hashes checked; they do not become prerequisites or graph edges. Their supplied selection/build identity is not recomputed by Copy Me.

## Ownership

The acquisition proof bounds logical Git blob requests and bytes passed into review. It does not instrument Git's internal pack/delta storage reads or provide an OS/process sandbox. Access to the selected repository and local workspace remains caller authority. It proves neither secret detection nor provider-side privacy.

`internal/source` owns selective Git acquisition. `internal/adoption` owns the shared closed handoff/scope and deterministic validation over explicit bytes. `internal/app/adoption_*` owns orchestration and guarded external storage. `internal/copyme` owns interpretation-record validation, with no Core/app/source acquisition dependency. CLI owns explicit dispatch and exits: success 0 for completed preparation/byte-reference validation; invalid/refused/stale input 2. Success never implies canonical adoption or authenticated approval.

Direct acquisition spies, external-write fault injection, CLI fixtures and Windows/Linux gates establish only the tested byte/read/write/freshness properties. The public sanitized Konfyra inventory can replay this boundary without private source capture. Synthetic interpretation records establish no discovery quality. No new Domain operator, inference, automatic adoption, provider semantics or background operation is included.
