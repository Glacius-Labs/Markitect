# Zero-churn representation adoption (source alpha)

Existing representations do not become canonical intent. Owner-reviewed canonical Definitions and desired representations must exist first. A separate exact artifact selection matches existing bytes to one desired representation; it is not source inference, generation, normalization or permission to overwrite UNKNOWN files.

`adopt-plan` is read-only. It binds a full canonical revision, full target Git revision and snapshot, selected paths/bytes/modes, resolved runtime capability, selected policies, declared command definitions, an explicit supplied active-record set and an owner-supplied review reference. It returns a prospective unverified ProjectionRecord and an adoption plan digest. The reference and approval are supplied claims, not reviewer authentication or proof that source semantics were reviewed.

`adopt` requires the exact reviewed plan digest and freshly derives the same plan. It runs the existing immutable fixed-check verifier. Only a passing bounded result returns the adopted record together with its separate verification evidence. Failure or missing evidence returns no adopted record. Neither operation generates target bytes, calls a renderer/Executor, changes canonical input, writes artifacts, selects active ownership or persists a ledger. The caller must review and explicitly persist/select the record. The prospective owner is checked against the supplied active records before any verification: collisions and implicit replacement of an existing representation owner fail. The active set is an explicit supplied claim, not automatic ledger discovery. Unknown files outside the exact selected set remain visible in `unmatchedArtifacts`; normal reconciliation continues to escalate them. A record proves only its exact selected artifact set, not whole-prefix completeness.

The operational record stores `origin: adopted`, the fixed adoption evidence revision, review reference and retained artifact facts. Those facts participate in content identity. Existing source-alpha records without adoption metadata retain their digest interpretation. Adopted records may contain only retained artifacts, never created/modified/deleted claims. Canonical revision and evidence revision remain distinct. Changed semantic inputs, source config/checks/capability, target revision/bytes/modes, artifact selection or review reference stale the approval. Later target drift still fails normal verification and contributes reconciliation work.

This proves zero target churn and fixed-command evidence for an explicitly selected representation. It does not establish whole-repository completeness, business correctness, independent agent assurance, authenticated owner approval, or a general Brownfield adoption controller. Existing valid representations can be retained despite differing from a deterministic renderer's preferred form; declared evidence and owner review govern adoption, not byte equality with a regenerated output.
