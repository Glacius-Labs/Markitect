# Proof-readiness capabilities

Decision frozen on 2026-10-06 after the owner's complete-capabilities steer. This implements the accepted [canonical operating model](canonical-projection-reset.md); it adds no Core language concept. [Vision](../vision.md) owns the product thesis. Source-only work does not change published v0.13.0.

The [protocol-v1 checkpoint](../../experiments/capability-proof/results.md) remains a historical C5 FAIL. Its snapshots, raw logs, receipts and stop decision are not edited into a successful result. The new steer supersedes that blanket implementation pause: missing accepted capabilities are implementation work followed by fresh, versioned proofs. Actual product-model falsification, inaccessible external execution and genuine owner authority decisions remain stop conditions.

## One compiler, explicit acquisition

The normal source snapshot and digest contracts remain unchanged. A selected canonical loader first reads one exact config at a full immutable commit, then its exact declared Definition, Module manifest and Schema paths. It calls the same decoder, Module resolver and Core compiler as the ordinary loader. Full revision, repository identity, selected paths and selected-byte digest remain distinct evidence. All canonical inputs are still compiled; this is not an incremental compiler.

Working target observation has separate channels: metadata-only inventory of explicitly configured roots, and bytes read for explicitly affected roots/owned artifacts. Skipped bytes are unobserved, never clean or verified. Unknown paths remain visible within declared inventory scope; nothing claims whole-repository coverage. Reconcile reports conservative model/revision evidence refresh separately from materialization work.

Application plans bind exact canonical input bytes, observed target preimages/modes and absence checks, declared-root inventory, full source HEAD, runtime bindings and ledger head. Newly selected files must be validated before execution; stale in-flight intent/runtime/ownership fails before writing. Reviewed outputs never become canonical intent.

## Modules propose, Host composes

Markdown and .NET each own a private Core-facing proposal input and work/no-op/escalation output. They do not import one another, Host or shared work DTOs. Host translates validated IR, selected policies and operational observations. Markdown owns its output naming and rendering. .NET proposes a bounded Executor task and permitted target prefix/extensions; the Executor selects exact filenames. Host validates filenames, ownership, canonical-source protection and collisions before forming a plan.

A no-op means the stated inspected evidence supports no materialization work; it does not imply semantic PASS, acceptance, or freshness of skipped/global evidence. Missing, conflicting or insufficient guidance escalates rather than inventing conventions. No Module deletes retired/unowned artifacts implicitly.

## Durable operational records

A Host-owned record store persists existing ProjectionRecords and separate VerificationResults unchanged. The store requires an explicit external absolute location disjoint from source/Git/target roots. Immutable, versioned, bounded hash-chain events record attempts, verification and a complete explicit active-owner selection. Canonical serialization, sequence, prior links and content IDs are checked on read.

Exclusive creation and writer lock plus expected-head compare-and-swap serialize changes. Partial/staging remnants and stale locks block with concrete paths; there is no automatic deletion, rollback, latest-mtime selection or recovery. A committed event can be recognized by its digest when retrying an uncertain write. Active selection is ownership, not PASS; failed/incomplete verification is retained. Partial/escalated attempts cannot silently replace complete ownership. Supplied identities/review references are not authentication.

## Real bounded agent execution

Host invokes an explicitly configured literal command with closed versioned JSON input/output, fixed limits and a fresh external workspace/session for every invocation. Roles are Executor, Verifier and reverse-inference proposer. Input binds canonical revision/model, selected identities/Schema purposes/policies, exact Module/runtime configuration and supplied artifact bytes. Context inclusion and edit scope are separate; referenced external facts explain relationships without granting ownership.

Executor returns candidate bytes or escalation. Verifier receives independently selected canonical obligations, actual candidate/materialized artifacts and applicable fixed checks, not the Executor transcript, hidden reasoning or assertions as proof. It returns passed/failed/incomplete/escalated evidence with exact input bindings; no autonomous authority to waive or alter intent. Reverse inference returns a noncanonical candidate requiring real owner disposition.

Receipts bind request/context/configuration/command identities, unique attempt/session, outputs, observed duration, diagnostics, retries and provider-reported usage when available. Uninstrumented tokens/calls remain unavailable. Boundary tests may use helper processes; AI behavior proofs use real fresh agents. External commands run with local caller authority: fresh directory/read-only declarations are not an OS sandbox, credential filter or provider privacy guarantee.

A standalone Codex adapter translates this generic command protocol. Provider/model options remain outside Core. Its sessions and telemetry do not prove semantic correctness. Executor-authored tests never replace independent verifier evidence or project-owned checks.

## Controller and recursive assurance

The operational sequence is canonical compile → semantic diff/impact → Module proposals → conflicts/ownership → bounded execution scopes → Executor → reviewed exact candidate plan → explicit guarded Apply → immutable checks and separate Verifier → affected parent scope's own checks → record/active selection → converged or explicitly incomplete.

Preparation and observation remain read-only to the adopter; invoking a configured runner is explicit and may incur provider cost. Saved plans include exact candidate bytes and input identities. Apply requires explicit write intent and an expected reviewed digest; it recomputes all bindings. Multi-scope plans validate the aggregate write set before writes; partial failure names every created/changed artifact. No silent rollback, automatic deletion, canonical rewrite or adoption.

Recursive scheduling uses the existing finite explicit scope DAG, validates it before any invocation, and executes children then each affected parent's own obligations once. Passing children cannot make a parent pass without its composition evidence. A failed/incomplete child propagates visibly. Runtime scope configuration lives above Core; no hierarchy/query primitive is added.

Verification remains fixed-input. If a workflow needs a post-apply immutable Git evidence commit, its creation is a separate explicit write operation affecting object storage only, with no HEAD/index/branch movement. It must not manufacture a Git revision for an in-memory candidate. Review references and passing technical checks never imply human architectural acceptance.

## Work order and acceptance

1. Selected source/target infrastructure, Module proposals, durable ledger and bounded runner evolve independently behind these contracts.
2. Host integrates real preparation/application/verification, scoped contexts and recursive scheduling, with stale-work negative controls.
3. New-model workflow/provider projection and Brownfield reverse inference use the same authority boundary.
4. Fresh C1–C13 experiments retain positive, negative and invalid outcomes separately; then execute the queued concurrency, longitudinal and re-projection proofs to their meaningful limit.

Normal Windows/Linux Go, schema, import, artifact and executable-example gates remain mandatory at the exact integrated head. Capability tests establish only the behavior they execute. No release or economic/attention benefit follows from an API, a green gate, synthetic records or a successful runner smoke.
