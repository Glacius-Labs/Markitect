# Managed artifact coverage

Managed artifact coverage is a project-owned accounting check over a selected
set of repository roots. It answers whether each file in those roots has one
declared role: canonical Markitect source, a declared opaque input, renderer
output with renderer-reported owner or owners, explicitly owned tooling, or an
exact exclusion with a reason. A file with no role is a finding.

The standalone `markitect-check-artifacts` command reads a versioned
`ArtifactCoverage` YAML file. The file names literal file or directory roots,
explicit tooling owners and exact exclusions. It does not repeat canonical
resource or input declarations: those come from the parsed Project and its
normalized input resolution. Generated paths and owners come from
`render.GenerateWithOwners`. Exclusions have no wildcard or recursive syntax,
so a new sibling file cannot become excluded by inheritance. Directories can
be managed roots; roots cannot overlap.

The checker reports stale roots, tooling paths and exclusions, unexpected
files, generated files without a current renderer owner, expected generated
files that are missing, and path ownership collisions. Multiple resources may
consume one declared input; those are recorded as consumers of the single
input, not as competing owners. Path aliases are rejected using portable
case-insensitive path rules and Windows-invalid spellings on every host.

Direct invocation uses Markitect's full working-tree loader enumeration and
checks all enumerated files within the configured roots, including untracked
and `.gitignored` files. `.gitignore` alone does not filter this scan. The
loader applies its own fixed exclusions before the checker sees the snapshot.
`verify` runs the same explicit argv check over its immutable materialized Git
snapshot, so it checks only configured roots and files present in that commit;
uncommitted files are absent. Both modes omit paths filtered by the loader. The
check makes no claim about files outside those boundaries.

This check accounts for declared artifact ownership and renderer output
identity. It does not inspect source-code semantics, infer domain meaning,
validate generated bytes against the renderer, or establish human acceptance.
Existing `markitect check` remains responsible for comparing generated output
bytes to their canonical source.
