# Owner account of Markitect's conceptual influences

Date: 17 October 2026. Source: direct owner message in the marketing chat `01a1495c-4b1d-7d82-b1c1-d1fd276d131a`. The German text below preserves the owner's wording. This is an account of influences on Markitect's development, not a new implementation specification or a change to the frozen Apply concept. The [origin and rationale](../origin-and-rationale.md#conceptual-influences) organizes these influences; current decisions retain their status in the [register](../register.md).

## Owner statement

Ich gebe dir ein paar Dinge die als Idee hinter dem ganzen stecken:

- 4 Augen Prinzip
- Verantwortungsbereiche
- Delegation und Eskalation
- Teile und Herrsche im Sinne von Problem aufteilen in seine Teile und wieder zusammenfügen
- Modell und Projektionen: Das Softwareprojekt als Projektion eines kanonischen Modells oder Realisierung eines Weltbilds.
- Kontrolle durch gute Planung, System und Struktur (egänzend zu AI Agents => Trust the Process)
- Stakeholder, Steuerung durch Anreize, Verschiedene Blickwinkel desselben Etwas
- Typsystem für Konsistenz => typisierte Sprache vs dynamische Sprache => Compiler deckt vieles zur Compile Time schon auf statt erst zur Laufzeit
- Viele günstige Subagents (Luna statt Astra, Sonnet oder Haiku statt Fable) die systematisch zusammenarbeiten statt eines God Agents (God Class)
- Abstraktion nutzen, Need to know Prinzip für saubereren Kontext, Agenten mit breitem Wissen und Agenten mit tiefem Wissen koordinieren.&#x20;
- Doc driven Development, Spec driven Development, Single Source of Truth, Clean Architecture, Dependency Rule, Software Architektur learnings, Programmieren in Markdown (mittlerweile YAML, daher ursprünglich "Markitect = Markdown Arcitect).



Diese Ideen oder Konzepte haben alle beigetragen zur Entwicklung und Konzeption von Markitect
