# Owners realize, others use — owner, 19 October 2026

Recorder's note: verbatim owner statement from the Claude implementation session, after the [three repeated demonstrations](../../validation/recursive-apply-repetitions-20261019.md). Their source audit found a cross-area rule (`members/eligibility`) re-implemented in lending while the owner's realization was dead code, and availability held twice. Fresh Verify did not block it. [DEC-060](../register.md#dec-060-owners-realize-others-use-parents-settle-cross-area-matters) records the decision.

## The question

The session proposed a concept rule: a Definition is realized by its owner's artifacts, and other areas use that realization instead of rebuilding it. Re-implementation would then be a concrete, blocking finding for the parent's Verify, without a new process. It asked: "Soll „Owner setzt um, andere nutzen“ eine verbindliche Konzeptregel werden, also blockierend in der Verify?"

## The answer

> Ja, Konzeptregel einführen und danach Extract auf der Bibliothek. Generell sind ja die Parent Manager jeweils zuständig dafür Bereichsübergreifende Dinge zu regeln. Generell soll kein Manager etwas anfassen was nicht zu seinem Bereich gehört. Notfalls könnte eine vorherige Planrunde sowas auch verhindern

Recorder's note: the planning round is named as a fallback ("Notfalls"), not adopted. The rule is introduced first; a prior planning round is considered only if the rule does not prevent the problem.
