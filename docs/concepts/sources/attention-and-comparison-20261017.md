## Owner account — English translation

The cost of a model such as Luna should be understood relative to the developer attention needed to notice an omission or wrong result, explain it in another prompt and check the correction—if the developer notices it at all. Too many agents are not the central problem. Time and human attention are; human attention is currently the bottleneck. AI agents can also overlook things and cannot always think of everything. Parallelization within the organization can reduce elapsed time.

The central question is: "Does what the AI built actually match what I intended?" The developer either checks it personally, trusts blindly or sends another agent afterward just to be sure. A structured, thought-through process, drawing on practices used repeatedly in human organizations, is intended to help.

The intended comparison gives an agent ordinary documentation with the same content as the canonical model and the instruction: "Read the documentation and implement it accordingly."

## Recorder's interpretation and boundaries

- Quality, faithful realization and required human attention are the main questions. Model expenditure and elapsed time remain distinct operating observations. Low-cost models can make more focused implementation and verification practical; lower total spending remains outside the product goal.
- The owner's relative-cost premise is not an independently measured wage/model-price comparison. No numerical cost advantage is inferred here.
- Human organizational practices motivate the method; their transfer to AI and the method's effectiveness still need evidence.
- Parallel execution is a later direction. The first selected Apply strategy retains its one-writer policy.
- The baseline is semantically equivalent ordinary documentation and an agent, not an uninformed agent deprived of requirements.
