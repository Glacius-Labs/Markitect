# Markitect-first Change Protocol

Shipped in the immutable [v0.13.0 release](https://github.com/Glacius-Labs/Markitect/releases/tag/v0.13.0). [Release evidence](validation/markitect-first-release-readiness.md) separates the verified workflow contract from unproven human-attention benefits.

The embedded provider-neutral [Markitect-first Change workflow](../src/internal/host/embedded/resources/workflow-markitect-first-change.yaml) defines how implementation and maintenance work should use an adopting Project's canonical intent, configured checks, packages, adapters, and fixed-snapshot evidence. The [authoring Skill](../src/internal/host/embedded/resources/skill-authoring.yaml) includes it in Markitect's portable authoring context.

The workflow classifies work as implementation-only, an intent change, a migration, or ambiguous. Intent changes establish desired state in its canonical owner and review `check` plus fixed-revision `impact` before corresponding implementation begins. Implementation-only work follows accepted intent without creating model edits to simulate compliance. Final evidence binds `check`, selected `context`, `impact`, configured `verify` checks, and adapter reconciliation to the exact candidate revision.

Adopting Projects remain responsible for source-level analysis through their declared checks and configured adapters. Build the standalone helper from the exact source package and put the reviewed binary on PATH, then configure `run: [markitect-check-artifacts, --repo, ., --config, markitect-artifacts.yaml]` in `spec.checks`. Markitect source dogfood uses the equivalent `go run ./src/cmd/markitect-check-artifacts --repo . --config markitect-artifacts.yaml` argv; the configuration declares managed roots, tooling owners, and reasoned exclusions. The helper reports path ownership and gaps without interpreting file contents. `verify --revision CANDIDATE` runs the configured argv against the fixed candidate snapshot. Uncovered artifacts must be reported as unverified. Architecture ambiguity, exceptions, conflicting intent, and material risk require a human decision. Machine results do not constitute acceptance.
