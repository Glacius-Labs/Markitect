# What is shown and what is not

The concept rests on a few results of real runs, each run once and on the tool of an earlier concept, so none of them is a rate.

| Shown | What it supports | Where |
|---|---|---|
| Readers of a model, without the code, found all three contradictions another agent had planted, and four of the nine later model problems of a full build before it started | Reading the model as a source of its quality | [#1079](https://github.com/Glacius-Labs/Markitect/pull/1079), [#1083](https://github.com/Glacius-Labs/Markitect/pull/1083) |
| A pass per perspective, such as security or operation, described little more than a single pass at several times its cost | Perspectives as questions to ask, in catalogs, not as passes | [#1040](https://github.com/Glacius-Labs/Markitect/pull/1040) |
| Types of their own for deployment, operating procedures and roles, tried by hand on one model, did not make it better; what helped was that a type's sections show what a document leaves unstated | What a model states as the sections of a few types, not as many types of their own | [#1051](https://github.com/Glacius-Labs/Markitect/pull/1051) |

**Not shown:** the language on a real software project; a model of a project's way of working, with general types, realized by skills; and a series of changes to one model over weeks.

When Markitect counts as proven is open ([OQ-015](../decisions.md#open-questions)). Being proven brings in what waits for it: a user interface and other clients, and telemetry for reference values ([roadmap](../roadmap.md#conduits)).
