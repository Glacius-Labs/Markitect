# Development risk register

**Status:** preparation evidence and triage, updated 2026-10-03. This document classifies risks for coordinator planning; it is not a product roadmap, a new policy contract, or authorization to implement one feature per risk. The [engineering constitution](../engineering-constitution.md) remains the canonical owner of adopted invariants. A future product change needs a separate concrete case, owner, and decision.

The preparation baseline assessment below is preserved. Current package ownership and mechanically enforced independence are recorded in the [consolidation report](../validation/clean-architecture-consolidation.md); current release status is owned by the roadmap.

## Evidence boundary

This assessment uses the current preparation-branch source after merged PR #59 (`e9550f5`) and the completed [three-task AGENTS.md comparison](../validation/agents-md-vs-markitect.md). **v0.12.0 remains the latest published release.** The current source also contains explicit read-only analysis for structurally valid policy failures; that behavior is unreleased source and must not be described as part of the v0.12.0 binary. See the [roadmap](../implementation-plan.md) and the [policy-failure analysis contract](../design/policy-failure-analysis.md).

PR #59 compared a short `AGENTS.md` plus existing source/tests with Markitect guidance on three tasks. Its overall conclusion is **inconclusive**: simple candidates worked, while Markitect exposed a useful policy-migration explanation; the comparison did not show that extra model maintenance pays for itself. It had one pair per task, incomplete upstream test infrastructure, unmatched policy history for Task 2, shared environment and instrumentation limits, no available token/model-call telemetry, and no human acceptance or database/runtime verification. File reads and byte counts are not productivity or token measures. The report preserves negative findings, including broad Impact, missing source selection, projection work, and extra maintained artifacts. These findings guide what to investigate; they do not prove general failure or benefit.

The code references below identify focused tests, not exhaustive assurance. No test suite can establish source-language or business semantics unless a declared project check actually observes them. The existing synthetic and bounded integration evidence should be read with the product boundaries in [Architecture](../architecture.md), not as proof of universal adoption or business benefit.

## Triage

1. **Kernel too weak or too powerful — DESIGN PROPOSAL.** The adopted response is a small finite, deterministic language and a repeated-concrete-need bar before adding primitives ([constitution](../engineering-constitution.md#constraint-language-and-specialist-engines), [domain-language pressure test](../design/domain-language-pressure.md)). `internal/core/same_target_test.go` covers bounded paths, typing, structural failures, and deterministic results. Aggregate fan-out, incoming ownership, and arbitrary name-pair rules remain known limits; the matched study did not establish a repeated generic semantic need. Do not turn each awkward fixture into a Core feature.

2. **Hidden semantic relationships — ALREADY PROTECTED for declared model edges; NEEDS REAL-WORLD EVIDENCE for declaration completeness.** Relations explicitly separate context, invalidation, and cycle behavior ([Architecture](../architecture.md)); context provenance and unknown-input fallback are exercised by `internal/app/context_provenance_test.go` and `internal/app/impact_policy_test.go` (`TestImpactCausesNameReverseEdgeAndUnknownInputFallback`). The adopter must still declare the relevant edge/input. The comparison's omitted ADR and source facts concern selection and modeling, not a proven hidden-edge defect in Core.

3. **Ambiguous policy composition — ALREADY PROTECTED by the current bounded composition rule; DESIGN PROPOSAL for any future overlay.** A resource shape's interacting constraints live in one active Domain/API version; `conformsTo` does not activate another Domain, and package activation is explicit ([constitution](../engineering-constitution.md#reuse-existing-domain-packages), `internal/app/domain_inputs_test.go`: `TestPinnedPackageDomainRequiresActivationAndKeepsExactOrigin`). There is no general Company + Architecture + Project overlay or last-wins resolution. Keep that absence explicit; adding overlay/conflict semantics requires a concrete design decision and evidence.

4. **Canonical, observed, generated, inferred, and proposed state conflation — ALREADY PROTECTED.** Adoption is a reviewed source change; projections do not become canonical and observation does not silently rewrite desired state ([constitution](../engineering-constitution.md#copy-me-propose-review-adopt), [Architecture](../architecture.md)). Policy analysis is read-only and cannot turn failure into acceptance; structural-failure boundaries are covered by `internal/app/policy_analysis_boundary_test.go`. The pilot's `Observe → Plan → Apply → Verify` replay converged for its configured local projections, a bounded observation recorded in [the pilot](../validation/real-project-adoption-pilot.md#reconciliation-and-copy-me).

5. **Reconciliation non-convergence — ALREADY PROTECTED in the implemented local projection path; TEST HARDENING for a repeatable regression gate; NEEDS REAL-WORLD EVIDENCE for future adapters.** `internal/app/reconcile.go` binds plans to source/config/model/desired/tool inputs and validates before Apply. `internal/app/reconcile_write_test.go` and `internal/app/reconcile_conflict_test.go` cover no-op/write/collision boundaries. The pilot observed a second plan with no operations once for its configured outputs. That bounded replay is not a generic idempotency guarantee; add a focused second-plan-empty automated scenario if reconciliation is extended, and evaluate each future adapter on its own contract.

6. **Impact false negatives — ALREADY PROTECTED for declared and unknown inputs; NEEDS REAL-WORLD EVIDENCE for recall and noise in adopter work.** Fixed-snapshot comparison, explicit dependency behavior, conservative fallback, and causes are defined in [Architecture](../architecture.md#fixed-inputs-and-evidence). `internal/app/impact_policy_test.go` covers bounded per-resource impact, global selection impact, and unknown-input fallback; `internal/app/impact_analysis_test.go` covers policy transitions and structural blockers. PR #59 recorded two direct policy subjects against 69 conservatively affected resources after a package change. The remaining set was not individually judged, so it is not evidence that 67 were false positives; nor does the run establish semantic recall.

7. **Provider or technology leakage into Core — ALREADY PROTECTED.** Adopting-project artifacts are opaque exact inputs; technology-specific inspection belongs in explicit project checks/adapters ([Architecture](../architecture.md#project-artifact-boundary)). `internal/core/graph_test.go` exercises typed mappings and `internal/render/render_test.go` checks explicit targets and rule adapters. PR #59's bounded project-reference check is adopter-owned evidence, not generic Core source analysis.

8. **Adapter coupling — ALREADY PROTECTED as a product boundary; DOCUMENTATION ONLY for the independence default; no defect established.** Configured outputs consume canonical model inputs and have explicit owners (`internal/render/render_test.go`: `TestGenerateWithOwnersReturnsExplicitOutputOwnership`). The implementation deliberately uses concrete adapters where no substitution use case exists ([Architecture](../architecture.md#go-implementation-boundaries)); it does not claim arbitrary adapters are independently parallelizable. Clarify this boundary in future implementation guidance if needed. A parallel-work audit is evidence gathering, not an automatic refactor.

9. **Silent reinterpretation during model/package evolution — ALREADY PROTECTED.** Exact package version/digest pins, explicit activation, origin-qualified identity, Impact, and digest-bound exceptions are adopted ([constitution](../engineering-constitution.md#policy-results-and-explicit-exceptions)). Relevant tests include `internal/core/packages_test.go` (`TestPackagePinsRequireExactVersionDigestAndSafeUniqueArchivePath`), `internal/core/policy_test.go` (stale/expired/wrong-version exceptions), and `internal/app/impact_analysis_test.go` (pin provenance/version changes). These establish declared migration mechanics, not that every adopter selected a complete policy cohort.

10. **Explainability and provenance — ALREADY PROTECTED for structured results; NEEDS REAL-WORLD EVIDENCE for human usefulness.** Policy results, context inclusion provenance, path traces, fixed input identities, and Impact causes are represented ([Architecture](../architecture.md), [policy-failure analysis](../design/policy-failure-analysis.md)). Focused coverage is in `internal/app/context_provenance_test.go`, `internal/app/impact_analysis_test.go` (`TestAnalyzeImpactSeparatesDirectPolicyChangesFromConservativeAffectedSet`), and `internal/app/same_target_test.go` (`TestSameTargetImpactTracksPathInputsAndExactConsumers`). Structured presence does not prove that reviewers find an affected set appropriately clear or actionable.

11. **Constraint-language creep — ALREADY PROTECTED.** The constitution limits policy to finite deterministic assertions and defers specialist engines until repeated cases justify them ([constitution](../engineering-constitution.md#constraint-language-and-specialist-engines)). `internal/core/same_target.go` bounds path length; `internal/core/same_target_test.go` tests termination and deterministic evidence; `internal/format/schema_test.go` checks the supported operator schema. No arbitrary query language or creep defect is established.

12. **Canonical model mistaken for implementation reality — ALREADY PROTECTED as a claim boundary; NEEDS REAL-WORLD EVIDENCE for adoption practice.** Architecture and constitution state that a check proves only its configured assertions, not prose, source behavior, runtime wiring, business correctness, or acceptance ([Architecture](../architecture.md#compiler-and-evidence-model), [constitution](../engineering-constitution.md#example-contract-vertical-slice-usecases)). `internal/app/verify_test.go` covers declared fixed-snapshot commands. PR #59's source/build/test checks explicitly did not establish database or runtime behavior. No Core defect follows from this boundary.

13. **Architecture fossilization — NEEDS REAL-WORLD EVIDENCE.** Exact versioned package changes and narrow human-owned exceptions provide explicit change paths (`internal/core/policy_test.go` covers exception binding/staleness). Whether these paths are costly enough to block legitimate change requires repeated adopter decisions and observed maintenance. A theoretical risk is not grounds for weakening policy or adding another composition feature.

14. **Apply-capable adapter trust/security — ALREADY PROTECTED for current CLI boundaries; DESIGN PROPOSAL for future external adapters.** Current documentation says command checks run with caller authority and snapshot materialization is not an OS sandbox; Apply is explicit ([Architecture](../architecture.md#fixed-inputs-and-evidence)). `internal/app/reconcile.go`, `reconcile_write_test.go`, and `verify_test.go` cover current plan validation, bounded command execution, and controlled writes. This is not a least-privilege or generic plugin-security guarantee. No present exploit or blocking defect was established; any future adapter needs a separately specified authority/evidence contract.

15. **Authoring and upkeep burden — NEEDS REAL-WORLD EVIDENCE.** PR #59 recorded more manually maintained artifacts in Markitect arms on these three tasks, but one pair per task, unequal history inputs, missing telemetry, and no sustained-upkeep measurement prevent a general cost claim. The report found no independent source of truth or human review step removed. The next useful step is repeated matched adopter work, not a Core implementation task ([comparison](../validation/agents-md-vs-markitect.md), [roadmap](../implementation-plan.md#read-only-policy-failure-analysis-unreleased-source)).

16. **Context noise and omissions — ALREADY PROTECTED technically for explicit selection/provenance; TEST HARDENING and NEEDS REAL-WORLD EVIDENCE for selection quality.** Context follows declared edges/inputs and exposes inclusion causes ([Architecture](../architecture.md#authoring-and-queries), `internal/app/context_provenance_test.go`, `internal/app/run_context_test.go`). PR #59 found the supplied packet omitted ADR 0009 and other needed source facts in specific tasks, while including broad Domain/project inputs. This is an observed authoring/selection limitation, not a violation of closure semantics. Test focused source-selection review affordances if developed; do not claim complete, minimal, or universally task-relevant context.

17. **Existing-project adoption completeness — NEEDS REAL-WORLD EVIDENCE; DESIGN PROPOSAL for inventory/cutover tooling.** Explicit selected evidence and human adoption boundaries are documented in the [constitution](../engineering-constitution.md#copy-me-propose-review-adopt). Neither PR #59 nor the earlier [real-code pilot](../validation/real-project-adoption-pilot.md) proves complete discovery of an adopter's policies or rules. Repeated owner-led migrations should establish what inventory evidence is missing before adding automated inventory, conflict detection, or cutover workflows.

18. **Parallel implementation pressure — DESIGN PROPOSAL / evidence gathering; no defect established.** Package boundaries and consumer-owned interfaces are described in [Architecture](../architecture.md#go-implementation-boundaries). Output ownership has focused coverage in `internal/render/render_test.go`, but PR #59 did not run parallel adapter implementation work or demonstrate a shared-contract failure. Audit a concrete independent adapter change against the stable semantic contract before refactoring shared code. Shared Domain semantics remain intentionally coordinated.

## Preparation versus product work

This register is preparation material for coordinating bounded investigations. It does not add requirements to Markitect, alter the published contract, promote unreleased source behavior into v0.12.0, or authorize implementation. The only current product-level blockers that this audit can establish are the existing declared structural/policy gates; no blocking Core defect was demonstrated by the register or PR #59. Any future work should start from a reproduced adopter case, cite the fixed evidence and affected contract, preserve the conservative and human-acceptance boundaries, and be triaged separately against the [engineering constitution](../engineering-constitution.md).
