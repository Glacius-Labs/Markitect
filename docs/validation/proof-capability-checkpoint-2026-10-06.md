## Gaps found during implementation and review

The next implementation steps are accepted operating-model completion, not additional Core operators:

- Reuse passed verification only after recomputing exact immutable evidence, current working bytes/modes, checks, runtime, configuration and child-result provenance. The implementation exists; repeated real fresh-agent convergence remains unproven. Missing historical provenance remains conservative. An unrelated skipped target is unobserved, never a claimed passing no-op.
- The current verifier protocol requires exact selected scope, policy and artifact references, and one passing typed observation for each required subject: selected scopes, policies, every supplied artifact byte (including fixed-check inputs), and fixed-check identities. The controller validates this response coverage before recording a pass. Coverage bookkeeping cannot establish semantic truth, understanding, provider identity/authentication or acceptance.
- Ledger selection error recovery was subsequently integrated at `8494a1d`: the CLI reports `observed-selected`, `observed-not-selected`, or `unknown`, omitting unobserved head/IDs. Focused tests cover pre-commit failure, a committed selection followed by an error, and unreadable recovery. No rollback or automatic retry occurs.

Observation-coverage enforcement is integrated in the controller verifier; the reconstructed required-observation contract is also bound during cached-result freshness validation. This is a source capability, not evidence of fresh-agent convergence or semantic correctness. The C11 v4 Verify refusals show a separate configuration boundary: undeclared assurance-scope check IDs produce `incomplete` before provider work; no Verifier result was produced.
