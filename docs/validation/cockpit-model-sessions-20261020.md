# Cockpit model sessions — 20 October 2026

**Scope:** the fifth slice of the [cockpit](../design/cockpit.md#working-through-the-cockpit), adopted by the owner as [DEC-065](../concepts/register.md#dec-065-work-through-the-cockpit-agent-proposed-model-changes-and-configuration): an Agent session that proposes model changes on the owner's prompts, implemented in [authoring](https://github.com/Glacius-Labs/Markitect/blob/447ac3b152de79b52de80513e14dc94349a060bd/internal/authoring/README.md#model-sessions) and the [cockpit adapter](https://github.com/Glacius-Labs/Markitect/blob/447ac3b152de79b52de80513e14dc94349a060bd/internal/adapters/cockpit/README.md#model-sessions). It reuses the [configuration proposals](cockpit-configuration-20261020.md) path. One real session ran with the owner's approval of a bounded test (at most two prompts, a repository copy).

## What was built

- `markitect cockpit --run-config PATH --runtime-profile PATH` enables model sessions. Bootstrap captures the committed source with its settings and the Runtime profile as an Apply does, composes the container engine, the Agents of the prepared profiles with their mapped credentials and the workspace helper from the run configuration, and keeps session evidence under the run configuration's state directory.
- A session runs Root's Execute profile. Each owner prompt is one Execute turn on the session's workspace, read-only except `.markitect/model` and `.markitect/registry`, bounded by the execution budget's turn timeout; the session takes at most the budget's Agent turns. Follow-up prompts resume the provider conversation and keep the workspace.
- The first prompt carries the task, the language guide of the model's vocabulary and the owner's authority over intent. The Agent has three tools: `check` answers with the changed files and the structural check of its workspace, `submit` makes a `model` proposal with its summary through the one proposal path, `answer` reaches the owner without a proposal. Changes outside the model and the registry are refused.
- A turn whose container end was not observed halts the session; a failed or uncertain materialization, and a session closed while it prepares, release the workspace.
- `#/model` starts a session in two steps, shows its state, profile, limits, reported usage, tool uses, proposals and the Agent's text, takes follow-up prompts and closes the session; a model proposal's page shows the Agent's summary as the Agent's text.

## Demonstration

**Real session (owner-approved test, 20 October 2026).** In WSL Ubuntu with Docker 29.4.1, a Linux build of this branch served the cockpit over a clone of the stockroom trial project at its committed head `e5b369a`, selected with its two dependency models, and the Runtime profile of that trial with its Agent model set to `claude-sonnet-5-5` (Claude Code adapter, existing agent image and dedicated runtime token). The turns were started through the cockpit's interface while the owner watched the page.

- Prompt 1, "Lower the highest allowed on-hand quantity of an item from 9999 to 5000.": the turn ran about 25 seconds. The Agent called `check` (passed, one changed file) and `submit`; proposal `model-1` changed only `.markitect/model/stockroom/stock-limits.yaml`, the three statements of 9999 to 5000, with a passed check and no finding. In its final text the Agent noted, without changing them, that the realization files still state 9999. The container's end was observed.
- Prompt 2 asked which Definitions state the limit, without a change: the conversation was resumed, the Agent answered through `answer` (`stock-limits` states it; `receive` and `item` refer to it) and made no proposal.
- The provider reported 12 provider steps and an estimated 0.13 USD for both turns.
- Accepting `model-1` through the cockpit published it with the outcome `applied` and the read-back state `after`; the clone's working tree held exactly that change, uncommitted, and `markitect check` passed on it. Closing the session left no volume or container of the session. Its evidence: `events.jsonl` (session start, two prompts and turn starts, the tool uses, the proposal, two turn ends, close) and one transcript per turn.

**Synthetic page check.** In headless Chrome, the model page ran against a scripted session interface injected into the page (no Agent, no container, no provider): the two-step start with its cost note, the working state with polling, an answered turn with a check, a submitted proposal, usage and the Agent's text, a follow-up prompt, closing, and at 390 px in dark mode no horizontal scroll. No browser console errors were logged. Its usage figures were invented by the script and prove nothing about a provider.

## Checks

`go test` of `internal/authoring`, the cockpit, CLI, apply, bootstrap and tooling packages, `go vet`, `gofmt`, the architecture gate and `markitect check` passed locally on Windows. With scripted Agents and an in-memory workspace over the bootstrap fixture repository, the tests cover: the turn's profile, kind, read-only base with exactly the model and registry writable, timeout, home, workspace and transcript path; the check tool's changed files and passed check; a submitted proposal of kind `model` with the session, summary, passed check and only the model file changed; the resumed conversation on the next prompt; the Agent-turn limit; one open session at a time; a prompt refused while the session works; closing a working session, which stops the turn, closes the workspace and removes the home; changes outside the model, an empty summary and an unknown tool refused without a proposal; the session record's kinds; a halted session after an unobserved container end; a failed materialization that closes the workspace and records the failure; closing while the session prepares; and no prompt while a close waits for the working turn, which does not reopen the session. `apply.SessionBasisOf` is tested for Root's Execute profile, the budget and the language guide. The HTTP tests cover the cockpit's own JSON request for start, prompt and close, unknown fields, and the status of each refusal.

The independent review required releasing the workspace after a failed materialization, closing the race between a close and a new prompt, halting after an unobserved container end, and the language guide in the prompt; all four are addressed, with smaller findings on evidence, wording and cleanup.

## Not established

Sessions with Codex, with a larger model or a longer conversation, a halted session or a cut-off turn in a real container, and the owner's own use of the page. The test session ran one small change on a trial project; it says nothing about the quality of larger model changes.
