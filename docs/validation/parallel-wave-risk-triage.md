# Parallel-wave risk triage

**Assessed source:** `0ba7a7218f2ceae65b8db90bb8133c2ffa583ada` (the frozen preparation baseline supplied for this wave). **Published release:** v0.12.0. This report classifies the 18 concerns in the [development risk register](../development/risk-register.md); it does not convert them into a product backlog or alter that register. The source baseline includes unreleased read-only policy-failure analysis, which must not be attributed to v0.12.0.

## External command adapter regression coverage

The baseline already binds plans to adapter identity, source/model/config/tool identities and a captured observation. `ApplyCommandAdapter` re-observes external state, compares the observation digest, recomputes the plan and compares the saved operations before invoking Apply. `ReadCommandAdapterPlan` checks the captured observation's identity and digest. The new [focused test file](../../internal/app/parallel_wave_risk_test.go) preserves these negative boundaries: changed target identity, changed external observation, altered saved operations and tampered captured-observation bytes must be rejected before mutation. Its local helper uses a copied test executable and temporary state; it requires no live service, credentials or adopter checkout.

Command run against the worktree candidate: `go test ./internal/app -run '^TestParallelWaveCommandAdapter' -count=1` — **passed**. This is source-level regression evidence only. It does not prove remote concurrency semantics, executable trust, least privilege, idempotency across arbitrary providers, or human authorization. No production code, existing tests, shared contract, schema, CLI, adapter protocol or release files changed.

## Preserved adopter findings and limits

The [AGENTS.md comparison](agents-md-vs-markitect.md) remains inconclusive. Its concrete negative findings remain relevant: additional maintained artifacts, missing task-source selection, broad Impact, and projection work. The one-pair-per-task design, incomplete upstream infrastructure, unmatched Task 2 policy history, shared environment, absent token/model-call telemetry, and lack of human/runtime acceptance still prevent broader claims. These observations were not rewritten or reinterpreted here. In particular, the 67 resources outside the two direct policy subjects in one Impact result were not individually judged.

The earlier [real-code adoption pilot](real-project-adoption-pilot.md) remains bounded evidence for its configured project and local projections. Its observed reconciliation replay does not establish generic adapter convergence, complete policy discovery, semantic correctness, adopter acceptance or production safety. No risk in this triage produced a reproduced product defect or a request to change Core semantics.
