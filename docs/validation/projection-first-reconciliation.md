## Remaining authority and assurance limits

The source is projection-first for explicitly selected intent and targets, not a whole-repository controller. Undeclared semantics outside managed scope remain unassessed. Existing narrative, externally supplied inputs, check implementations, vendor/tool artifacts and explicit exclusions retain their declared owners. Normal unregistered Projects preserve their existing validation/verification behavior. Projects must activate registration; no background mechanism intercepts arbitrary code edits or merges. Check implementation can accidentally repeat a canonical fact, as the negative evolution demonstrates. Such duplication still needs owner review and cleanup; artifact accounting cannot discover semantic duplication.

Generic configured checks may themselves be candidate-authored or no-op; Host does not prove independence or semantic sufficiency, and Verify states that limit explicitly. The demonstrated independent checker is a separately fixed property of the synthetic setup. This remains assurance pressure, not a new primitive.

Local checks execute with user authority. Fresh copies detect changes to original snapshot bytes/regular-file identity and Unix executable modes; they do not prevent effects outside their tree, authenticate evidence authors, prove all dependencies, or establish arbitrary source-code correctness. CI/hook evidence checks literal commands, not actual provider execution or hook installation. No AI semantic reviewer, assurance tree, new Obligation primitive, universal bootstrap replacement, automatic adoption or autonomous merge authority was introduced.

Historical PR #78 remains a separate paused Draft with frozen raw evidence, no overall winner and unopened holdout. Private Konfyra evidence/adoption authority remains untouched. Its actor/controller protocol failures are distinguished from product/agent findings. The owner reset identifies model/code divergence under the prior guidance-first operating model as motivation, not a rescored outcome.

## Completion answers

1. **Canonical intent:** explicit project/package Domains and typed resources, including owned Rule/Workflow prose, selected by the Project. Projection mapping/configuration is a separate explicit project owner.
2. **Competing authority:** governed representations cannot redefine their declared intent. Unmodeled scope, independent-check hardcoded expectations and existing narrative ownership remain the explicit limitations above; this does not establish universal single authority.
3. **Artifact states:** ownership accounting distinguishes canonical, input, generated, projected, tooling, vendor and excluded; unexplained managed files fail accounting. Projection evidence reports converged/drift/incomplete/blocked independently.
4. **Custom Kinds:** existing explicitly activated Domain definitions; no new Core noun.
5. **Meaning:** typed properties, descriptions/purpose, references, declared relations and finite existing assertions. Narrative alone is not executable proof.
6. **Projection expectations:** the closed versioned project-owned config binds sources, exact targets, materializer, freedom, prerequisites and named checks.
7. **Contract:** one explicit desired-meaning-to-representation mapping with provenance and bounded evidence requirements; it is not a new Domain/Core primitive.
8. **Common lifecycle:** Observe/Plan capture bounded inputs; deterministic renderers supply exact expected bytes, AI supplies reviewed candidate bytes; explicit Apply materializes; fixed Verify evaluates evidence.
9. **Freedom:** explicit descriptive freedom plus externally checked finite obligations. Freedom text is not a general executable policy.
10. **Observed state:** exact captured regular-file bytes/modes at a working tree or immutable Git snapshot, distinct from canonical meaning.
11. **Drift:** known deterministic mismatch, failed required check or accounting contradiction; AI presence without evidence is incomplete.
12. **Convergence:** declared targets, registered rendering, policy governance, accounting and fixed named checks satisfy their scoped contract. Not bug freedom, owner acceptance or universal semantics.
13. **Fan-out:** exact source GraphKeys/Domain identities and existing invalidation closure map to declared contracts/targets. Unknown inputs bind conservatively; review targets and actual writes remain separate.
14. **Apply:** requires explicit write, fresh exact plan, complete digest-reviewed AI record when needed, safe paths and lock/branch protection; partial writes are reported without rollback or automatic retry.
15. **Verify:** same normalized model plus immutable observed bytes and fresh independent check copies. Required failures cannot become success; evidence remains method-bounded.
16. **Context/Impact:** expose contract config/provenance, matched sources, freedom, checks and target fan-out. Policy dependencies do not become context edges.
17. **Artifact Coverage:** projected and vendor owner facts are explicit. Registered Host composition supplies contract/config owners; no output-content inference.
18. **Existing Modules:** Markdown and Agent Rules retain independent deterministic renderers; Pipelines/Hooks retain bounded project checks. Host composes them without sibling imports or a new universal CI DSL.
19. **Core technology:** no Core source/Domain/SPI semantic change; projection technology stays in module config and Host/project checks.
20. **Validator vocabulary:** already expressible as adopter Kind with existing relations/assertions; no built-in requirement.
21. **Project-specific projection:** DispatchBoard/ListingView/DispatchProcess proof uses external vocabulary.
22. **Greenfield:** twenty selected representations materialized from the frozen seventeen-file seed, with bounded independently checked behavior; arbitrary repositories are unproven.
23. **Repair:** six controlled surfaces repaired against unchanged intent; exactly one target written per repair and fixed verification reconverged.
24. **Corrected behavior:** explicit active projection participation in Verify; AI presence cannot pass; guarded complete candidates; opaque targets cannot become canonical; check-input mutation invalidates evidence; required-gate failure means drift.
25. **Prior findings:** preserved model/code divergence motivation plus separate actor/controller failures, no retroactive winner or score.
26. **Unproven benefits:** human-attention savings, generalized autonomy/obedience, reduced defects/tokens, economic value and complete semantic/integration assurance.
27. **Next adopter test:** one owner-reviewed fact, two real representations and independently owned acceptance evidence in shadow mode; measure duplicate truth removed and ongoing upkeep.
28. **Accurate model:** desired state → projections → observed state → reconciliation within explicitly governed scope. It cannot yet accurately claim that every project artifact derives from Markitect; remaining escape hatches are enumerated above.
