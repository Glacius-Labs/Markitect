# Cockpit run inspector and the current Apply concept — 21 October 2026

**Scope:** the run inspector and the run list of the [cockpit adapter](https://github.com/Glacius-Labs/Markitect/blob/447ac3b152de79b52de80513e14dc94349a060bd/internal/adapters/cockpit/README.md#projection) read the Apply concept of 21 October 2026: the [mandatory Model assessment and closed Runs](../design/canonical-model/manager-apply-workflow.md#mandatory-model-assessment-and-closed-runs), the [conformance mandate and observation kinds](../design/canonical-model/manager-apply-workflow.md#conformance-mandate-and-observation-kinds), the [model context delivery](../design/canonical-model/manager-apply-workflow.md#model-context-delivery-and-completeness) and the [strategy boundary](../design/canonical-model/manager-apply-workflow.md#provisional-direct-baseline-21-october-2026). The owner should understand a run of today without reading raw logs. No change to the run engine, Apply, any format or `go.mod`.

## What changed

- **Model assessment as a verdict.** The first Pass is named *Model assessment* everywhere. Its page shows the verdict, the conclusions of its Managers whole (no clipping), the findings with their class (`model_error`, `model_gap`, `unclassified`) and per Manager and Definition the status and the evidence's claim, source, location and reasoning. A Run the engine ended because a Model assessment or Root confirmed a material model problem (recognized from its failed-outcome reason) reads as the closed ending *Model problem confirmed — nothing published. Correct the model and start a new run.*, in the header pill, the account and the Pass page.
- **Observation kinds.** Deviation, suspicion, model problem and suggestion have distinct labels in quiet colors, with expected, receipts, subject, Definition and closure. Open confirmed deviations and model problems name a correction and block; an open suspicion is listed as one, holds the Pass back until a fresh review decides it and names no correction; suggestions say they never block. A correction round (open confirmed findings that name a correction) is told from a re-Verify of an unchanged candidate (a review of the very candidate an earlier review of the same purpose judged).
- **Probes.** `probe.requested`, `probe.receipt` and `probe.disposed` are projected: timeline and event labels (*Probe R4 on the candidate: passed*), probe rows on the Verify Pass and Manager pages (obligation, claim, expected, stand, outcome, exit code, uncertainty, disposition), a probe page with the probe's bytes and output from the record, and links from findings and from result evidence to receipts.
- **Lookups and context.** `lookup.definition` and `lookup.brief` read *Root looked up stockroom/interface*. A Manager page shows the context `run.start` bound (Brief, in full, reference only) and which reference-only Definitions it looked up in each Pass. Turn rows and the turn page show mode and how the context arrived (brief, history, rehydrated).
- **Strategy and binding.** The header and the run list show the strategy; the binding (build, source, work Passes, budget) is in the tooltip and the run page. A Pass shows its turns and cost, the rail and its tooltip too.
- **Report and publication.** The inspector presents the Run's own status with the publication and no longer lists a missing report `outcome` as a gap (an earlier build's report lacks it). `report.run.problems`, `turns` and `probes` are read. A no-change publication reads *no change — nothing to write*, with no read-back count or table.
- **Closed Runs.** The Owner node, its edge and the legend entry appear only when the record holds owner-channel records of an earlier run.
- **Waits.** The form "the accepted basis of <Manager>" (a Manager's own named wait) is recognized and its reason is joined through `report.wait.stage`.
- **Header and polish.** The header holds the run identity, strategy, start and duration, the outcome pill and a small Live or Replay chip whose tooltip holds the link details. Pass labels in the timeline no longer overlap. *What this record does not establish* is a collapsed section. 390 px has no horizontal overflow.

## Checks

- `gofmt`, `go vet` and `go test` of the cockpit, CLI and bootstrap packages; `go run ./cmd/markitect-check-architecture --repo .`; `node --check` of every changed page module; `go run ./cmd/markitect check --repo .`; the documentation link check; `git diff --check`.
- New tests (`concepts_test.go`) on synthetic records in the run engine's shapes: binding and context decoding, per-Pass usage, probe lifecycle with dispositions and their withdrawal, finding kinds and effects, correction round versus re-Verify, the assessment's coverage and both routes into the closed ending (and a technical failure that is none), the named wait form, the owner-channel flag and the report as the producer writes it today.
- Contract test: `TestEveryRecordedKindIsProjectedOrListedOnly` reads the source of the run engine and Apply (literal kinds, kinds in a local variable, kinds passed to the recording helper) and fails for a kind that is neither projected nor on `listedOnly`; the allowlist holds the bookkeeping kinds and the historical `environment.release`, and a listed kind need not still be produced (the per-Turn baseline removes the working environments, with `turn.start.environment` and `turn.end.instance`, which stay readable: `TestListedOnlyKindsAndHistoricalKeysStayReadable`). `TestReportDecodesOnlyFieldsTheProducerWrites` compares the report fields the cockpit decodes with the producer's report types. The consumed-key table gained the new keys. The gap *kinds not interpreted* lists only unknown kinds; for both real runs it no longer appears.

## Demonstration on real runs

Two runs of Main `b9cdd6d8` (strategy `staged`, model `claude-sonnet-5-5` as the reports state), served read-only with `markitect cockpit --no-open --state DIR`, driven in headless Chrome over the DevTools protocol:

- `20261021T125155Z-6b50606a`: verified, no change, 322 records (Model assessment p1, Plan p2, Prepare p3, Implement p4, Verify p5 with 12 probes R1 to R12, 31 definition lookups, 3 brief lookups). The header reads *Verified · no change* with the strategy; the rail shows each Pass with turns and cost and *Publish: no change — nothing to write*; the Model assessment page shows the verdict, the Managers' conclusions whole and the 11 Definitions of stockroom with the evidence's claim, source, location and reasoning; the Verify page lists the nine probes of the Pass; Root's page shows its context (one Definition in full, ten reference-only, all ten looked up in the assessment, in Plan and in Verify) and three further Brief lookups; the event list reads *stockroom: turn m1 ended, reported basis; 3 probes*.
- `20261021T131037Z-8876730c`: cancelled in Plan p2 (79 records): the pill reads *Incomplete*, p2 *ended unsealed*, *Publish: nothing published*, no owner node.
- Synthetic records (not a real run): a Model assessment that confirms a `model_gap` (the closed ending, the class, the open coverage entry) and a Verify with a deviation, a suspicion, a suggestion, a failed probe with its violation disposition, an uncertain error receipt without disposition and a re-Verify of the unchanged candidate. They show the paths the two real runs do not contain.

At 390 px the header, the rail and a Pass page fit without horizontal overflow. The screenshots are not part of the repository.

## What this does not establish

- The real runs contain no finding, no adverse probe, no model problem, no dependency binding and no owner-channel record; those views were shown on synthetic records only and have not met a real Run of the new concept.
- The recorded `context` of a Manager says what the Run bound and what the Agent looked up; it does not show what the Agent read or understood, and no record shows the provider payload.
- Layout was checked at 1440 and 390 px in one browser engine, not with assistive technology or other engines; the inspector's live link was not re-driven against a running Apply in this change.
