# P03 — Normal tools, Git context and complete changes

Replace the no-history candidate file tree with a genuine Git-backed project workspace based on the selected repository/revision. Managers need meaningful surrounding source, dependencies, tests, native instructions and usable log/blame/diff/branch/history context. Use an isolated real worktree or another validated Git-backed strategy; choose it from current project needs, not an artificially narrow few-file restriction. Preserve explicitly needed local task inputs. A separate Git directory must reference real history, not fabricated one-commit history.

Support shell/build/test/Git tools and actual additions, modifications, deletions, renames and relevant binary artifacts. Harvest actual before/after changes and exact modes/content, and integrate them through normal candidate/Verify/Apply. Existing Apply contains delete support; reuse and complete the pipeline rather than imposing the old text-only adapter restriction. Acceptance of writes remains scoped even when read context is broader. Managers cannot silently publish into adopting Main before the guarded integration step.

Acceptance: focused observable tests for Git history access, add/edit/delete/rename, cross-file references, binary roundtrip, executable modes and applicable Windows behavior; out-of-scope changes, links, stale bases and concurrent candidates; preservation of adopting WIP; failure/recovery/cleanup of own workspaces. Check compiler/model inventory and required checks after deleting/renaming artifacts. Do not delete shared worktrees or original evidence. Coordinate shared envelope changes through Designer.
