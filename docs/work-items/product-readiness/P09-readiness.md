# P09 — Maintained tests and real product acceptance

Build and maintain a reusable risk-based suite across model/compiler, setup/skills, shared CLI/MCP operations, App Server lifecycle, independent Managers/helpers/review, Git workspaces and all change kinds, freshness/ownership, candidate integration, Verify/Apply and recovery. Each implementation item adds focused tests while it is built; P09 integrates coverage and actual evidence, not a late testing-only phase. Tests must detect wrong behavior, including failure paths, instead of asserting duplicated prose or mocks as product success.

Use the finite new product acceptance allocation in README/backlog; old failed grants are not reusable. After exact source/config bindings and offline checks, the three allocated jobs cover App Server operation, true parallel roles/helpers/review, and normal end-to-end delivery with an actionable model/check failure and correction, consistent rename/delete, real tests/Review/Verify/Apply and recovery. Keep projects disposable and own. No Case Study fixtures, private evaluations or comparative claims.

Acceptance: actual clean source/binary/config, logs/handles/role starts/failures, candidate and applied outcome, real test/review results and bounded timing/usage where available; explicit unknowns and unsupported behavior. Independently review final integrated source and user experience. Required local and hosted Linux/Windows gates run on the precise final candidate; preserve tested revision if a later change needs only focused checks. Critical normal-work defects block Main; do not reclassify required features as unsupported just to get green. Product correctness evidence is distinct from future productivity comparisons.
