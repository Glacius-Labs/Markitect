## Implemented source

The new `internal/core` compiles explicitly supplied Schemas and Definitions into normalized structural IR. It supports exact nominal identities, typed and closed Properties, cardinalities, references and Kind references, resolved edges, provenance, deterministic semantic digests, bounded input validation, and stable diagnostics. It does not load files, select Modules, evaluate project policy, interpret source code, write targets, or execute checks.

Host loads the closed canonical source manifest from a Git-backed source snapshot and reads only explicitly named Definition, Module, and Schema inputs after acquisition. It activates exact pinned Schema/Projection Modules, binds a full Projection identity to a configured runtime Module, and supplies selected model data and target paths to statically composed capabilities. The canonical Projection describes desired representation, scope, target, and selected policy identities; the runtime binding supplies the implementation.

Installable Modules have one of two disjoint types. Schema Modules add Kinds and have no projector registrations. Projection Modules register target capabilities and have no Schemas. The import architecture gate enforces that Core does not depend on Host or Modules and that Modules do not import sibling Modules or Host.

The Markdown capability renders a generic structural view from Core data. The .NET helper validates caller-supplied candidate bytes, exact allowed paths, supplied Schema Kinds, and per-Kind guidance. It returns `candidate-unverified`; it does not generate C# or determine semantic correctness. The Host has bounded context, impact, reconcile planning, explicit Plan/Apply/Verify and adoption actions, operational ProjectionRecords, ownership indexing, and pure recursive assurance. These are separate from a continuous controller, autonomous agent scheduling, a durable active-record ledger, and human acceptance.
